# Личный ассистент компьютера NOZZA — внешняя программа помощника и навыков

Агент — **не часть коннектора** и с 18.14 — личный ассистент компьютера. Он ставится в своё окружение, слушает только
`127.0.0.1` и ничего не знает о базе PrintFlow: связь с панелью идёт по HTTP
через loopback. PrintFlow хранит только его адрес и статус, а с 18.14 — читает у него реестр навыков.

Зачем отдельная программа: зависимости звука, захвата экрана, ввода в чужих
окнах и индекса документов не должны попадать в окружение, которое `pf.py` ставит каждому, включая
телефон-кассу. Поэтому `pf.py` агент не запускает и не импортирует.

## Что он умеет

| Порт | Роль | Маршруты |
| --- | --- | --- |
| 8791 | Речь | `GET /health`, `POST /transcribe`, `POST /mic/arm`, `POST /mic/disarm`, `GET /capabilities` |
| 8799 | Личный ассистент + компьютер | `GET /health`, `GET /status`, `GET /windows`, `GET /screen`, `GET /pending`, `POST /click`, `POST /type`, `POST /key`, `POST /activate`, `POST /action/confirm`, `GET /skills`, `POST /skill`, `GET /journal`, `GET /ui` |

Портов два, потому что панель настраивает их раздельно: `assistant_speech_url`
(голос) и `assistant_agent_url` (окна, навыки и действия). Можно включить одно, не
включая другое.

- **Речь** считает на процессоре: видеопамять уже делят текстовая модель и
  WebGPU-нарезка сечений.
- **Стоп-слово** (по умолчанию «ноза») включает микрофон на короткое окно
  времени — постоянно открытого микрофона нет. Услышанная фраза уходит в панель
  (`POST /api/assistant/phrase`) как запись журнала, а не как выполнение.
- **Действия в чужих окнах** (клик, ввод текста, клавиша, активация окна)
  сначала становятся «ожидающими» и выполняются только после окна подтверждения
  на этом же компьютере. Неподтверждённое действие умирает через 60 секунд.
  Нет экрана — нет подтверждения, значит нет и действия.
- **OCR в комплекте нет.** Без него агент не угадывает, куда кликать: он отдаёт
  снимок экрана, а координаты задаёт человек.
- **Личный ассистент (18.14): реестр навыков, своя база, файлы и день.** `agent/skills.py` — 18 живых навыков: `panel.*` (панель как навык), `files.*` (индекс, поиск, недавние, вопрос по документам, факты, файл в заказ, план и исполнение раскладки), `knowledge.shop` (знания цеха), `day.*` (брифинг и итог), `agent.*` (что умею, почему не получилось, журнал, новый навык словами). Своя SQLite `~/.printflow/assistant.db` — память, индекс, журнал, факты, заметки, выученные навыки. Окно ассистента — страница `/ui` на порту 8799 и его необязательная обёртка `pywebview`. Подробно: `docs/НАВЫКИ.md`.

### Мозг помощника (18.21)

Окно агента (`/ui`) — теперь разговор: фраза словами → ответ словами. Частые
команды понимаются правилами без модели и одинаково каждый раз:

| Сказать | Что будет |
| --- | --- |
| «громкость 30», «громче», «тише», «выключи звук» | общая громкость Windows (Core Audio) |
| «пауза», «следующий трек» | медиаклавиши для любого плеера |
| «открой блокнот / калькулятор / орку / авито / загрузки» | программа, сайт или папка из белого списка |
| «какие окна открыты», «переключись на телеграм», «сверни его», «закрой блокнот» | окна по имени программы; закрытие — с подтверждением |
| «нажми контрл с», «введи: текст» | клавиши и ввод в активное окно — с подтверждением |
| «как там компьютер», «что грузит компьютер» | процессор, память, диски, батарея; процессы |
| «таймер на 25 минут», «запиши: купить PETG», «скажи вслух: готово» | таймер, заметка, озвучка |
| «запомни, что…», «что ты помнишь про Марию», «забудь…» | память помощника |
| «ещё», «а на 50», «закрой его», «открой первый» | продолжение по прошлой реплике |
| «17*23+4», «а если поделить на 5?», «умножь на 2», «15% от этого» | счёт и действие над прошлым результатом |
| «привет», «как дела», «кто ты», «спасибо» | ответ сразу; приветствие — со сводкой цеха от панели |
| «что печатает P1S», «сколько ему осталось», «кто нам должен», «открой заказы» | отвечает мозг панели цеха (см. ниже) |

Порядок слоёв: план от панели → часы → счёт (и продолжение счёта) → разговор →
«что ты умеешь» → память → правила компьютера → **панель цеха** → модель →
понятный ответ «без модели умею…» (техническая причина — только в «Как я понял»).

**Панель цеха как второй мозг.** Вопрос про станки, заказы, деньги или склад (или
продолжение разговора с панелью — «а у второго?») агент задаёт мозгу панели
(`POST /api/assistant/chat`, своя сессия `agent-…`, `delegate: false` — панель не
вернёт вопрос агенту). Ответ показывается с меткой «панель цеха», подсказками и
ссылкой на раздел («Открыть «Финансы» в панели»); «открой заказы» открывает раздел
в браузере или даёт ссылку. Предложенное панелью действие («поставь его на паузу»)
агент не исполняет сам: оно становится навыком `panel.do` с пояснением словами
панели и ждёт «Подтвердить» в окне агента. Если панель не поняла фразу
(`understood: false`), решает сам агент; своя модель есть — общий вопрос идёт
сразу ей, без лишнего вызова панели.

**Подтверждение в окне.** Просьба из окна агента подтверждается карточкой в ленте
(и во вкладке «Ждёт») с обратным отсчётом — всплывающее окно tkinter для неё не
открывается (раньше без экрана оно сразу отклоняло действие, а в Windows человек
видел два окна подтверждения). Голос и панель по-прежнему спрашивают всплывающим
окном на этом компьютере.

Остальное разбирает модель (JSON-режим, только доступные навыки, проверка
реестром). Модель берётся из `PRINTFLOW_MODEL_NAME`, иначе из настроек панели,
иначе — подходящая из установленных в Ollama. Маршруты: `POST /chat`
(`mode=pc` — только команды компьютеру, без модели; так зовёт панель),
`GET /chat/history`, `POST /chat/clear`, `GET|POST /memory`.

Голос: фраза после стоп-слова идёт мозгу; команда компьютеру исполняется сразу,
вопрос цеха отвечает панель, ответ звучит вслух (SAPI в Windows).

Агент отвечает только своему окну и панели: запросы с чужим `Origin`
(страница сайта в браузере) и чужим `Host` получают 403.

## Установка (Windows, компьютер цеха)

```bat
cd agent
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m agent
```

Агент напечатает оба адреса и честно перечислит, чего ему не хватает: нет модели
речи, нет микрофона, нет Pillow/mss, нет OCR, нет pywebview/pystray.

**Модель речи.** Скачайте одну модель на процессор и положите рядом, например
`vosk-model-small-ru-0.22` в папку `models/`. Путь передаётся конструктору
`speech.Recognizer(model_path=...)`; переменные окружения — ниже.

**Модель текста.** Ollama на этом компьютере (`http://127.0.0.1:11434`): `ollama serve`, `ollama pull qwen2.5:3b`. Адрес и имя — `PRINTFLOW_MODEL_URL`, `PRINTFLOW_MODEL_NAME`. Без модели навыки чтения работают, а ответы по документам — отдают найденные места и причину.

**PrintFlow.** В панели: Настройки → «Локальный помощник» → включите «Голосовой
вход» и/или «Агент компьютера», адреса оставьте `http://127.0.0.1:8791` и
`http://127.0.0.1:8799`. Проверка без сервера: `python pf.py doctor` — блоки
«Голос» и «Агент компьютера» скажут, жив ли рантайм и почему нет.

**Файлы.** Папки ассистента задаются переменными окружения: `PRINTFLOW_ASSISTANT_FOLDERS` (личные документы через `;`), `PRINTFLOW_KNOWLEDGE_FOLDERS` (знания цеха, по умолчанию `docs/` репозитория), `PRINTFLOW_DOWNLOADS_FOLDER` (что раскладывает `files.tidy_*`, по умолчанию `~/Downloads`), `PRINTFLOW_ASSISTANT_DB` (своя база).

## Переменные окружения

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `PRINTFLOW_SPEECH_PORT` | `8791` | порт рантайма речи |
| `PRINTFLOW_AGENT_PORT` | `8799` | порт агента и личного ассистента |
| `PRINTFLOW_URL` | `http://127.0.0.1:8765` | адрес панели PrintFlow |
| `PRINTFLOW_WAKE_WORD` | `ноза` | стоп-слово |
| `PRINTFLOW_SPEECH_LANG` | `ru` | язык расшифровки |
| `PRINTFLOW_MIC_ARM_SECONDS` | `25` | сколько секунд микрофон открыт после включения |
| `PRINTFLOW_MODEL_URL` | `http://127.0.0.1:11434` | адрес рантайма текстовой модели (loopback) |
| `PRINTFLOW_MODEL_NAME` | `` | имя модели: без него навыки чтения работают, а ответы по текстам — нет |
| `PRINTFLOW_MODEL_TIMEOUT_SEC` | `90` | таймаут модели |
| `PRINTFLOW_ASSISTANT_DB` | `~/.printflow/assistant.db` | своя база: память, индекс, журнал |
| `PRINTFLOW_ASSISTANT_FOLDERS` | `` | личные документы для индекса (через `;`) |
| `PRINTFLOW_KNOWLEDGE_FOLDERS` | `docs/` репозитория | знания цеха |
| `PRINTFLOW_DOWNLOADS_FOLDER` | `~/Downloads` | что раскладывает `files.tidy_*` |
| `PRINTFLOW_ASSISTANT_WINDOW` | `1` | открывать ли окно при старте |

Порты в тестах заняты другими значениями (18791/18799), чтобы агент из
`connector/tests/test_agent_os.py` не конфликтовал с живым.

## Границы

- Агент не читает и не пишет базу PrintFlow: только HTTP по loopback.
- Своя база ассистента — отдельный файл, без таблиц цеха; резервная копия цеха не становится копией чужой жизни.
- Снимок экрана возвращается байтами тому, кто спросил, и не сохраняется на
  диске. Запись голоса не сохраняется тоже. Индекс документов — своя SQLite, тексты файлов машину не покидают, в модель уходят только найденные отрывки по loopback.
- Адреса, не являющиеся loopback, отклоняются до запроса — и агентом, и
  панелью, и рантаймом модели.
- Зависимости агента не попадают в `connector/requirements.txt`; контракт
  «agent не импортирует коннектор и наоборот» держит
  `test_agent_os.IsolationTests`.
- Файловые навыки двигают файлы только внутри разрешённых папок и только с подтверждением человека; удаления нет.
- Чужие сайты до агента не достают: `Origin` и `Host` проверяются, CORS не выдаётся (18.21).
- Программы запускаются только из белого списка (`agent/pc.py: APPS, SITES`), без аргументов; выход из системы, Ctrl+Alt+Del и Alt+F4 помощник не нажимает.

## Что нельзя проверить автоматом

Живой голос, точность расшифровки в шуме цеха, стоп-слово, снимок экрана, клик
в чужом приложении, окно `pywebview` и иконка в трее требуют Windows, микрофона и модели. Для них — чеки-лист
владельцу в [`../docs/ПОМОЩНИК.md`](../docs/ПОМОЩНИК.md) и [`../docs/НАВЫКИ.md`](../docs/НАВЫКИ.md).
