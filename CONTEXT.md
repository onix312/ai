# CONTEXT — глоссарий PrintFlow

Только канонические термины. Определение — одно предложение: что это, а не что
делает. Термин согласован с владельцем — вносится сразу. «Избегать» — устаревшие
или неоднозначные синонимы того же понятия.

## Термины

- **Конвейер (FarmLoop)** — автоматический цикл производства на P1S с толкателем:
  печать, охлаждение, срезание детали, захват следующего задания.
- **Смена** — рабочая стойка цеха на панели: план/факт производства, обращения
  клиентов, правила автоматизации, состояние оборудования.
- **Выдача** — передача готового заказа клиенту с записью оплаты или долга.
- **Приёмка** — перевод заказа в «готов к выдаче» с проверкой качества.
- **Дополнения (FarmLoop)** — строки G-code, которые оператор добавляет в
  проверенный FarmLoop-блок перед запуском цикла.
- **Подготовка серии** — виджет сборки печатного задания для конвейера: файл,
  подбор катушки склада, смета и число циклов.
- **Тестовая очистка стола** — пробный запуск G-code-блока FarmLoop на
  свободном принтере для проверки механики сброса детали без печати модели.
- **Конструктор финала (FarmLoop)** — визуальный редактор последовательности
  действий завершения печати, генерирующий проверенный G-code-шаблон сброса.
- **Hero-пульт станка** — сквозной полноразмерный блок живого станка на главном экране («Обзор») с MJPEG-видеопотоком, телеметрией, оперативными командами (пауза, свет, стоп, скорость) и кнопкой прямого запуска следующего задания из очереди.
- **Регулятор скорости** — поворотная ручка с четырьмя фиксированными
  делениями скорости Bambu Lab (Тихо 50 %, Стандарт 100 %, Спорт 124 %,
  Ludicrous 166 %), уровень которой подтверждается телеметрией станка; стоит
  в Hero-пульте и во вкладке «Принтеры».
- **Тракт AMS** — схема стойки катушек и пути филамента до сопла:
  слоты с цветом, материалом и остатком, внешняя катушка, подсвеченная трубка
  активного слота, влажность и температура блока; стоит в Hero-пульте и во
  вкладке «Принтеры».
- **Шкала слоёв** — ползунок по слоям печатающегося G-code с картинкой
  выбранного слоя по типам линий, расходом пластика по слоям и режимом
  «Следить» за текущим слоем станка; стоит в Hero-пульте и во вкладке
  «Принтеры».
- **GPU-сечения** — предпросмотр нарезки в браузере до нарезки: выбранная STL
  режется на плоскости слоёв (WebGPU, иначе процессор) с картинкой слоёв,
  свесами, тонкими местами и оценкой массы; не заменяет нарезку — G-code
  делает серверный движок.
- **Шторка инцидентов** — выдвижная панель из шапки со всеми тревогами фермы
  (живые проблемы станков и события журнала), фильтрами по важности и
  действием в строке; счётчик непрочитанного — на кнопке-сирене.
- **Звуки панели** — синтезированные в браузере сигналы интерфейса и событий
  станков с настройками на устройство (выключатель, категории, громкость,
  тихие часы).
- **Ретранслятор SSDP (шлюз Studio)** — режим шлюза Bambu Studio, в котором
  PrintFlow объявляет Studio реальные станки фермы и шлёт объявления адресно
  на указанные компьютеры (UDP :2021) — для Studio в другой подсети или VLAN.
- **Группа витрины** — именованный набор из ≥2 позиций стеллажа с одним средним
  ценником; позиция входит не больше чем в одну группу.
- **Средний ценник** — печатный ценник группы витрины (формат promo), а не
  отдельный SKU и не штрихкод кассы.
- **Выравнивание цен группы** — явная операция: проставить членам с ненулевой
  ценой медиану по ненулевым ценам состава.
- **Помощник** — локальная модель на этом же компьютере, которая разбирает фразу
  и входящее сообщение клиента; ничего не сохраняет и не двигает деньги без
  нажатия человека.
- **Панель помощника** — страница `assistant.html` (`/assist`, `/помощник`) и её
  нативное окно `pf.py assistant`: разговор, каталог действий, входящее
  сообщение, журнал, ответ по фактам базы, день цеха, навыки агента.
- **Каталог действий** — список действий помощника на сервере: имя, заголовок,
  существующий маршрут, параметры и признак подтверждения; источник адресов для
  панели, а не ответ модели.
- **Действие с подтверждением** — действие каталога, которое двигает деньги или
  печать и выполняется только после «Подтвердить и выполнить».
- **Журнал помощника** — события `kind='assistant'` с пометкой источника: след
  каждого действия помощника и единственная замена отсутствующему входу.
- **Рантайм речи** — внешняя программа, которая расшифровывает запись голоса на
  процессоре и отдаёт текст по loopback.
- **Агент компьютера** — внешняя программа из `agent/`: стоп-слово, активное
  окно, снимок экрана и действия в чужих приложениях; PrintFlow хранит только её
  адрес и статус.
- **Стоп-слово** — слово, после которого агент слушает команду; микрофон открыт
  только на короткое окно времени после явного включения.
- **Ожидающее действие** — действие агента в чужом окне, которое не выполняется
  до подтверждения человека на этом же компьютере и умирает по сроку.
- **Личный ассистент компьютера** — программа `agent/` со своей базой, реестром
  навыков и окном: PrintFlow — один из её навыков, а не хозяин.
- **Реестр навыков** — данные вместо веток кода: навык объявляется структурой
  (имя, заголовок, риск, параметры, требуемые способности, идея), а исполнение —
  в диспетчере; источник для модели и для интерфейса.
- **Навык** — действие ассистента с объявленным риском и параметрами: `panel.*`
  (панель по loopback), `files.*` (файлы), `knowledge.shop` (знания цеха),
  `day.*` (день владельца), `agent.*` (мета).
- **Своя база ассистента** — SQLite `~/.printflow/assistant.db`: память, индекс
  документов, факты, заметки, выученные навыки, журнал действий на ПК; таблиц
  цеха в ней нет.
- **Индекс документов** — отрывки текстов с путём и номером строки: лексический
  поиск без модели, оценка из совпадений слов.
- **Факт из документа** — сумма, дата, телефон, почта, количество, номер — с
  местом `строка N` в файле; разбор детерминированный.
- **План раскладки** — список перемещений файлов по делам с причиной каждого:
  риск `read`, ничего не двигает до подтверждения.
- **Ответ по фактам базы** — вопрос владельца → факты из существующих сервисов
  панели и ответ только по ним; числа сверяются, расхождение — предупреждение.
- **Период вопроса** — окно времени, которое мозг помощника читает из фразы
  владельца без модели («с 21.09 по 25.09», «за неделю», «на прошлой неделе»,
  «за сентябрь», «в 2025 году», «вчера»); без названного периода — 30 дней,
  и ответ всё равно называет даты, чтобы месяц не приняли за неделю.
- **Топ продаж** — ответ помощника на «топ товаров / что берут / топ клиентов»:
  ранжирование по реестру продаж за период вопроса (документы, заказы, полка —
  та же правда, что рисует «Финансы»), а не по остаткам стеллажа; «берут» —
  по штукам, «топ» — по сумме.
- **День цеха** — брифинг утром и итог вечером из тех же сервисов, что рисуют
  панели плана и финансов; без модели.
- **Окно ассистента** — страница `/ui` на порту агента (только loopback) и её
  необязательная обёртка `pywebview`: реестр навыков, журнал, подтверждение.
- **Выученный навык** — навык `my.*`, собранный словами из шагов существующих:
  всегда с подтверждением, без своих параметров, не может звать другой выученный.

## Избегать

- «Центр 10.0» — прежнее название «Смены».
- «Закрывать заказ» — неоднозначно: финал заказа — «выдача»/«приёмка»,
  «закрывать» остаётся за сменами и платежами.
- «FarmLoop» в названии раздела интерфейса — в UI раздел называется «Конвейер».
- «Категория» / `nom_groups` как синоним группы витрины — это справочник
  номенклатуры, а не набор ценников на полке.
- «Средний ценник» как «средняя арифметическая цена» — на бумаге и при
  выравнивании считается **медиана**.
- «Джарвис», «ИИ-ассистент», «чат-бот» про помощника — в интерфейсе и документах
  он «помощник»; «бот» остаётся за Telegram-ботами.
- «Голосовой помощник слушает всегда» — микрофон открывается только на время
  фразы, постоянно открытого прослушивания нет.
- «Агент выполняет команды» — агент показывает и подтверждает; решение и
  подтверждение денег и печати остаются в панели.

## 18.24.0 — периоды и предмет вопроса (И337–И341)

- **Понимание периода** — новый модуль `connector/printflow/periods.py`:
  детерминированный разбор окна из фразы владельца без модели. Точные даты
  («с 21.09 по 25.09», «21–25 сентября», «с 28 по 3», «с 25.12 по 05.01»),
  относительные («за неделю», «за 2 недели», «за 10 дней», «на прошлой
  неделе» — полный пн–вс, «на этой неделе», «за выходные», «с начала месяца»),
  календарные («за сентябрь» — текущий месяц до сегодня, «в августе»,
  «за сентябрь 2025», «за 2026»), дни («сегодня», «вчера», «позавчера»).
  Периода во фразе нет — окно 30 дней и признак `explicit=False`: ответ
  обязателен называть даты, чтобы месяц не приняли за неделю. Окно
  полуоткрытое (`start` включается, `until` нет) — под запросы учёта;
  `Period.previous()` — окно той же длины сразу перед этим, для сравнения.
- **Деньги за названный период** — слой «Деньги» мозга (`assistant_brain`)
  читает период из фразы и считает `acc.summary(start=, end=)` за его
  границы; «за 30 дней» стало лишь окном по умолчанию. «Больше, чем прошлая?»
  добавляет прибыль окна `previous()` одной строкой.
- **Топ продаж** — новый слой `_top_sales` перед «Деньгами»: «топ товаров»,
  «что берут/популярнее» (по штукам), «топ клиентов» (по сумме) — реестр
  продаж `acc.sales_details(start=, end=)` с границами фразы. Слово «товар»
  больше не уводит вопрос в дамп остатков стеллажа; пустое окно отвечает
  честно, а не списком товаров.
- **Окно в ответе** — ответ на деньги и топ несёт `period` (границы, подпись,
  `explicit`), чтобы агент и бот показали «за какое окно» без повторного
  разбора фразы. Факты для модели (`assistant_knowledge`) тоже читают период
  из вопроса.
- Реестр маршрутов и идей не менялся: изменений API нет, `summary` и
  `sales_details` получили только необязательные `start`/`end`. Идеи И337–И341.

## 18.21.0 — мозг помощника: память, контекст, сущности цеха, руки на ПК

- **Мозг** — слой, который решает, куда идёт фраза: уточнение → память → мгновенные
  ответы → цех без модели → компьютер (агент) → планировщик на модели → разговор.
  У панели это `assistant_brain.py` (`POST /api/assistant/chat`), у агента —
  `agent/brain.py` (`POST /chat`). Страница больше не выбирает маршрут сама.
- **Память помощника** — записи «запомни/забудь» (`assistant_memory` в базе цеха,
  `memories` в базе агента) и **разговор** (`assistant_dialog` / `dialog`) с
  метками сущностей. Это не «история чата в браузере»: разговор переживает
  перезагрузку, а метки дают «а у второго?», «поставь его на паузу», «закрой его».
- **Сущность цеха** — станок, заказ или клиент, найденный в базе по имени (в любом
  падеже), модели, номеру, порядковому слову или местоимению. Модель сущности не
  угадывает: планировщик получает список станков с id, а `printer_id` сверяется.
- **Уточнение** — вопрос «какой?» с вариантами, когда подходит несколько сущностей;
  короткий ответ завершает начатое действие (`awaiting` в метке реплики).
- **Риск `soft`** — мягкое действие удобства на ПК (открыть программу из белого
  списка, звук, пауза, свернуть/переключить окно): обратимо, без ввода в чужое
  окно, поэтому без окна «Подтвердить». Ввод в окна, питание, микрофон, файлы —
  по-прежнему с подтверждением на компьютере.
- **Граница агента** — loopback-порт отвечает только своему окну и панели: чужой
  `Origin` или `Host` → 403, CORS нет (ADR-0004, дополнение 18.21).
- Реестр: 691 маршрут, 416 декораторных, 95 в `routes_assistant.py`, OpenAPI 399/691;
  навыков агента 104; идеи И301–И315.

## 18.20.0 — мозги помощника + экспорт AMS с мультиколором

- Помощник отвечает «что сейчас печатается», «что печатаем и из какого пластика» и «какое сегодня число» детерминированно, из сервисов панели: живое задание с материалом и остатком его катушек, часы. Модель не зовётся, полный дамп катушек остаётся за прямым «сколько пластика».
- Разговор модели видит дайджест фактов цеха (дата, парк, склад, долги ≤ 900 символов); цифры — только из фактов, дата — из него же, веб-поиск — только для свежих фактов и пересказывается без ссылок.
- Экспорт AMS с вкладки «Принтеры»: кнопка «Экспорт в AMS» (`POST /api/ams/export`) шлёт цвета и настройки привязанных катушек тем же шлюзом, что автозапись (`ams_push`: только IDLE/FINISH, дедуп 30 мин, журнал, отмена); в ответе — советы плана.
- План AMS (`ams_doctor.plan`) учитывает мультиколор: явные катушки заказа `orders.spools` → по строке на катушку; список цветов `orders.colors` (JSON или старый текст «Белый:40, Чёрный:15») → по строке на цвет с делением граммов; простой заказ → одна строка. Чип «мультицвет» в UI.
- Реестр: 685 маршрутов, 410 декораторных, OpenAPI 395/410; `docs/МАРШРУТЫ.md` пересчитан.
