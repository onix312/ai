САМОЕ ГЛАВНОЕ
───────────────────────────────────────────────────────────────

  Все данные хранятся не в браузере, а в базе на вашем
  компьютере:  %APPDATA%\PrintFlow\printflow.sqlite3   (Windows)
               ~/.config/printflow/printflow.sqlite3    (Mac/Linux)

  Поэтому PrintFlow нужно ЗАПУСКАТЬ, а не открывать index.html.
  Если просто дважды кликнуть index.html, интерфейс откроется,
  но данные не загрузятся и не сохранятся — вверху появится
  предупреждение «Коннектор недоступен».


ЗАПУСК: ОДНА КОМАНДА НА ЛЮБОЙ СИСТЕМЕ
───────────────────────────────────────────────────────────────

  В папке с PrintFlow выполните:

      python pf.py            (на Windows:  py pf.py)

  Что произойдёт при первом запуске:
    1. создастся отдельное окружение Python
       Windows:   %LOCALAPPDATA%\PrintFlow\venv
       Mac/Linux: ~/.local/share/printflow/venv
    2. поставятся зависимости из connector/requirements.txt
       (нужен интернет — только в первый раз; дальше лаунчер
        запоминает отпечаток файла и не дёргает pip зря);
    3. появятся адреса панели и QR-код для телефона;
    4. откроется браузер.

  Пример того, что вы увидите:

      Этот компьютер
        http://localhost:8080/                █▀▀▀▀▀█ ▄▀▄ █▀▀▀▀▀█
                                              █ ███ █ ▀▄▀ █ ███ █
      Телефон и планшет в той же Wi-Fi сети   █ ▀▀▀ █ █▄▀ █ ▀▀▀ █
        http://192.168.1.50:8080/             ▀▀▀▀▀▀▀ ▀ ▀ ▀▀▀▀▀▀▀

  Наведите камеру телефона на код — панель откроется на телефоне.

  Не закрывайте окно, пока работаете: без коннектора интерфейс
  не сохраняет данные. Остановка — Ctrl+C.


ОКНО ВМЕСТО ЧЁРНОЙ КОНСОЛИ
───────────────────────────────────────────────────────────────

      python pf.py gui

  Окно с индикатором состояния, кнопкой «Запустить», адресами,
  QR-кодом, журналом и кнопками обслуживания: диагностика,
  копия базы, обновление, установка ярлыка.

  Если tkinter не установлен (бывает на голом Linux —
  sudo apt install python3-tk), лаунчер сам предложит
  текстовое меню с теми же действиями.


ЯРЛЫК И АВТОЗАПУСК
───────────────────────────────────────────────────────────────

      python pf.py install                 ярлыки + включить автозапуск
      python pf.py install --no-autostart  ярлыки + отключить автозапуск
      python pf.py autostart status        проверить состояние и порт
      python pf.py autostart disable       отключить, не удаляя ярлыки
      python pf.py autostart enable        снова включить
      python pf.py autostart repair        восстановить после переноса папки
      python pf.py uninstall               убрать (данные остаются)

  Windows:  ярлыки на рабочем столе и в меню «Пуск», задача
            Планировщика с защитой от дублей и повторными попытками.
            Если Планировщик недоступен — используется папка Startup.
  macOS:    ~/Applications/PrintFlow.app и LaunchAgent (launchd).
  Linux:    пункт меню и служба systemd --user; если пользовательский
            systemd недоступен — запись XDG Autostart.

  Повторный install обновляет существующие файлы и не создаёт дублей.
  Планировщик, launchd и systemd запускают сервер уже при установке и затем
  при каждом входе. Fallback Startup/XDG сработает при следующем входе.
  Системный менеджер следит за реальным сервером и перезапускает его
  после ошибки — окно держать открытым не нужно.

  Настройки порта и доступа тоже сохраняются, например:

      python pf.py install --port 9000 --local --startup-delay 20

  Задержка может быть от 0 до 300 секунд (по умолчанию 10): она даёт
  системе время поднять сеть и подключить диски. Команда repair сохраняет
  ранее выбранный порт и режим доступа.


ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК
───────────────────────────────────────────────────────────────

      python pf.py doctor

  Проверит и скажет человеческим языком: версию Python,
  окружение и зависимости, каталог данных и права на запись,
  целостность базы (PRAGMA integrity_check), свежесть резервных
  копий, свободное место, адреса в сети, занят ли порт,
  отвечают ли принтеры по портам 8883 / 6000 / 990.

  Частые ситуации:

    «Порт 8080 занят другой программой»
        python pf.py --auto-port        (возьмёт свободный)
        python pf.py --port 9000        (конкретный порт)

    PrintFlow уже запущен
        Повторный запуск не падает с ошибкой, а просто
        открывает панель в браузере.

    Нужен режим «только этот компьютер»
        python pf.py --local

    Посмотреть журнал
        python pf.py logs

ПОДКЛЮЧЕНИЕ С ДРУГИХ УСТРОЙСТВ В СЕТИ
───────────────────────────────────────────────────────────────

  • Компьютер с PrintFlow и телефон/планшет должны быть в одной
    Wi-Fi сети (или LAN через роутер).
  • Проще всего — навести камеру на QR-код при запуске.
    Или открыть адрес вида http://192.168.1.50:8080/.
  • Изменяющий API принимает браузерные запросы только с того же
    адреса, по которому открыта панель (Origin должен совпадать с Host).
  • Если не открывается — проверьте брандмауэр Windows:
    при первом запуске система спросит «Разрешить Python?» → Да.


ПЕРВОЕ ПОДКЛЮЧЕНИЕ ПРИНТЕРА
───────────────────────────────────────────────────────────────

  Основной способ — через аккаунт Bambu Cloud. Принтер остаётся
  в обычном облачном режиме: Bambu Handy и Bambu Studio
  продолжают работать, а LAN Only Mode / Developer Mode
  включать НЕ нужно.

  1. Настройки → Bambu Cloud: email и пароль аккаунта Bambu →
     «Войти». Если Bambu пришлёт код на почту/SMS — введите его.
  2. Принтеры → «＋ Принтер» → «Найти» → список «Аккаунт
     Bambu Cloud» → выберите свой принтер → «Сохранить».
     IP, серийный номер и Access Code подставятся сами.
  3. Всё: телеметрия, команды, загрузка 3MF и запуск печати
     идут через облако Bambu. Камера и список файлов на SD
     доступны, если компьютер в одной сети с принтером
     (введите IP в карточке принтера).

  Запасной способ — локальная сеть (как в прежних версиях):
  связь «Локальная сеть (LAN + Developer Mode)» в карточке
  принтера. На защищённых прошивках для этого нужен
  LAN Only Mode + Developer Mode — он отключает Bambu Cloud
  и Bambu Handy, поэтому это опция, а не требование.

  ВАЖНО: PrintFlow ничего не переключает на принтере
  автоматически — режим меняете только вы на экране принтера.

  Печать, запущенная из Bambu Handy, тоже учитывается:
  PrintFlow видит её по событиям облака и дополняет журнал
  весом, временем и фото из облачной истории.

  Принтеров можно добавить несколько: они переключаются
  вкладками, а очередь печати общая на весь парк.


ЧТО МОЖНО ДЕЛАТЬ С ПРИНТЕРОМ
───────────────────────────────────────────────────────────────

  Мониторинг:
    • состояние, задача, прогресс, слой, оставшееся время;
    • температуры сопла, стола и камеры;
    • вентиляторы, скорость печати, Wi-Fi, прошивка;
    • слоты AMS: тип, цвет, остаток, влажность;
    • HMS и код ошибки печати;
    • локальная камера.

  Управление (с подтверждением):
    • пауза, продолжение, стоп, свет, скорость;
    • температуры сопла и стола, обдув детали;
    • парковка и перемещение осей, подача и выгрузка филамента;
    • калибровка стола, вибраций, полная калибровка;
    • назначение типа пластика в слот AMS.

  Файлы и печать:
    • список 3MF/G-code на SD-карте (FTPS, порт 990);
    • загрузка файла перетаскиванием;
    • запуск печати с выбором плиты, слотов AMS и калибровок;
    • очередь заданий с ручным или автоматическим запуском.


АВТОМАТИЧЕСКИЙ УЧЁТ
───────────────────────────────────────────────────────────────

  Печать началась  → создаётся задание, заказ переходит
                      в статус «Печать».
  Печать закончена → записываются граммы и минуты, пластик
                      списывается с катушки активного слота AMS,
                      считаются энергия и износ, обновляется
                      себестоимость заказа.
  Заказ закрыт     → в кассу попадает доход.

  Любой из шагов отключается в «Настройках → Автоматизация».
  Ваши ручные правки автоматика не перетирает.

  Остаток катушки, показываемый AMS, — оценка производителя,
  а не результат взвешивания. Точнее считает склад PrintFlow.


БЕЗОПАСНОСТЬ (ЗАПУСК ВИДЕН В ЛОКАЛЬНОЙ СЕТИ)
───────────────────────────────────────────────────────────────

  • python pf.py запускает коннектор с --host 0.0.0.0 --port 8080,
    чтобы панель открывалась с телефона. Это НОРМАЛЬНО для
    домашней и офисной сети, но означает: любой в вашей Wi-Fi
    сети видит панель. В общественной сети запускайте с --local.

  • Изменяющий API сверяет Origin с Host: посторонняя веб-страница
    не сможет отправить команды от имени открытой панели. Это защита
    от межсайтовых запросов, но не авторизация пользователей LAN.

  • НЕ открывайте порт 8080 наружу на роутере (проброс портов / NAT).
    НЕ пробрасывайте MQTT порты принтера 8883, 6000 и FTPS 990.

  • Для режима «только этот компьютер»:
      python pf.py --local

  • Access Code и Telegram-токен лежат только в каталоге данных
    и не попадают в браузер, Git и резервную копию.
  • Опасные команды требуют подтверждения в интерфейсе,
    а сервер проверяет допустимые пределы.
  • Для удалённого доступа из интернета используйте VPN,
    а не проброс портов.

РЕЗЕРВНАЯ КОПИЯ И ПЕРЕНОС СТАРЫХ ДАННЫХ
───────────────────────────────────────────────────────────────

  Настройки → Данные:

    • «Скачать копию» — JSON со всеми заказами, клиентами,
      складом, финансами и журналом печати (без секретов).
      Делайте это раз в неделю.
    • «Восстановить» — загрузка копии обратно.
    • «Перенести из браузера» — забирает данные старой версии
      PrintFlow из localStorage этого браузера и переносит их
      в базу. Откройте страницу в том браузере, где работали
      раньше, и нажмите эту кнопку один раз.

  Резервная копия старого формата тоже принимается кнопкой
  «Восстановить».

  База: Windows → %APPDATA%\PrintFlow\printflow.sqlite3
        Mac/Linux → ~/.config/printflow/printflow.sqlite3

  Копии базы файлом (быстрее и полнее, чем JSON):
      python pf.py backup      → каталог backups/ рядом с базой
      python pf.py restore     → выбрать копию из списка
  Перед откатом текущая база тоже сохраняется — «before-restore-*».


АВТОНОМНАЯ ПРОГРАММА (без Python)
───────────────────────────────────────────────────────────────

      python pf.py build

  Результат:  dist\PrintFlow\PrintFlow.exe   (Windows)
              dist/PrintFlow/PrintFlow        (macOS/Linux)

  Лаунчер сам создаёт окружение сборки, ставит PyInstaller и
  зависимости (нужен интернет на время сборки), затем собирает
  программу. Папку dist/PrintFlow/ можно целиком скопировать на
  другой компьютер той же системы и запускать двойным кликом —
  Python там не нужен. Данные хранятся в %APPDATA%\PrintFlow
  (Windows) или ~/.config/printflow и при переносе не теряются.

  ВАЖНО: собранная программа не обновляет сама себя. Вышла новая
  версия — пересоберите тем же способом (база сохраняется).
  Автопроверка обновлений подскажет, что сборка устарела.
