# Как телефон находит сервер PrintFlow

Короткий документ про одну вещь, из-за которой чаще всего звонят: «касса не
подключается и не может найти сервер». Здесь — как это устроено с 17.0.27, что
делать, если не находит, и где в коде лежит каждая часть.

## Одно число на всю систему: 8765

Порт PrintFlow по умолчанию — **8765**. Он один и тот же в четырёх местах:

* лаунчер (`python pf.py`, `pf.py --port` и порт из автозапуска);
* сам коннектор (`connector/printflow_connector.py`, `DEFAULT_PORT`);
* подсказка на экране выбора сервера в приложении кассы;
* UDP-маяк автопоиска (тоже 8765, но UDP — TCP и UDP не мешают друг другу).

До 17.0.27 сервер слушал 8080, а касса показывала в подсказке 8765: владелец
вводил адрес из подсказки и не попадал никуда. Установки, сделанные раньше, не
ломаются: порт из конфигурации автозапуска считается «своим» (обычный запуск
берёт его), а 8080 остаётся в списке поиска навсегда — вместе с 8766 и 8790.

## Три шага поиска, от быстрого к медленному

Ищет приложение, а не владелец: адрес сервера вводится один раз (или не
вводится вовсе).

1. **Сохранённый адрес.** Проверка `/api/health` за 1,6 с: «тот же адрес» —
   самый частый случай, роутер не меняет IP посреди смены.
2. **Автопоиск по UDP (быстрый путь).** Приложение шлёт `PRINTFLOW?` на
   широковещательный адрес и на адрес своей подсети, порт 8765. Сервер отвечает
   JSON-датаграммой: приложение, версия протокола, HTTP-порт, версия, имя, свои
   адреса и пути страниц. Ответ приходит за десятые доли секунды. Каждый
   найденный адрес подтверждается тем же `/api/health` — «кто-то говорит на нашем
   протоколе» ещё не значит «сервер PrintFlow».
3. **Перебор подсети (запасной путь).** Если широковещание в сети закрыто
   (гостевая Wi-Fi-сеть, изоляция клиентов, запрет UDP в фаерволе): TCP-пробник по
   всем адресам своих подсетей сразу по четырём портам — 8765, 8080, 8766,
   8790, — а затем проверка открытых портов через `/api/health`. Wi-Fi идут
   первыми, мобильная сеть оператора (`rmnet`/`ccmni`/`pdp`/`wwan`) не
   перебирается вообще: это 254 гарантированных таймаута и «сервер не найден».

Кнопка «Найти сервер в сети» и сторож связи (автовосстановление после смены IP)
делают шаги 2–3 в том же порядке.

## Датаграмма маяка

Ответ сервера — обычный JSON, его видно глазами:

```json
{"app":"printflow","proto":1,"port":8765,"version":"17.0.27","name":"PETYA-PC",
 "lan":["192.168.1.50"],"paths":{"panel":"/","kassa":"/cashier.html","pult":"/pult"}}
```

Правила, которые нельзя нарушать при правках:

* `app` и `proto` проверяются **обязательно**: в гостевой сети кто угодно может
  «представиться кассой», и переключаться на такой ответ нельзя;
* `127.0.0.1` и `169.254.x` (APIPA) в список адресов не попадают: телефон по ним
  не дойдёт;
* маяк не поднимается при `--local` (телефону там нечего искать) и гаснет вместе
  с сервером;
* версия протокола поднимается, если меняется формат: старый APK должен
  игнорировать незнакомый ответ, а не пытаться его понять.

Проверить автопоиск на самом компьютере (руками):

```bash
python pf.py net          # адреса для телефона, QR, проверки — включая автопоиск
python pf.py doctor       # то же в диагностике: «автопоиск работает / не ответил»
echo -n 'PRINTFLOW?' | nc -u -w1 127.0.0.1 8765   # сырой ответ сервера
```

## Если касса не находит сервер

Проверьте по порядку — каждая строка закрывает свой частый случай:

1. **`python pf.py net`** на компьютере: если и там «автопоиск не ответил»,
   значит широковещание режется, и нужен не телефон, а сеть или фаервол.
2. **Порт 8765 и UDP 8765 разрешены** во входящих правилах брандмауэра. Готовое
   правило печатает `python pf.py net` (Windows: `netsh advfirewall firewall add
   rule …`).
3. **Телефон и компьютер в одной сети.** Гостевая Wi-Fi-сеть с изоляцией
   клиентов не подходит: телефон не увидит даже компьютер в той же подсети.
4. **VPN на телефоне или компьютере** выключен: он уводит трафик в другую сеть.
5. **Сервер слушает не только себя.** `python pf.py status` скажет «сервер
   слушает только этот компьютер», если запущено с `--local`.
6. **Порт не менялся вручную.** `python pf.py status --json` покажет фактический
   порт; `python pf.py install --port N` запоминает его для автозапуска.
