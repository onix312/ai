## Фаза 6. Стеллаж магазина — РЕАЛИЗОВАНО (17.08.2026)

Полка NOZZA в магазине: учёт готовой продукции поштучно, продажи по данным 1С,
общий остаток для стеллажа и онлайн.

- [x] **6.1 Карточка позиции стеллажа** — имя, привязка к каталогу, цена ценника,
      себестоимость штуки, мин. остаток, фото, заметка.
- [x] **6.2 Пополнение с партии печати** — приход N шт с выбором задания из журнала
      (себестоимость штуки подставляется из себестоимости задания) или вручную.
- [x] **6.3 Списание продаж** — быстрое «−1 шт» и «Продажи за день» (раз в день,
      по данным 1С); с ценой — проводка дохода с пометкой «стеллаж», без цены —
      только штуки.
- [x] **6.4 Инвентаризация** — «ожидалось X, посчитали Y», расхождение в журнал
      и корректировка остатка.
- [x] **6.5 QR-ценник на позицию** — модалка с QR (ведёт на `shelf.html?id=…`,
      страница позиции для телефона: остаток, цена, «Продать N шт») + печать ценника.
- [x] **6.6 Оборачиваемость и план пополнения** — продажи за 7/30 дней, скорость
      шт/день, «хватит на N дней», подсказка «напечатать N шт».
- [x] **6.7 Мёртвый сток** — нет продаж 14+ дней → подсветка и сумма замороженного.
- [x] **6.8 Остаток в рублях** — стоимость стеллажа по себестоимости (замороженный капитал).
- [x] **6.9 Единый остаток с онлайн** — продажи «онлайн (Авито/Telegram)» списывают
      с того же остатка, с пометкой канала.

Модель согласована с владельцем: самообслуживание + касса магазина (1С) —
PrintFlow ведёт штуки и остатки, продажи вводятся вручную раз в день;
деньги заносятся с пометкой «стеллаж» для полной картины прибыли.

## Общие замечания (вне фаз)

- Безопасность: PIN при `--lan`, шифрование секретов в SQLite — отдельным этапом.
- Тесты: pytest на бухгалтерию, HMS-декодер, миграции схемы.
- CI: GitHub Actions (ruff + pytest), сборка Windows-бинаря (PyInstaller).
- SSE — технический долг: заменить поллинг, но не ломать мобильную вёрстку.
