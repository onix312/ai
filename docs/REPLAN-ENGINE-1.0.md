# Replan Engine 1.0

Когда проверка результата шага возвращает `failed`, Task Engine останавливает задачу
и в фоне просит локальную модель предложить новый маршрут. Модель получает цель,
снимок выполненных и оставшихся шагов, причину сбоя, evidence и доступные навыки.
Она может создать только черновик; действия по нему не запускаются.

В разделе «Задачи» видны причина, старый и новый хвост, риск каждого нового шага
и необходимость подтверждения. Человек принимает новый маршрут или оставляет
старый. Для остановленной задачи можно запросить черновик вручную.

## Контракт API

- `GET /replans` → `{ok, replans}`.
- `POST /replans` с `{op: "preview", task_id: N}` → `replan` или вопрос `ask`.
- `POST /replans` с `{op: "approve", id: "opaque-id"}` → обновлённая задача.
- `POST /replans` с `{op: "discard", id: "opaque-id"}` → результат удаления черновика.

Черновик живёт 10 минут и привязан к отпечатку незавершённого хвоста. При
одобрении сервер ещё раз проверяет доступность и параметры всех навыков,
запрещённые meta skills, лимит шагов и актуальность задачи. Замена проходит
одной транзакцией SQLite, затрагивает только незавершённый хвост и записывает
старую и новую версии в `assistant_task_replans`. Задача остаётся `paused`.
Продолжение возможно только отдельной командой человека. Обычные подтверждения
рискованных навыков остаются в `Agent.run_skill`.

Автоматического применения, повторного запуска шага и цикла retries нет.
