# Mini App цеха: адрес и настройка

Дата: 22.09.2026, PrintFlow 18.12.2.

Mini App цеха — это страница `site/staff.html` (адрес `/staff`), которую бот
сотрудников открывает кнопкой **«🏭 Открыть цех»** прямо внутри Telegram: полка,
касса, очередь, принтеры, заказы, inbox, деньги. Панель при этом остаётся
локальной: Mini App — единственная часть PrintFlow, которой нужен **внешний
HTTPS-адрес**, потому что Telegram открывает окно приложения только по `https://`.

## 1. Почему вместо цеха открывается «Example Domain»

До 18.12.2 незаполненный адрес молча подменялся значением
`https://example.com/staff`. Telegram честно открывал его — и владелец видел
страницу «Example Domain» вместо своего цеха. Причина всегда одна из трёх:

| Что не так | Как выглядит |
| --- | --- |
| Адрес Mini App не задан | «Example Domain» (до 18.12.2) или сообщение с инструкцией (18.12.2+) |
| Адрес задан без HTTPS (`http://192.168.1.50:8765`) | кнопки «Открыть цех» нет вовсе: Telegram отклоняет сообщение с такой кнопкой целиком (`BUTTON_URL_INVALID`) |
| Адрес HTTPS есть, но телефон его не достаёт | «Сайт не найден» / бесконечная загрузка внутри Telegram |

С 18.12.2 панель показывает вердикт прямо в настройках: **Настройки → Система и
боты → «Telegram-уведомления» → «Адрес Mini App цеха»** — под полем написано,
куда ведёт кнопка или почему её нет.

## 2. Три условия, чтобы кнопка работала

1. **Адрес `https://…`**, который ведёт на этот компьютер и порт панели
   (по умолчанию 8765). LAN-адрес `http://192.168.…` не годится: Telegram
   принимает только HTTPS.
2. **Телефон достаёт до адреса.** Либо адрес смотрит в интернет (Cloudflare
   Tunnel, свой домен), либо телефон в той же частной сети (Tailscale).
3. **Человек в команде.** Mini App авторизуется подписью Telegram по токену
   бота сотрудников; роль ищется по `tg_user_id`/`chat_id` в «Команде
   Telegram». Постороннему страница честно скажет «Вы не в команде».

Перезапуск коннектора после смены адреса не нужен: настройка читается на каждое
сообщение. В Telegram достаточно нажать «Меню» ещё раз.

## 3. Шаг 1: дать панели HTTPS-адрес

Коннектор должен быть запущен (`python pf.py` или ярлык) — адрес панели
`http://localhost:8765`.

### Вариант А. Tailscale — приватно, без публикации в интернет (рекомендуем)

Панель остаётся видна только вашим устройствам: посторонний, узнав адрес, ничего
не получит.

1. Поставьте Tailscale на компьютер цеха и на телефон сотрудника, войдите в один
   аккаунт (та же сеть — tailnet).
   * Windows: `winget install --id tailscale.tailscale`
   * Android/iOS: приложение Tailscale из магазина, вход тем же аккаунтом.
2. В админке Tailscale (login.tailscale.com) включите **DNS → MagicDNS** и
   **HTTPS Certificates**.
3. На компьютере цеха один раз:
   ```bash
   tailscale serve --bg 8765
   ```
   Tailscale напечатает адрес вида `https://ceh-pc.tailXXXX.ts.net` — он ведёт на
   `http://127.0.0.1:8765`.
4. Адрес цеха для панели: `https://ceh-pc.tailXXXX.ts.net/staff`.

Плюсы: бесплатно, ничего не публикуется в интернет, сертификат настоящий.
Минус: на телефоне сотрудника Tailscale должен быть включён (значок VPN) — иначе
адрес не откроется. Внутри Telegram это тоже работает: браузер использует сеть
телефона вместе с Tailscale.

### Вариант Б. Cloudflare Tunnel — публичный адрес, но с защитой

Подходит, если телефон сотрудника без VPN, а адрес должен открываться откуда
угодно.

**Быстрая проверка (адрес живёт до перезапуска):**

```bash
cloudflared tunnel --url http://127.0.0.1:8765
```

Cloudflared напечатает `https://<случайные-слова>.trycloudflare.com`. Адрес цеха:
то же самое + `/staff`. Годится, чтобы убедиться, что всё работает; для работы
постоянно — нет: адрес меняется при каждом запуске.

**Рабочий вариант (свой домен в Cloudflare):**

```bash
cloudflared tunnel login                     # один раз, выбрать домен
cloudflared tunnel create printflow          # создать туннель
cloudflared tunnel route dns printflow ceh.example.ru
```

Файл `config.yml` (обычно `%USERPROFILE%\.cloudflared\config.yml`):

```yaml
tunnel: printflow
credentials-file: C:\Users\<вы>\.cloudflared\<id-туннеля>.json
ingress:
  # Открываем только страницу цеха и её API — остальная панель снаружи недоступна
  - hostname: ceh.example.ru
    path: ^/(staff|цех|assets/(tokens\.css|js/staff-miniapp\.js|brand/.*)|api/staff/.*)
    service: http://127.0.0.1:8765
  - hostname: ceh.example.ru
    service: http_status:404
```

Запуск: `cloudflared tunnel run printflow`, для автозапуска —
`cloudflared service install` (Windows) после создания конфига.
Адрес цеха: `https://ceh.example.ru/staff`.

Правило `path` в ingress оставляет снаружи ровно то, что нужно Mini App, — вся
остальная панель (заказы, деньги, принтеры) отвечает 404. Так безопаснее: в самой
панели пароля нет, и открытый целиком адрес панели = полный доступ к цеху для
любого, кто его узнал.

Если хочется защиты входа, включите **Cloudflare Zero Trust → Access** для
домена `ceh.example.ru` (политика «одноразовый код на вашу почту», бесплатно до
50 пользователей). Тогда при открытии Mini App Telegram покажет страницу входа —
после неё всё работает как обычно.

### Вариант В. Свой домен + обратный прокси

Если уже есть VPS или сервер с домёном: nginx/Caddy на нём, сертификат
Let's Encrypt (Caddy получает сам), `proxy_pass` на компьютер цеха. Компьютер
должен быть доступен с этого сервера — либо напрямую по белому IP/порту, либо
через постоянный туннель. Вариант для тех, кто уже держит сайт; для одного
цеха это самая длинная дорога.

### Чего не делать

* **Не открывать порт 8765 в интернет напрямую** (проброс на роутере) — панель
  без пароля, и любой сканер получит доступ к данным и станкам.
* **Не использовать `http://` адрес** — Telegram такую кнопку не примет.
* **Не публиковать адрес Mini App** в открытых чатах: если адрес с `path`-фильтром
  или Access, риск невелик, а без них — это ключ от цеха.

## 4. Шаг 2: вписать адрес в панели

1. Панель → **Настройки** → вкладка **«Система и боты»** → карточка
   **«Telegram-уведомления»**.
2. Поле **«Адрес Mini App цеха»**: вставьте адрес цеха целиком, например
   `https://ceh.example.ru/staff` или `https://ceh-pc.tailXXXX.ts.net/staff`.
   Схему `https://` можно не писать — панель подставит сама; хвостовой `/` не
   нужен.
3. Нажмите **«Сохранить»** (внизу раздела). Под полем появится строка
   «Кнопка «🏭 Открыть цех» ведёт на …» — значит адрес принят.
4. (Необязательно) То же можно задать через **«Публичный адрес панели»** в
   **«Система 2.0»**: если заполнено только оно, к `/staff` добавляется
   автоматически. Отдельное поле «Адрес Mini App цеха» сильнее — оно выигрывает,
   если заполнены оба.

Тот же ключ виден во вкладке «Все настройки» → группа «Telegram и уведомления»
(`staff_miniapp_url`).

## 5. Шаг 3: проверить

1. **С телефона** откройте адрес цеха в браузере. Должна открыться страница
   цеха (полка, заказы, принтеры). Надпись «нет доступа — откройте через
   Telegram» здесь нормальна: подписи Mini App вне Telegram нет, но видно, что
   сервер и адрес живые.
2. **В боте**: /start или кнопка «Меню» → «🏭 Открыть цех». Внутри должен
   открыться тот же экран, но уже с данными и вашим именем в шапке.
3. Если бот ответил инструкцией вместо кнопки — адрес ещё не принят:
   смотрите вердикт под полем в настройках.

## 6. Доступ сотрудникам

* **Владелец**: достаточно `telegram_chat_id` в настройках — он видит Mini App
  как owner, даже если строки в команде нет.
* **Руководитель / сотрудник**: «Команда Telegram» в настройках или команды
  боту — `руководитель Имя 123456`, `сотрудник Имя 123456`, либо приглашение
  `пригласить сотрудник Имя` → человек пишет боту `старт PF-XXXX`.
* Права в Mini App те же, что у бота: сотрудник не увидит деньги и команду,
  руководитель — не увидит раздел «Команда».

## 7. Частые ошибки

| Симптом в Telegram | Причина | Что делать |
| --- | --- | --- |
| «Example Domain» | адрес не задан (версия до 18.12.2) | обновиться до 18.12.2+ и заполнить «Адрес Mini App цеха» |
| Сообщения приходят без кнопки «Открыть цех» | адрес пустой или `http://` | дать https-адрес (шаг 1) |
| Ничего не приходит вообще после настройки `public_url = http://192.168…` | Telegram отклонил сообщение с web_app-кнопкой (`BUTTON_URL_INVALID`) | в 18.12.2+ кнопка просто не добавляется; обновиться, чтобы уведомления снова доходили |
| «Нет подписи Mini App — откройте через Telegram» | страница открыта в браузере, а не из Telegram | открывать только кнопкой в боте |
| «Подпись Mini App неверна — обновите приложение» | `initData` старше суток или сменился токен бота | закрыть и открыть Mini App заново; проверить, что бот тот же |
| «Вы не в команде — попросите владельца добавить вас» | нет роли для этого Telegram-аккаунта | добавить сотрудника (раздел 6) |
| «Бот не настроен: нет telegram_token» | токен бота сотрудников не заполнен | Настройки → Telegram → Bot Token |
| Адрес открывается на компьютере, но не на телефоне | туннель не поднят, Tailscale выключен, или телефон не в сети | проверить туннель/`tailscale status`; для Cloudflare — `cloudflared tunnel info` |
| Адрес перестал открываться после перезапуска туннеля | быстрое туннелирование (`--url`) меняет адрес | сделать именованный туннель и обновить адрес в панели |

## 8. Что проверяет код

* `connector/printflow/staffbot/core/config.py` — `get_miniapp_url`,
  `miniapp_state`, `normalize_miniapp_url`: адрес берётся из
  `staff_miniapp_url`/`public_url`, без `https` кнопки нет.
* `connector/printflow/staffbot/ui.py` — `miniapp_button` не отдаёт web_app
  кнопку для не-HTTPS адреса: иначе Telegram отклоняет всё сообщение.
* `connector/tests/test_miniapp_setup.py` — тесты этих правил (настройка
  сохраняется, «example.com» нигде не подставляется).
