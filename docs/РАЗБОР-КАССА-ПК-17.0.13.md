# Разбор перед раундом 17.0.13: взаимодействие кассы, ПК и панели

Основание: ответы раунда вопросов от 2026-09-11 и замеры из
`docs/ЗАМЕР-КАНАЛ-17.0.13.md`. Ниже — противоречия, риски, варианты с ценой и
рекомендация. Продуктовые решения (LAN, SQLite как источник правды, минимум
зависимостей, фронтенд без бандлера) не меняются.

## Ответы раунда и что из них следует

| Вопрос | Ответ | Следствие |
|---|---|---|
| Касс одновременно | **одна** | Presence нужен «на вырост», но сложность та же: одна строка в списке |
| Смена IP ПК | **после перезагрузки роутера** | Обязателен фон-перескан и «последний живой адрес»; ручной ввод IP кассиру не возвращаем |
| Список касс в панели | **полный** | Нужны поля «кто», «когда вошёл», «когда последний раз отвечал» → в `cashier_tokens` добавляется `last_seen` |
| Обновление APK | **предлагать при старте, с changelog** | Ответ `/api/app/android` расширяется; оболочка показывает «что нового», файл и размер |
| Кто чинит «не видно кассу» | **владелец по телефону** | Кассир ничего не жмёт: восстановление автоматическое; кнопки — на панели выбора сервера у владельца |
| Автовыгрузка очереди | **таймер ~20 с + прогресс** | Очередь уходит сама, кассир видит «N из M» |
| Дубль при обрыве на ответе (F1) | **чинить в этом раунде** | Меняется только страница: очередь переиспользует `request_id` уже отправленного запроса |
| Presence | **heartbeat в SQLite** | Миграция `ALTER TABLE cashier_tokens ADD COLUMN last_seen` + страховочная копия базы (механизм уже есть) |
| Каталог по событию | **касса перечитывает сама** | Новое событие `catalog_changed` в шине; формат денежных событий не трогаем |
| Цена изменилась при собранной корзине | **предупредить кассира** | Перед оплатой сверяем цены корзины с каталогом: «в каталоге 550 вместо 500» + «Обновить корзину» |
| Сигнал «касса офлайн» | **панель + Telegram** | Порог в минутах в настройках, по умолчанию выключен (телефон на ночь уносят домой) |
| Объём | **всё сразу, один раунд** | Один APK `versionCode 170013`, одна правка страницы, одна миграция |

## Противоречия (проговариваю, а не замалчиваю)

1. **«Кассир чинит сам» (критерий готовности) vs «чинит владелец».** Формально
   противоречие. Разрешение, не меняющее продукт: касса восстанавливается **сама**
   (health сохранённого адреса при старте, фон-перескан, автоповтор с backoff) —
   кассир не вводит адрес и не жмёт технических кнопок; владелец получает
   ручную кнопку «Переподключиться» и статус в панели. Критерий выполняется,
   ответ заказчика тоже.
2. **«Одна касса» vs «полный список».** Список из одной строки — нормально:
   он же покажет подменный телефон и «касса офлайн». Цена списка почти не
   зависит от их числа.
3. **Офлайн-таймер vs «не долбить сервер».** Таймер работает только при непустой
   очереди и живой связи, с паузой 5→30 с при ошибках; на пустом телефоне
   сеть не дёргается вообще.
4. **Проверка APK «на целостность» vs отсутствие AndroidX/FileProvider.** Полная
   проверка sha256 внутри оболочки требует скачать APK в приватный каталог и
   отдать его установщику через `FileProvider` — это AndroidX (запрещено) либо
   свой `ContentProvider` (дорого и рискованно). В этом раунде: сервер отдаёт
   `size_bytes` + `sha256` + changelog, оболочка **сверяет имя, размер и версию**
   до открытия загрузки и показывает их кассиру; битой загрузке установщик
   откажет сам (подпись APK — часть контракта Android). Отступление от принципа
   (AndroidX) оставлено на отдельное «да» — см. вариант C.

## Риски

| Риск | Оценка | Чем закрыт |
|---|---|---|
| Правка офлайн-контура задевает деньги | высокий по последствиям, низкий по вероятности | Меняется **только** генерация `request_id` для записи очереди; проводка, статусы, права и идемпотентность сервера не трогаются. Контракт: тест «повтор с тем же id не создаёт вторую продажу» |
| Таймер выгрузки грузит слабый ПК | низкий | Последовательно, по одной записи, пауза между попытками; замер `sell` — 3 мс |
| Предупреждение о цене тормозит продажу | средний (скорость кассира святое) | Сверка — один запрос каталога (3 мс) до открытия модалки оплаты; при расхождении — мягкая плашка, оплата не блокируется |
| Telegram-алерт спамит | средний | Порог в минутах, тихие часы бота уже есть, по умолчанию выключен |
| Миграция базы на живом ПК | низкий | Механизм `ADDED_COLUMNS` уже делает копию в `backups/pre-migration-*.sqlite3` |
| Ложный «офлайн» в панели, когда телефон просто уснул | средний | Онлайн = отклик за последние 60 с; статус подписан словом «молчит N мин», а не «сломалась» |

## Варианты и цена

Оценка в часах senior-разработчика и в рублях при ставке 2 500 ₽/ч (ориентир рынка
для правок в чужом коде без документации); в скобках — «своими руками» владельца.

| Вариант | Что входит | Часы | Рубли |
|---|---|---|---|
| **A. Критичное** | Фикс дубля (F1), таймер очереди с прогрессом, честный индикатор связи/потока, таймауты запросов | 6–8 | 15–20 тыс |
| **B. Рекомендуемый** (= выбран «всё сразу») | A + автопереподключение и фон-перескан, помнить живой IP, «Проверить обновление» с changelog и размером, `catalog_changed`, presence в SQLite + список касс в панели, Telegram-алерт, TTL офлайн-QR, докуменация и тесты | 20–26 | 50–65 тыс |
| **C. Максимум** | B + скачивание APK внутри оболочки со сверкой sha256 (свой `ContentProvider`), фон-скан по расписанию, история сессий касс в панели | 30–36 | 75–90 тыс |

Что **ломает** каждый вариант и как откатывать:
* Все три меняют `site/cashier.html` → поднимается `CACHE` в `site/sw.js`, иначе
  телефон останется со старой вёрсткой (иначе «ничего не изменилось»).
* B и C трогают Kotlin → `versionCode 170013`; откат = `git revert` записи
  17.0.13 и повторная раздача APK (данные WebView при откате не теряются,
  `applicationId` не меняется).
* B и C добавляют колонку `last_seen` — откат кода без отката базы безопасен:
  лишняя колонка старому коду не мешает.
* Деньги: F1-фикс не меняет ни одной серверной строки. Откат фикса возвращает
  риск двойной продажи при обрыве на ответе — это регресс, а не «как было».

## Рекомендация

Идти **вариантом B** (он же выбранный «всё сразу»), с двумя оговорками:
полную проверку sha256 внутри оболочки не делать в этом раунде (это вариант C и
отступление от «без AndroidX»), и Telegram-алерт по умолчанию выключить, включив
его настройкой `cashier_offline_alert_min` (0 = выключено).

Порядок внутри раунда — от денег к удобству: F1 → канал (таймауты, статус,
автопереподключение) → офлайн-очередь → каталог по событию → presence и панель →
APK/changelog → документация и тесты.
