# PrintFlow 5.0 — справочник для ИИ: что уже есть в системе

Обновлено 17.08.2026. Этот файл — карта существующего функционала: чтобы,
работая над проектом, ИИ не предлагал и не дублировал то, что уже реализовано,
и точно знал, где что лежит.

---

## 1. Архитектура

PrintFlow 2.0 — локальная система управления 3D-производством (Bambu Lab P1S/X1C/A1 + AMS).

- **Коннектор** (`connector/`, Python 3.10+, единственная зависимость — `paho-mqtt`):
  локальный HTTP-сервер на `http.server`, источник правды — SQLite в каталоге
  пользователя (`%APPDATA%\PrintFlow` на Windows, `~/.config/printflow` на Linux/macOS).
- **Интерфейс** (`site/`): одностраничник на чистом JS (без сборщика и библиотек),
  роутер по хэшу (`#dashboard`, `#printers`, `#queue`, `#orders`, `#customers`,
  `#finance`, `#inventory`, `#niches`, `#calc`, `#library`, `#settings`).
- Бренд витрины — NOZZA, PrintFlow — внутреннее имя.

## 4. Уже реализованные возможности

### Управление принтером (Bambu Lab, LAN-режим)
- MQTT/TLS (8883), камера (6000, JPEG/MJPEG), FTPS (990), SSDP-поиск принтеров.
- Команды с белым списком и серверными пределами: пауза/продолжить/стоп, свет,
  скорость (1–4), температуры сопла/стола, вентиляторы, парковка и перемещение осей,
  подача/выгрузка филамента, калибровка стола/вибраций, таймлапс, skip-объекты.
- Опасные команды требуют подтверждения в интерфейсе.
- **AMS**: слоты с типом/цветом/остатком (нормализация 0–100), назначение
  материала и цвета в слот (`ams_filament_setting`), подача/выгрузка, активный слот,
  температура и влажность AMS.

### Автоматический учёт (всё отключается в настройках)
- Старт печати → задание + заказ в статус «Печать» (связь по имени файла/номеру).
- Завершение → списание пластика с катушки активного слота AMS (`tray_uuid`),
  энергия, износ, себестоимость заказа, наработка принтера.
- Доход в кассу при переводе заказа в финальный статус (однократно).
- Брак: потеря в ₽ (пластик + энергия + износ) в ленту событий.
- Постоянные расходы начисляются по расписанию; налоги НПД/УСН/патент/своя ставка;
  резерв под налоги; точка безубыточности; P&L по месяцам.

### Сторож печати (watchdog)
- HMS-коды → понятный текст; при серьёзном уровне — пауза + кадр камеры.
- Зависание (прогресс не растёт), холодное сопло при печати → тревога.
- «Пластик заканчивается» по остатку активного слота AMS.
- Регламент ТО по наработке часов (стол, сопло, смазка, ремни…).

### Очередь и планирование
- Общая очередь парка, приоритеты, автозапуск, тихие часы (23:00–08:00).
- Группировка по материалу (меньше перезаправок AMS), проверка остатков катушки
  перед стартом, запуск с выбором плиты/AMS-маппинга/калибровок.

### Telegram-бот (включён в настройках, long polling)
- Команды: `статус`, `кадр`, `очередь`, `деньги`, `день`, `пауза`, `продолжить`,
  `свет`, `стоп` (с подтверждением «стоп да»), `помощь`.
- Автоуведомления: завершение, ошибка, пауза, низкий пластик, тревоги сторожа,
  ТО — с кадром камеры (настраивается `notify_*`).
- Бот приватный: отвечает только владельцу по chat_id.

### Стеллаж магазина (раздел `#shelf`) — обновлено 17.08.2026
- Позиции стеллажа: название, привязка к каталогу, цена ценника, себестоимость
  штуки, мин. остаток, фото, остаток штук.
- Приход с партии печати (`shelf/produce`): выбор задания из журнала → себестоимость
  штуки из себестоимости задания; или вручную.
- Продажи: быстрое «−1 шт» (`shelf/sale`) и «Продажи за день» (`shelf/sales`,
  несколько позиций одной операцией, канал `shelf`/`online`). С ценой — проводка
  дохода с пометкой «стеллаж»; без цены — только списание штук (деньги видит 1С).
- Инвентаризация (`shelf/inventory`): ожидалось vs факт, расхождение в журнал.
- QR-ценник: `shelf/qr-link` отдаёт URL страницы `shelf.html?id=…` (открывается
  телефоном: остаток, цена, «Продать N шт»), модалка с QR и печатью.
- Аналитика: продажи за 7/30 дней, скорость шт/день, «хватит на N дней»,
  план пополнения, мёртвый сток (14 дней без продаж), остаток в ₽.
- Модуль: `connector/printflow/shelf.py`; таблицы `shelf_items`, `shelf_moves`.

### Автоматизация и уведомления (17.08.2026)
- **Telegram**: inline-кнопки (пауза/продолжить/свет/стоп/кадр) в сообщениях,
  утренний дайджест (`digest_time`), еженедельный отчёт (`weekly_report_day/time`),
  команда «готов N» (статус заказа + шаблон клиенту).
- **AMS-мониторинг**: сверка остатков AMS ↔ склад (расхождение >20 п.п. → событие
  и Telegram), история смены катушек по слотам (смена tray_uuid), «закончился
  пластик» по HMS-кодам runout, влажность AMS выше порога → «пора сушить»,
  проверка материала слота перед автозапуском (`queue_check_material`).
- **Многоцветная печать**: поле `orders.colors` (JSON [{color,grams}]), списание
  с катушек по цветам (`consume_order_colors`), продувка 12 г/смену в калькуляторе
  (`color_swaps`).
- **Сушка**: таблица `drying_sessions`, API `spool/dry`.
- **AMS-профили**: таблица `ams_profiles`, API save/delete/apply (отправляет
  настройки слотов на принтер).
- **QR катушки**: страница `spool.html?id=…` — сканируете, выбираете слот,
  `spool/bind` привязывает катушку к слоту.
- **Оценка печати до запуска**: парсер 3MF/G-code (`estimate.py`) — время и граммы
  показываются в очереди; оценка сохраняется в `print_jobs.est_minutes/est_grams`.
- **Журнал брака**: таблица `defects`, API `defect/save|delete`, причина/фаза/код/
  граммы/потеря ₽; в карточке заказа блок брака и кнопка «Записать брак».
- **Фото к заказу**: таблица `order_photos`, загрузка или «кадр с камеры»,
  авто-снимки при событиях печати (start/complete/error/pause) в каталог `photos/`.
- **Чек-лист качества**: `orders.qc_done` (JSON), пункты из настройки `qc_checklist`.
- **SSE**: `/api/stream` — событие «refresh» при новых событиях; фронт снижает
  поллинг до 15 с, когда SSE работает.
- **Отложенные команды**: таблица `scheduled_commands`, API
  `schedule/command|delete`, выполнение в фоновом цикле.
- **Умная очередь**: сортировка по дедлайну заказа (`orders.due`) раньше приоритета.
- **«Готово через N минут»**: `notify_finish_remind_min` — Telegram за N минут до финиша.
- **ABC-анализ**: `/api/abc?days=30` — классы A/B/C по выручке (карточка в отчётах).
- **Статистика расхода пластика**: `/api/filament-stats` — по материалам и цветам
  (карточки в «Складе пластика»).
- **История цен**: таблица `price_history`, запись при сохранении заказа,
  `/api/price-history`, кнопка в карточке позиции каталога.
- **Шаблоны ответов**: настройка `reply_templates`, `/api/templates`,
  раздел «Библиотека → Шаблоны ответов».
- **Напоминания о закупке**: `restock_remind` — раз в день катушки ниже порога.
- **Браузерные уведомления**: `browser_notify_enabled`, Web Notifications API.
- **Проверка обновлений**: `updater.py`, `/api/update-check`, плашка в настройках.
- **Логи в файл**: `logging_setup.py` — `connector.log` в каталоге данных,
  ротация 2 МБ × 3 копии.
- **Фильтр журнала печати**: поле поиска в «Очередь → Журнал печати».

### Панель «Обзор» (дашборд) — обновлено 17.08.2026
- KPI-ряд: печатает сейчас, очередь (часы и % от недельной ёмкости), активные
  заказы, «требуют внимания» (просроченные сроки), «ждём оплату», прибыль за период,
  напечатано сегодня, «нужно пластика».
- **Активная печать**: процент, слой, осталось, ETA, потрачено ₽, итог печати,
  стоимость часа, заказ; пустое состояние «свободен».
- **Спидометр «прибыль за час печати»** (SVG) против нормы 250 ₽/ч.
- **AMS на главной**: слоты с остатками и предупреждением ниже порога, активный слот.
- **Пластик на очередь**: потребность очереди по материалам vs склад.
- **Таймлайн печати за день** (API `/api/timeline`): задания, простой между ними.
- График денег/часов/граммов по дням (7/30/90 дней), парк принтеров, ближайшие
  сроки, лента событий.
- **Настройка виджетов** (кнопка «◫ Виджеты»): скрытие/возврат, localStorage.
- **PDF** (кнопка «⎙ PDF»): печать только панели, print-стили.
- Режим «Стена» (из раздела Принтеры): крупные плитки, камера, прогресс, AMS-предупреждения.

### Прочее
- Командная палитра Ctrl+K (разделы, действия, поиск по заказам/клиентам/катушкам),
  `N` — новый заказ, `/` — поиск.
- Склад пластика: катушки, остатки, автосписание, пополнение, ручное списание,
  база изделий (граммы/часы/цена подставляются в заказы и калькулятор).
- Калькулятор: себестоимость партии (пластик, энергия, износ, упаковка, брак,
  ручное время), цена с наценкой/комиссией канала/скидками, прибыль за час.
- Клиенты: автосоздание из заказа, сегменты (новый/повторный/постоянный), долги.
- Ниши: воронка (показы → обращения → заказы → повторные), вердикт по прибыли за час.
- Финансы: P&L, налоги с кварталами и лимитами, кассы, постоянные расходы,
  долги, ТБУ, экспорт CSV (отчёт и проводки).
- Заказы: канбан с drag&drop, таблица, фильтры, экспорт CSV, экономика заказа
  (комиссии, налог, прибыль, прибыль за час), статусы настраиваются.
- Библиотека: чек-листы (прогресс в localStorage), инструкции, копирование кода,
  печатные материалы NOZZA (ценники с QR, наклейки, постеры, визитки) и
  материалы витрины (воблеры, прайс на подставку, таблички зон, карточки
  «как заказать», плакат «закажи по QR»). Статьи: ночная смена, авто-эжектор,
  сеть и доступ, стартовый закуп PLA, витрина и QR-заказ, Telegram-панель,
  3D-витрина.
- Бэкап: скачивание JSON (секреты не попадают), восстановление, перенос данных
  из старой браузерной версии, полная очистка данных.
- Безопасность: сервер слушает 127.0.0.1, Origin-проверка, секреты не в Git,
  path traversal защита в статике, лимиты команд принтера.

## 5. Горячие клавиши и соглашения

- `Ctrl+K` — командная палитра и поиск; `/` — то же; `N` — новый заказ; `Esc` — стена.
- Состояния заданий: `queued → starting → running → done|failed|cancelled`.
- Статусы заказов: `new → estimate → prepay → queue → printing → post → ready → done`
  (настраиваются; `is_final` закрывает заказ и создаёт доход).
- Все суммы в рублях; числа в UI форматируются `ru-RU`; CSV с разделителем `;`.
