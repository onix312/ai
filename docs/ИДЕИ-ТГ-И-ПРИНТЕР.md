# Идеи глобального обновления: Telegram-бот + принтер (август 2026)

> Рабочий список для согласования. Сначала — фикс камеры, дальше — два больших
> блока (Telegram и принтер) плюс сквозные темы. Каждый пункт: что / зачем /
> оценка (⚡ до полудня · ◐ день · ▣ несколько заходов). Всё остаётся в пределах
> локального компьютера + уже согласованных исключений (Telegram Bot API, GitHub).

## 0. Камера (диагноз и фикс)

**Корневая причина:** `camera.py` работает только по LAN (порт 6000, нужны
`host`+`access_code`). Принтер, добавленный из облака («Найти принтеры»),
получает `serial`, но НЕ `access_code` (облако его отдаёт как `dev_access_code`,
но `bambu_cloud.get_devices()` его выбрасывает) и НЕ `host` (облако не знает
локальный IP).

- **0.1 `get_devices` отдаёт `dev_access_code`** ⚡ — подстановка кода в карточку
  принтера без ручного переписывания (это заявлено в доке, но не реализовано).
- **0.2 «Найти принтеры» = облако + SSDP** ⚡ — облачный список даёт serial+код,
  `bambu.discover()` даёт IP; объединяем по serial. Камера/FTPS заработают по LAN
  в облачном режиме.
- **0.3 RTSP-фолбэк на порт 322** ◐ — новые прошивки и X1 отдают RTSP
  (`rtsps://bblp:code@ip:322/streaming/live/1`); P1S остаётся на 6000. Подсказка
  про «LAN Mode Liveview» в настройках принтера.
- **0.4 Диагностика камеры по этапам** ⚡ — отдельная проверка: порт открыт →
  рукопожатие → первый кадр; честный текст что именно не так (аналог `health()`).
- **0.5 Удалённая камера через TUTK P2P (опционально)** ▣ — `get_ttcode`/
  `get_camera_credentials` → P2P-клиент TUTK. Единственный способ смотреть кадр
  вне дома без VPN; хрупкий, держим за флагом и фолбэком на LAN.

## A. Telegram-бот — принтер в кармане (главный упор)

Текущий бот — текстовые команды + пара inline-кнопок. Цель — превратить его в
полноценный пульт и диспетчера.

### A.1 Живой пульт принтера

- **A.1.1 Живой дашборд-сообщение** ◐ (из «осознанно осталось») — во время печати
  одно сообщение автообновляется через `editMessageText` (процент, слой, ETA,
  сопло/стол, осталось ₽, заказ). Обновление только при изменении данных (шина
  `bus.py` уже есть) — не спамим API.
- **A.1.2 Полная inline-панель управления** ◐ — кнопки: пауза/продолжить/стоп,
  свет, скорость (4 уровня), кадр, видео, таймлапс, вентиляторы, температуры.
  Меню вместо набора команд.
- **A.1.3 «Кадр» → «видео 10с» → «таймлапс»** ◐ — собрать N кадров в GIF/video
  (`sendAnimation`/`sendVideo`); таймлапс из архива снимков или команды
  `ipcam_timelapse` (уже есть) + забор файла.
- **A.1.4 Глубокие данные принтера** ⚡ — ✅ 11.2 («датчики»: температуры с
  целями, вентиляторы, скорость, WiFi/прошивка, AMS с влажностью и слотами,
  HMS-расшифровка; сверка слотов с катушками склада по tray_uuid).
- ~~A.1.4 (исходная формулировка)~~ — команды/кнопки: «температуры» (сопло/
  стол/камера), «вентиляторы», «wifi/прошивка», «AMS» (каждый слот: цвет, тип,
  %, влажность/температура блока), «HMS» (расшифровка ошибок из `hms.py`).
- **A.1.5 Команды из чата: скорость/темп/вентилятор/замена филамента/калибровка** ◐
  — белый список `bambu.command()` уже есть; оборачиваем в безопасные текстовые
  команды с подтверждением для опасных (нагрев/движение/стоп).
- **A.1.6 Многопринтиерный выбор** ⚡ — сейчас `manager.get()` берёт первый
  подключённый. Добавить выбор принтера (`/принтер 2`) и имя принтера в каждом
  сообщении.

### A.2 Уведомления с действиями

- **A.2.1 Уведомления с inline-кнопками** ◐ — «печать завершилась» → [кадр]
  [следующее задание] [снял]; «ошибка HMS» → [пауза] [стоп] [игнорировать];
  «мало пластика» → [списать] [закупить]. Действие не выходя из чата.
- **A.2.2 Расшифровка HMS-ошибок + подсказка** ⚡ — в сообщение добавлять не код,
  а человеческий текст (`decode_list` уже есть) и ссылку на wiki/`ТЕХНИКА-ПЕЧАТИ`.
- **A.2.3 Спагетти-тревога с видео-клипом** ◐ — при срабатывании `spaghetti.py`
  слать не один кадр, а GIF последних 10–20 кадров + кнопку [пауза].
- **A.2.4 «Готово через N минут» + финиш с фото** ⚡ — уже есть `remind_finish`,
  добавить кадр и кнопку [снял].

### A.3 Работа с заказами/очередью из чата

- **A.3.1 Полное управление очередью** ◐ — [старт] [пауза] [отмена] [выше/ниже]
  для каждого задания; «печать 1001» запускает заказ из очереди.
- **A.3.2 Подписка на заказ** ◐ — «следи 1001»: прогресс каждые 10% или N минут,
  с ETA и кадром; авто-отписка при завершении.
- **A.3.3 Фото к заказу из чата** ⚡ — прислал фото → привязывается к последнему
  активному заказу (или «фото 1001»).
- **A.3.4 Продажа/выдача/оплата кнопками** ◐ — вместо текстовых «−1», «выдать»,
  «оплата» — inline-меню с поиском позиции, быстрыми суммами и готовым текстом
  клиенту в буфер.
- **A.3.5 Отчётность по запросу** ⚡ — «итоги недели/месяца», «рейтинг изделий»,
  «долги», «брак» — из уже существующих `analytics.py`/`insights.py`.

### A.4 Режимы и безопасность

- **A.4.1 Несколько владельцев + права** ◐ — список `chat_id` с ролями
  (владелец/смена), команды «стоп/нагрев» только у владельца.
- **A.4.2 Тихие часы для бота** ⚡ — ночью не шлём некритичные уведомления
  (своя маска, не только «тихие часы» принтера).
- **A.4.3 «Спроси принтер» правилами** ◐ — «сколько осталось?», «что печатает?»,
  «когда закончит?», «сколько заработал?» — разбор по ключевым словам, без ИИ.

### A.5 Клиентский бот (крупно, опционально)

- **A.5.1 Публичный бот для клиентов** ▣ — заказ по номеру/телефону показывает
  статус (как `track.html`), фото результата, напоминание «готово». Отдельный
  токен, никаких внутренних данных. Дальше — приём заявок прямо в бота.

## B. Принтер: больше информации и взаимодействия

### B.1 Телеметрия и история

- **B.1.1 Журнал телеметрии** ▣ — писать температуры/вентиляторы/прогресс в
  таблицу с периодами; графики «температура по слоям», «аномалии за печать».
- **B.1.2 Паспорт печати** ◐ — к каждому заданию в журнале: факт vs оценка
  слайсера, материал/цвет/слот AMS, снимки, HMS. (Частично есть в `analytics`.)
- **B.1.3 Контроль прошивки** ⚡ — версия из `get_version`, уведомление о новой
  прошивке из облака.
- **B.1.4 Карта состояния AMS в реальном времени** ⚡ — слоты, тип/цвет/остаток,
  прогноз «кончится через N г печати» (текущий расход × остаток).

### B.2 Надёжность и сторож

- **B.2.1 Авто-пауза на HMS-ошибке** ◐ — критичная ошибка → пауза + фото + Telegram
  (сейчас только сообщает). Выключается в настройках.
- **B.2.2 Повтор задания после сбоя** ◐ — failed-задание с кнопкой «перепечатать»:
  клон в очередь с теми же параметрами (и пометкой «повтор»).
- **B.2.3 Preflight 2.0** ◐ — расширить `preflight.py`: сопло vs профиль файла,
  влажность AMS, SD-карта, калибровка просрочена (часть уже в доке-анализе).
- **B.2.4 Спагетти-детект 2.0** ◐ — скоринг кадра + меньше ложных срабатываний;
  обучение порога по истории.

### B.3 Управление

- **B.3.1 Управление SD/облачными файлами** ◐ — список облачных проектов, удаление,
  свободное место; для LAN — дерево SD (частично есть).
- **B.3.2 Живая регулировка скорости/потока** ⚡ — слайдеры скорости печати и
  потока (`print_speed`, `gcode` M220/M221) из UI и Telegram.
- **B.3.3 Таймлапс-конвейер** ◐ — включение таймлапса командой, забор готового
  файла (FTPS/облако), отправка в Telegram, хранение к заданию.

## C. Сквозные (глобальное обновление)

- **C.1 Конструктор правил «если-то»** ▣ (из `ИДЕИ-АВТОМАТИЗАЦИИ.md`) — настраиваемые
  триггеры: заказ «Готов» → сообщение клиенту; катушка <15% → список закупок;
  долг >14 дней → напоминание; ошибка печати → переделка; доход → отложить налог.
  Заменяет десяток отдельных флагов.
- **C.2 Браузерные Web Push** ◐ — уведомления в браузере/телефоне (роадмап 0.2).
- **C.3 Мини-панель `/m` 2.0** ◐ — больше кнопок: скорости, вентиляторы, AMS,
  запуск следующего задания, кадр.
- **C.4 Голосовой ввод в Telegram** ▣ — через голосовое сообщение (без внешнего
  ASR — локальный движок опционален). Отложить до C-блока.
- **C.5 Шифрование секретов в SQLite** ◐ (роадмап 10.10) — Access Code / токены
  через Fernet, ключ в `DATA_DIR` с правами 600.
- **C.6 Мультипринтиерное выравнивание** ▣ — многие места заточены под 1 принтер
  (очередь, `get()`, «снял»); пройтись и сделать честную поддержку N принтеров.

## Предлагаемый порядок (что делаем первым)

1. **Фикс камеры** (0.1–0.4) — быстро, закрывает заявленную проблему.
2. **Telegram-пульт** (A.1.1–A.1.5, A.2.1) — главный упор, максимум ценности.
3. **Уведомления с действиями + заказы из чата** (A.2, A.3).
4. **Принтер: телеметрия/паспорт/сторож** (B.1, B.2).
5. **Сквозные** (C.1, C.2) и опциональные крупные (TUTK-камера, клиентский бот).
