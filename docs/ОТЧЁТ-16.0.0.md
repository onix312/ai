## Контракт денег (реализовано и покрыто тестами)

| Требование | Как обеспечено |
|---|---|
| Нет фейковой выручки | Создание платёжа (new) не пишет проводку и не трогает `orders.paid`; выручка появляется только в `confirm` |
| Нет дублей | `request_id` (уникальный индекс) в сервисе + идемпотентный HTTP-слой (`idempotent=True` на `/api/sbp/create`) |
| Подтверждение не дублирует проводку | Повторный `confirm` возвращает `already_recorded`; одна проводка на платёж |
| Долг закрывается только при подтверждении | `confirm` → `accounting.add_payment` (заказ) или `add_transaction` (продажа без заказа) |
| Отмена без тихих правок | `reject` не трогает деньги; платёж помечается `rejected` с причиной, в аудите |
| Возврат обратим и виден | `refund` только для подтверждённого, требует отметки «возврат выполнен в банке», пишет обратную проводку, снимает оплату с заказа |
| Счёт настраиваемый | `sbp_account_id` (по умолчанию отдельный счёт «СБП»); при подтверждении — на выбранный счёт |
| Аудит | каждое действие → `audit_log` (кто/когда/действие) + `events` |

## Статусы платежа

`new → pending → confirmed / rejected / refunded`

## API

- `GET /api/sbp/state` — экран «Входящие»: счётчики, pending, последние, настройки.
- `GET /api/sbp/payments?status=&order_id=&limit=` — журнал.
- `GET /api/sbp/settings` — настройки и счёт СБП.
- `POST /api/sbp/create` — создать платёж (идемпотентен).
- `POST /api/sbp/confirm` — подтвердить: проводка + закрытие долга.
- `POST /api/sbp/reject` — отклонить (выручка не создаётся).
- `POST /api/sbp/refund` — возврат (`bank_done=1`, руководитель/владелец).
