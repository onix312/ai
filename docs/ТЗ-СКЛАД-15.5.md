# ТЗ — проект «Склад 15.5»: ручные корректировки «−1» / «+1»

Дата: 2026-09-04. Заказчик: владелец PrintFlow. Исполнитель: Arena-агент.
Промт: «доработка склада — проект Склад 15.5». Раунды вопросов проведены
в чате (Раунд 1 — 6 вопросов, Раунд 2 — 4 вопроса), решения ниже.

## 1. Цель

Вести склад проще и безопаснее: одна кнопка — одно простое действие;
остатки меняются только через регистр движений; деньги не затрагиваются;
любое изменение видно в журнале и обратимо.

## 2. Ключевые решения заказчика

| № | Вопрос | Решение |
|---|--------|---------|
| 1 | «−1» = списание или откат движения | Ручная корректировка: движение −1 в `stock_moves` с `doc_kind="manual"`; **не** продажа, **не** откат чужого движения. |
| 2 | Где кнопки «−1»/«+1» | (а) разрез склада — **кнопка «Позиции» на карточке склада** открывает список позиций с кнопками у каждой строки (клик по карточке ничего не делает); (б) карточка товара — кнопки в разрезе остатков по каждому складу. |
| 3 | Подтверждение/отмена | Короткое подтверждение (`confirmDanger`, как во всей панели): «Убрать 1 шт „Адресник“ со склада „Магазин“?» → одна кнопка действия + «Отмена». Полей и форм нет. |
| 4 | Кто может «−1» | Все, у кого открыта локальная панель (как все текущие кнопки). Каждое списание/возврат пишется в журнал аудита. Права ролей — когда/если кнопка появится в боте (там роли уже есть). |
| 5 | Охват первой версии | «−1» и «↩️ Вернуть» **плюс симметричная «+1»** (ручное оприходование 1 шт: нашли потеряшку/излишек) — тоже корректировка без денег, тоже обратимая. Отдельный экран «Корректировки» — не делаем (видно в движениях товара и оборотке). |
| 6 | Склад и полка: связывать? | **Отложено.** Полка (`shelf.py`, `shelf_items` — отдельный учёт со своим списанием) и склад пластика (катушки, `money.js`) в v1 не трогаем; отдельный раунд после приёмки v1. |
| 7 | Склад пластика | См. п.6 — отдельный раунд после v1. |
| 8 | Что не делаем | Полка/пластик, пин-коды и роли в панели, экран журнала корректировок, поля причин (фиксированная заметка), массовые списания, продажа/чек/касса/онлайн-деньги. |
| 9 | Приёмка | Автотесты pytest + смоук через API в отчёте; панель заказчик проверяет сам по сценарию из отчёта. |

Дополнительные решения:

- **Резерв**: «−1» работает только по свободному остатку
  (остаток − активные резервы). Если свободно 0 — кнопка неактивна,
  подсказка «N шт в резерве под заказы». Резерв под оплаченный заказ
  сломать нельзя. «+1» ограничения по резерву не имеет.
- **Возврат**: откат = удаление движения (как распроведение документа,
  `drop_doc_moves`): в регистре движения как не было, остаток и средняя
  себестоимость восстанавливаются штатным пересчётом; в оборотке пара
  «−1/+1» не висит. Факт отката фиксируется в аудите. Кнопка «Вернуть»
  доступна всегда, пока движение существует: в тосте сразу после действия
  (`toastUndo`) и в истории движений товара (с подтверждением).
- **Защита от минусов**: сервер отклоняет списание, если свободный
  остаток < 1; фронт делает кнопку неактивной при 0.
- **Возврат не создаёт минусов**: откат оприходования («+1») отклоняется,
  если найденной штуки уже нет в свободном остатке (ушла продажей или в
  резерв). Откат списания («−1») только добавляет штуку обратно и минус
  создать не может — он разрешён всегда, пока движение существует
  (в т.ч. когда остаток уже распродан: это случай «списали по ошибке,
  штука нашлась»).
- **Банк идей**: ~100 дополнительных идей заказчик пришлёт списком в чат,
  исполнитель разносёт их с оценкой стоимости; на v1 не блокирует.

## 3. Что происходит технически

Списание 1 шт:

- в `stock_moves` пишется движение `qty = -1`, `doc_kind = "manual"`,
  `cost = -avg_cost` (средняя себестоимость по складу), `note` —
  «ручное списание»;
- никаких документов продажи, чеков, заказов, выручки, маржи, кассы,
  онлайн-денег, долгов — корректировка не имеет `doc_id` и не видна
  в финансовых отчётах;
- событие в `events` (журнал аудита): кто/что/где/когда.

Оприходование 1 шт («+1»): то же зеркально: `qty = +1`,
`cost = +avg_cost`, `note = «ручное оприходование»`. Без приходного
документа и денег.

Возврат: движение удаляется (как при распроведении), аудит фиксирует
откат. Повторный откат невозможен — движения уже нет.

## 4. Состав v1 (итерация 1)

**Бэкенд** (`stock.py`, `api.py`):
- `Stock.manual_adjust(nom_id, warehouse_id, delta)` — корректировка ±1
  с проверками (позиция и склад существуют; списание только по свободному
  остатку; дробные остатки — минусуем целую штуку);
- `Stock.revert_manual(move_id)` — откат ручного движения с проверками;
- `Stock.warehouse_positions(warehouse_id)` — позиции склада с остатком,
  резервом, свободным и себестоимостью (для экрана «Позиции»);
- API: `GET /api/warehouse/positions?id=`, `POST /api/stock/adjust`,
  `POST /api/stock/revert`;
- аудит `db.add_event("stock", …)` на каждое действие и откат.

**Фронт** (`products.js`, `index.html`):
- кнопка «Позиции» на карточке склада → модалка со списком позиций,
  в каждой строке «−1» и «+1» (неактивны, когда нет свободного остатка);
- в карточке товара, в разрезе по складам: «−1» / «+1» у каждого склада
  + резерв/свободно в подписи;
- подтверждение, тост с действием «Вернуть» сразу после клика;
- в истории движений товара у строк `manual` — кнопка «Вернуть»;
- тип движения `manual`: «Корректировка» в `DOC_KIND`/`DOC_EVENT`.

**Тесты и релиз**:
- pytest: корректировки ±1, откат, защита минусов и резервов,
  неприкосновенность денег/продаж/кассы, идемпотентность отката;
- `py_compile`, `node --check`, смоук через API;
- `APP_VERSION = 15.5.0`, запись в `CHANGELOG.md`, отчёт `docs/ОТЧЁТ-15.5.0.md`.

## 5. Приёмка (сценарий автотестов и смоука)

1. Приход 5 шт по себестоимости 100 ₽ → продажа 1 шт → остаток 4,
   выручка/касса зафиксированы.
2. «−1» со склада → остаток 3, средняя себестоимость не изменилась;
   продажи за 7/30 дней, выручка, касса, онлайн-деньги — не изменились;
   в `events` появилась запись.
3. Резерв 3 шт под заказ → «−1» отклонён (свободно 0), кнопка неактивна.
4. «↩️ Вернуть» списание → движение исчезло, остаток снова 4; повторный
   возврат невозможен; откат списания разрешён даже при нулевом остатке
   (штука нашлась), откат оприходования при пустом свободном остатке —
   отклоняется (ушло продажей/в резерв).
5. «+1» → остаток 5, себестоимость пересчитана по средней; откат → 4.
6. Кнопка «Позиции» на карточке склада показывает позиции с резервами;
   карточка товара показывает кнопки по каждому складу.
