# Помощник NOZZA — как включить и что проверить руками

Дата: 22.09.2026, версия 18.14.0. Решение: `docs/adr/0004-помощник-три-внешних-рантайма.md`.

Помощник — надстройка, а не часть учёта. Он выключен по умолчанию, и панель,
заказы, печать и касса работают без него ровно как раньше. Включается в три
шага, каждый шаг проверяется своей строкой в `pf.py doctor`.

## Что здесь есть

| Слой | Где живёт | Что делает | Порт |
| --- | --- | --- | --- |
| Модель | внешняя программа (например Ollama) | понимает фразу, отвечает по фактам базы и документам | 11434 |
| Речь | `agent/` (та же программа, второй порт) | запись голоса → текст на процессоре | 8791 |
| Личный ассистент компьютера | `agent/` | реестр навыков, своя база, индекс документов, окно `/ui`, файлы, знания, день цеха | 8799 |
| Агент компьютера (18.13) | `agent/` | стоп-слово, активное окно, снимок экрана, действия в чужих приложениях | 8799 |
| Панель помощника | `site/assistant.html` | разговор, каталог действий, входящее сообщение, журнал, ответ по фактам базы, день цеха, навыки агента | порт PrintFlow |

Все три внешние программы слушают только `127.0.0.1`. Адрес проверяется до
запроса: если в настройках окажется чужая машина, помощник откажется работать и
скажет почему, а не отправит туда данные клиентов.

## Включение (Windows, компьютер цеха)

1. **Модель.** Установите Ollama, затем в командной строке:

   ```
   ollama serve
   ```

   `ollama serve` оставьте работающим. **Во втором** окне PowerShell скачайте модель:

   ```powershell
   ollama pull qwen2.5:3b
   ```

   Панель PrintFlow → Настройки → «Локальный помощник»: включите помощника,
   впишите адрес `http://127.0.0.1:11434` и имя модели `qwen2.5:3b`.
   Модель не закреплена за системой намеренно — поле в настройках, имя берётся
   из того, что отдаёт ваш рантайм (`ollama list`). Если `ollama list` пуст,
   `ollama serve` ещё не означает, что модель скачана. Код запрашивает список
   через **GET** `/api/tags`, а POST возвращает 405. Предупреждение Ollama о
   таймауте облачной модели не блокирует локальный запуск.

2. **Проверка без сервера.** В корне репозитория:

   ```
   python pf.py doctor
   ```

   Блок «Локальный помощник» должен сказать «помощник готов», блоки «Голос» и
   «Агент компьютера» — «выключен», пока вы их не включили.

3. **Панель помощника.**

   ```
   python pf.py assistant --local
   ```

   На Windows можно вместо команды дважды нажать **`ЗАПУСТИТЬ-ПОМОЩНИК.bat`**
   рядом с `pf.py`. Из основной панели есть ссылка «Помощник» в левом меню
   (открывает отдельную вкладку); обычная панель при этом остаётся открытой.

   Откроется нативное окно с `http://127.0.0.1:<порт>/assistant.html`. Если
   pywebview не установлен, команда честно скажет об этом и откроет страницу в
   браузере. В браузере те же адреса: `/assistant.html`, `/assist`, `/помощник`.
   Сервер PrintFlow стартует при необходимости и переиспользуется, если уже
   работает: второй процесс учёта не запускается. Помощник — отдельная страница,
   но та же база и сервер панели; Ollama — отдельный процесс на порту 11434.

4. **Голос и агент** (необязательно, ставится отдельно от коннектора):

   ```
   cd agent
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   python -m agent
   ```

   Агент поднимет оба порта и напечатает, чего ему не хватает: нет модели речи,
   нет OCR, нет экрана. Затем в настройках панели включите «Голосовой вход» и
   «Агент компьютера» — пилюли в шапке панели помощника станут зелёными.

   Зависимости агента живут в `agent/.venv` и **не** попадают в окружение
   коннектора: `pf.py` не читает `agent/requirements.txt`.

5. **Модель речи.** Скачайте одну модель на процессор и положите рядом с
   агентом, например `vosk-model-small-ru-0.22` в папку `models/`. Видеопамять
   она не занимает: 8 ГБ уже делят текстовая модель и WebGPU-нарезка.

## Что добавилось в 18.14 — личный ассистент компьютера

PrintFlow стал одним из навыков ассистента. Новые навыки 18.14 живут в `agent/` и проверены автоматом там, где можно:

- **Реестр навыков (И136, И178, И180).** `agent/skills.py` — 18 живых навыков: `panel.*` (каталог действий, действие, вопрос по фактам базы), `files.*` (индекс, поиск, недавние, вопрос по документам, факты, файл в заказ, план и исполнение раскладки), `knowledge.shop` (знания цеха), `day.*` (брифинг и итог), `agent.*` (что умею, почему не получилось, журнал, новый навык словами). Риск `read` — без подтверждения, `write`/`system`/`irreversible` — с подтверждением человека на этом компьютере. `confirmed` в теле запроса не читается вовсе. Недоступный навык показывается с причиной, а не прячется.
- **Своя база (И138).** `~/.printflow/assistant.db` — память, индекс, журнал, факты, заметки, выученные навыки. Таблиц цеха в ней нет. Путь меняется `PRINTFLOW_ASSISTANT_DB`.
- **Файлы и знания (И142, И143, И144, И147, И148).** Индекс без зависимостей там, где можно (.docx/.xlsx как zip), .gcode только комментарии, .stl только метаданные, фото честно отказывается до навыка зрения. Отрывок с путём и номером строки, токены без стоп-слов, факты детерминированные с местом. Граница папок — `PRINTFLOW_ASSISTANT_FOLDERS`, `PRINTFLOW_KNOWLEDGE_FOLDERS`, `PRINTFLOW_DOWNLOADS_FOLDER`.
- **Ответ по фактам базы (И1).** `POST /api/assistant/ask` — вопрос владельца → факты из существующих сервисов панели и ответ только по ним; числа сверяются, расхождение — предупреждение. Без модели — факты и причина.
- **День цеха (И174).** `GET /api/assistant/day?kind=briefing|summary&days=N` — утро и вечер из тех же сервисов, что рисуют панели плана и финансов; без модели, текст предложениями для озвучки.
- **Окно ассистента (И139).** `GET /ui` на порту агента (только loopback, без внешних ресурсов) и его необязательная обёртка `pywebview` (`agent/window.py`). Страница показывает реестр навыков, журнал и подтверждение. Трей ждёт `pystray` и появился в 18.16 с уведомлениями о новых объявлениях (И197).
- **Новый навык словами (И180).** `my.*` из шагов существующих, всегда с подтверждением, без своих параметров, не может звать другой выученный, максимум 8 шагов.

Подробно: `docs/НАВЫКИ.md` — форма навыка, правила исполнения, живые 18 и каталог на вырост Н1–Н57, маршруты агента, настройки окружения, границы.

## Что добавилось в 18.21 — мозг помощника

Разговор стал главным, а маршрут фразы выбирает сервер, а не браузер:

- **Одна точка разговора.** `POST /api/assistant/chat` — мозг панели
  (`connector/printflow/assistant_brain.py`). Уточнение → память → арифметика,
  часы и «что ты умеешь» → цех без модели → компьютер через агента → планировщик
  на модели → разговор. Под каждым ответом «Как я понял» — какие слои сработали.
- **Цех без модели.** «Поставь на паузу P1S», «что с Альфой», «а у второго?»,
  «поставь его на паузу», «что с заказом 1042», «выдай его», «переведи заказ
  1042 в готово», «что с Марией», «кто должен денег», «какая выручка», «план на
  сегодня», «открой склад». Станок ищется по имени в любом падеже, модели,
  порядковому слову или местоимению; два подходящих — вопрос «какой?», короткий
  ответ завершает действие. Действие с печатью и деньгами — карточка с
  «Подтвердить», как и раньше.
- **Память.** «Запомни, что Мария берёт только PETG», «что ты помнишь про
  Марию», «забудь…», «меня зовут Олег». Панель помнит в базе цеха
  (`GET|POST /api/assistant/memory`), разговор переживает перезагрузку
  (`GET|POST /api/assistant/dialog`). Справа на странице — «Сейчас в цехе»
  (`GET /api/assistant/context`) и список памяти с «закрепить» и «забыть».
- **Компьютер.** Команды ПК из разговора («громкость 30», «открой блокнот»,
  «переключись на телеграм») уходят агенту (`POST /chat`, `mode=pc`); агент
  выключен — честная подсказка, агент не отвечает — кнопка «Запустить агента».
- **Агент.** Окно `/ui` — тоже разговор; руки на ПК стали настоящими (звук Core
  Audio, окна по имени программы, питание с минутой на отмену, озвучка SAPI,
  здоровье ПК); агент закрыт от сайтов в браузере (Origin/Host → 403). Подробно —
  `docs/НАВЫКИ.md` и `agent/README.md`.
- **Агент спрашивает панель.** Вопросы цеха в окне агента («что печатает P1S»,
  «сколько ему осталось», «кто нам должен», «открой заказы») отвечает мозг панели;
  действие, которое предложила панель («поставь его на паузу»), ждёт «Подтвердить»
  карточкой в окне агента и исполняется маршрутом каталога. Без модели агент
  понимает приветствие, «как дела», «кто ты», счёт с продолжением («а если
  поделить на 5?») и отвечает по-человечески, а не текстом ошибки Ollama.
- **Окно агента.** Метки «панель цеха» и «модель» в шапке, кнопка «открыть панель»,
  ссылки на разделы панели в ответах, карточка подтверждения с обратным отсчётом,
  навыки по группам (щелчок — ручной запуск, результат фразой), журнал по-русски;
  в окне 420 px ничего не уезжает, боковая панель выдвигается поверх ленты.

## Что добавилось в 18.22 — личный помощник и обучение

Помощник ведёт ваши личные дела и учится вашим словам. Всё работает без модели,
живёт в своей базе агента и машину не покидает.

- **Напоминания по-русски.** «Напомни через 20 минут выключить чайник», «напомни
  завтра в 10 позвонить маме», «в пятницу вечером про оплату интернета», «по
  будням в 8:30 зарядка», «каждые 2 часа пить воду». Без времени помощник
  спросит «когда?» и поймёт ответ («завтра в 10»). Сработавшее напоминание
  приходит карточкой в окне агента, звуком и голосом; «Готово» и «Отложить на
  10 мин» — кнопками или словами («я позвонил маме», «отложи на 15 минут»).
- **Будильник у агента.** Раньше таймер фокуса только записывался, а заметка «на
  завтра» не всплывала никогда. Теперь фоновый планировщик сам поднимает
  напоминания, таймеры, заметки со сроком и привычки.
- **Списки, цели, привычки, расходы, дневник.** «Добавь молоко и хлеб в
  покупки», «купил хлеб»; «моя цель — прочитать 12 книг до конца года»,
  «прочитал 3 книги» (помощник скажет, отстаёте ли и сколько нужно в неделю);
  «новая привычка: зарядка в 8», «я сделал зарядку» (серия дней подряд);
  «потратил 450 на такси», «сколько я потратил за неделю»; «запиши в дневник …»,
  «настроение 8». «Доброе утро» — ваш день одним ответом, вместе со сводкой цеха.
- **Обучение.** «Научись: когда я говорю «рабочий режим» — открой телеграм и
  громкость 30»; ««телега» — это телеграм»; «нет, я имел в виду …» после ошибки;
  «это значит …» сразу после «пока не понимаю»; кнопки «верно» и «не то» под
  ответом. Понятое моделью помощник запоминает сам — в следующий раз без
  модели. Выученное видно во вкладке «Обучение» и забывается одной кнопкой.
- **Окно агента.** Новые вкладки «Дела» и «Обучение», карточки уведомлений,
  оценки под ответами. Панель цеха (`site/assistant.html`) в этом выпуске не
  менялась; команды вроде «напомни …», сказанные в панели, она передаёт агенту
  (`mode=pc`), и напоминание звонит на компьютере с агентом.

## Правила, которые помощник не нарушает

- **Деньги и печать — только через «Подтвердить и выполнить».** Чтение
  (что печатается, очередь, долги, план, диагностика) выполняется сразу.
  Признак подтверждения берётся из каталога на сервере, а не из ответа модели.
- **Помощник ничего не сохраняет сам.** Черновик заказа становится заказом
  только после вашего «Сохранить заказ».
- **Действие в чужом окне ждёт человека.** Агент показывает окно подтверждения
  на этом же компьютере; неподтверждённое действие умирает через 60 секунд.
  Нет экрана — нет подтверждения, значит нет и действия.
- **Данные клиентов не покидают машину.** Имя, телефон и сумма уходят только в
  loopback; запись голоса не сохраняется ни на диске, ни в базе.
- **Каждое действие оставляет след.** Журнал событий `kind='assistant'` с
  пометкой источника — единственная замена отсутствующему входу.

## Риск, принятый владельцем

Панель помощника открывается **без входа** — так решил владелец (вопрос 2
допроса), вопреки рекомендации. Любой, кто достал до сети цеха, может нажать
«Подтвердить» и остановить станок или изменить цену. Компенсация — журнал с
пометкой источника и подтверждение на деньги и печать. Если риск станет
неприемлем, закрывать его надо входом в панель помощника, а не отключением
журнала.
