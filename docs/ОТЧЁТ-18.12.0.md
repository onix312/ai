# Отчёт 18.12.0 — сечения в браузере, пульт во вкладке «Принтеры», честный G-code своего движка

**Статус:** готово (все срезы реализованы и проверены). Базис — 18.11.0.

Задача владельца: «делай всё» — закрыть границы релиза 18.11.0, названные в
итоговом отчёте, и довести до конца отложенный WebGPU. Утверждённый объём:

1. GPU-сечения (WebGPU-слайсер — в согласованном виде предпросмотра, полный
   слайсер отделён отдельным ADR);
2. пультовые виджеты 18.11 во вкладке «Принтеры»;
3. шкала слоёв для экскурсии NOZZA и для любого G-code своего движка;
4. живая проверка FTPS-заливки Studio (то, что в 18.11 не влезло в песочницу).

## Срез 1. GPU-сечения (`site/assets/gpuslice.js`, новый модуль)

- Кнопка **«Сечения»** в карточке «Свой слайсер»; модели до 30 МБ режутся
  автоматически при выборе из библиотеки, крупнее — по кнопке.
- Конвейер: STL (бинарный и ASCII) → модель на стол (как `place_mesh`) →
  плоскости слоёв те же, что `_plane_heights` движка Stage 1 → сечение →
  сшивка контуров → площади и аналитика. Чистые функции без DOM, потому
  проверяются в node (`connector/tests/test_gpuslice.py`, 20 тестов).
- Три бэкенда с честной подписью: **WebGPU** (compute-шейдер, поток на
  треугольник, атомарный счётчик отрезков, буферы до 3 000 000 отрезков),
  **процессор · фон** (тот же алгоритм в Web Worker, собирается из исходников
  функций), **процессор** (основной поток). Выбор «авто / только GPU /
  процессор» хранится на устройстве (`pf_gpuslice_backend`); отказ GPU
  (нет адаптера, потеря устройства, ошибка шейдера) понижает бэкенд, а не
  роняет вкладку.
- Картинка: заливка тела слоя (even-odd — отверстия видны), бледный предыдущий
  слой, розовые отрезки свесов, сетка стола с масштабом; полоса сечений с
  метками тонких мест (жёлтые) и свесов (розовые); панель слоя: площадь,
  периметр, острова/отверстия, средняя толщина, разрывы контуров.
- Аналитика словами: стол, объём и масса (заполнение/стенки/сплошные из
  настроек профиля + сплошная отливка для сравнения), свесы круче 45° с
  первым слоем-виновником, тонкие места (< 2 периметров) с диапазоном Z,
  нормали наизнанку, рваная сетка (несомкнувшиеся контуры), пятно контакта и
  узкое основание, острова первого слоя.
- Это **не слайсер**: периметры, заполнение и G-code остаются за сервером
  («План»/«Нарезать»). Решение зафиксировано ADR
  `docs/adr/0003-gpu-сечения-в-браузере.md`: полный WebGPU-слайсер признан
  необратимым проектом и отложен; сечения дают 90 % пользы без его рисков.

## Срез 2. Пульт во вкладке «Принтеры» (`site/assets/printer.js`)

- `renderPultWidgets(p, kind)` на каждом тике телеметрии монтирует те же
  модули, что Hero-пульт: регулятор скорости (пересоздаётся при смене
  принтера, отказ команды возвращает стрелку — `knobEl._knob.fail()`), тракт
  AMS над стойкой катушек (скрывается, если станок прислал пустой AMS), шкала
  слоёв под карточкой задания (показывается при печати/паузе, уничтожается
  при простое).
- Старый селектор скорости с кнопкой «Применить» остаётся запасным путём:
  если `knob.js` не загрузился, показывается он, а не дыра.

## Срез 3. Свой G-code говорит на языке слайсеров

- `slicer_engine.py` теперь пишет `;TYPE:` (External perimeter / Perimeter /
  Internal infill / Solid infill / Support material / Skirt/Brim) и `M73
  P<%> R<мин>` в начале каждого слоя плюс финальный `M73 P100 R0` (проценты
  монотонные, ≤ 99 до конца).
- Шкала слоёв (`gcode_layers.bucket_of`) сразу понимает этот G-code: корзины
  «Наружная стенка / Внутренняя стенка / Заполнение / Сплошные слои» вместо
  «Прочее», проценты — из M73 слайсера. Сторонние просмотрщики и прошивка
  Bambu тоже читают оба маркера.
- Совместимость: маркеры дописаны только в вывод движка; тесты Stage 1
  (нумерация `;LAYER:`, температуры, формы) не тронуты — 23/23 зелёные.

## Срез 4. Экскурсия NOZZA печатает настоящий файл

- `tour.py`: при старте тура демо-адресник нарезается своим движком; STL и
  G-code кладутся в библиотеку с пометкой тура, задание виртуального станка
  получает `tour-name-tag.gcode` из загрузок. Смета задания остаётся
  демонстрационной (2 часа), вес — из нарезки.
- Если нарезка не удалась (нет прав, битый диск) — задание получает прежнее
  имя `tour-name-tag.3mf` без локальной копии, тур продолжается, шкала слоёв
  честно объясняет пустоту. Проверено тестом на принудительном отказе движка.
- `virtual.py`: счётчик слоёв виртуального станка берётся из настоящего файла
  (`_layers_in_file` через `gcode_layers.index_for`), а не из формулы
  «минуты × 1,2» — шкала слоёв и телеметрия в туре идут в ногу.

## Отложено (сознательно)

- **Полный WebGPU-слайсер** (периметры/заполнение/поддержки в compute-шейдерах):
  нужен отдельный ADR с бенчмарками против Stage 1 — см. ADR 0003.
- **3MF/STEP в GPU-сечениях**: движок Stage 1 сам принимает только STL; когда
  сервер научится читать 3MF-сетку, тот же разбор добавится в браузер.

## Риски

- WebGPU проверен контрактом шейдера и кода буферов в node: настоящей
  видеокарты в песочнице нет, живой прогон шейдера — за браузером владельца
  (Chrome/Edge 113+). Падение GPU в любом случае понижает бэкенд на CPU.
- Живого браузера в песочнице по-прежнему нет: вёрстка виджетов «Принтеры» и
  карточки сечений проверена контрастами и стендом `panel-check.js`.
