# Касса 17.0.15 — плашки, `hidden` и шапка телефона

Разбор четырёх претензий владельца к мобильной кассе (`site/cashier.html`)
от 12.09.2026. Все четыре — про экран, деньги не затронуты.

| Претензия | Причина | Где исправлено |
| --- | --- | --- |
| «Не работает кнопка „Не показывать“ около кнопки „Скачать“» | `hidden` не прятал элемент | `site/cashier.html:26` |
| «Оранжевые панели сверху убрать целиком» | они рисовались пустыми всегда | `site/cashier.html:26` |
| «„Поток событий молчит“ отображается всегда» | то же: код прятал, CSS не слушал | `site/cashier.html:26` |
| «Верхняя панель на телефоне наплывает друг на друга» | ~500 px содержимого в строке на 336 px + прозрачный фон шапки | `site/cashier.html:39,46,218` |

## 1. `hidden` не работал

Касса не подключает `assets/theme.css` (там `[hidden] { display: none !important; }`
на строке 361), а в своём инлайн-`<style>` задаёт элементам `display` явно:

| Правило | Строка | Что за элемент |
| --- | --- | --- |
| `.linkbar{display:flex…}` | 57 | `#linkBar` — состояние канала, `#priceWarn` — сверка цен |
| `.offbar .prog{display:block…}` | 63 | `#offProgress` — прогресс выгрузки очереди |
| `.install{display:flex…}` | 74 | `#installHint` — баннер «Скачать приложение» |
| `.malert{display:block…}` | 78 | `#moneyAlert` — звонок о платеже |
| `.offbar{display:flex…}` | 116 | `#offBar` — «не проведено: N на сумму» |
| `.btn{…display:inline-flex…}` | 144 | `#bRepeat` — «Повторить» |

Авторское объявление сильнее браузерного `[hidden]{display:none}` независимо от
специфичности (происхождение важнее), поэтому `элемент.hidden = true` менял
свойство, но не экран. Следствия, которые видел владелец:

- баннер загрузки APK не скрывался, хотя обработчик
  (`site/cashier.html:1753`) прятал его и писал `cashier_install_off=1`;
- три цветные полосы под шапкой висели пустыми с первой секунды;
- «Поток событий молчит» оставалась навсегда: `netState()` при живом канале
  ставит `bar.hidden = true`, а текст внутри уже был записан;
- кнопка «Повторить» торчала в корзине без прошлой продажи, а в окне оплаты
  была видна пустая плашка сверки цен с кнопкой «Обновить».

Лечение — одна строка `site/cashier.html:26`:

```css
[hidden]{display:none!important}
```

`!important` обязателен: без него правило той же специфичности, стоящее выше
по файлу, проиграло бы `.linkbar` и остальным.

### Почему прошлая правка (17.0.14) не помогла

В 17.0.14 плашку «поток молчит» лечили по логике: канал стали считать живым и
по страховочному опросу (`netChannelAlive`, `site/cashier.html:405`). Логика
верная и осталась. Но стенд `scripts/kassa-check.js` проверяет свойство
`hidden` на заглушке DOM, у которой нет CSS, — проверки №8 и №9 были зелёными,
пока экран оставался прежним. Вывод для будущих раундов: контракт «плашка
исчезает» надо проверять и в CSS страницы, а не только в JS. Теперь это
`test_site_markup.CashierLayoutTests.test_hidden_attribute_actually_hides_bars`.

### Что осталось на экране после правки

Плашки не удалены — они больше не показываются впустую. У каждой есть денежный
смысл, поэтому «убрать целиком» — отдельное решение владельца:

| Плашка | Когда видна | Что потеряется, если выкинуть |
| --- | --- | --- |
| `#offBar` | в офлайн-очереди есть непроведённые продажи | кассир не видит, что N продаж на сумму ещё не в учёте |
| `#moneyAlert` | 30 с после сигнала о платеже | остаётся звук и счётчик на вкладке «Входящие» |
| `#linkBar` | нет связи с ПК / нет Wi-Fi / поток и опрос молчат | кассир не узнает, что продажи пишутся в очередь |
| `#installHint` | касса открыта в браузере и на сервере есть APK | пропадёт предложение поставить оболочку |

Разметку `#moneyAlert` к тому же пинит тест
`test_cashier_pin_shift.py:493` (точная строка элемента) — удаление молча
сломает контракт.

## 2. Шапка на телефоне

Было: бренд, точка связи, «СБП», имя кассира, счётчик, 🔔 и 🚪 в одну строку.
Считаем для экрана 360 px: доступная ширина 336 px, а сумма содержимого
~500 px (две кнопки по 48 px не сжимаются). Плашки сжимались в огрызки с
многоточиями, а фон шапки был `linear-gradient(to bottom,var(--bg) 78%,transparent)`
— нижние 22 % прозрачные, поэтому при прокрутке товары просвечивали сквозь
шапку. Это и есть «наплывает друг на друга».

Стало:

- `.top` — фон `var(--bg)` без градиента, `flex-wrap:wrap` (`:39`): не влезло —
  перенос на вторую строку, а не нахлёст. Перенос нужен и при крупном
  системном шрифте Android (масштаб 1.3×);
- `.pill{min-width:0}` (`:46`) — плашка сжимается предсказуемо;
- на ≤520 px сняты дубли (`:218`): «СБП» виден в окне оплаты, счётчик — в
  корзине («N поз.»), имя кассира — в смене («Смена открыта · имя»).
  Подпись «в кассе: N ₽ · M в наличии» оставлена (деньги и остаток);
- итог для 360 px: 316 px содержимого в строке из 336 — запас есть;
- от 521 px шапка не изменилась.

Откат одной строкой: убрать `#sbpPill,#countPill,#whoPill{display:none}` из
блока `@media(max-width:520px)` — вернётся прежнее поведение вместе с нахлёстом.

## 3. Как проверить «поток событий молчит» руками

Плашка означает ровно одно: за 45 с не пришло ни одного кадра SSE **и** за 75 с
не было ни одного успешного ответа сервера (`STREAM_QUIET=45000`,
`POLL_QUIET=75000`, `site/cashier.html:388`).

Сервер шлёт именованный кадр раз в 20 с (`SSE_PING_SECONDS`,
`connector/printflow/http_handler.py:51`). Проверка с ПК:

```
curl -N http://127.0.0.1:8766/api/stream
```

Должны идти `event: telemetry`, `event: event` и раз в ~20 с `event: ping`.
Замер на стенде 12.09.2026 (порт 8769, копия базы):

```
event: ping
data: {"at": "2026-09-12T10:07:41.964674+00:00", "idle": 21.3}
```

То есть поток жив, и плашка при живом потоке теперь исчезает. Точка в шапке:
зелёная — канал жив, жёлтая — поток и опрос молчат, красная — связи с ПК нет.
