# Вариации товара и цена из себестоимости (18.0)

Коротко: у товара могут быть сотни сочетаний цвета, размера и пластика — они
собираются перемножением осей, а цена каждой вариации считается из
себестоимости, где грамм берётся по цене **той катушки**, которой вариант
реально печатают.

Дата замера: 15.09.2026, версия 17.0.26.

## Зачем

Адресник «Кость» — это 12 цветов × 5 размеров × 3 пластика = 180 позиций.
Вводить их руками нельзя: владелец не заводит 180 карточек, а значит товар в
учёте живёт «одной строкой» и цена у него одна — хотя PETG за 3600 ₽/кг и PLA
за 1200 ₽/кг не могут стоить одинаково.

## Что такое вариация

Строка `nom_variants`: имя («Чёрный / L»), цвет, размер, пластик, артикул,
свои нормативы (граммы и часы), **привязанная катушка** и цена.

* нормативы вариации пустые — берутся из карточки товара;
* катушка не привязана — система подбирает подходящую по пластику и цвету
  (свежая, с остатком) и честно говорит, что цифра автоматическая
  (`spool_source = auto`);
* своя цена (`price > 0`) — решение владельца: пересчёт её не трогает.

## Оси и генератор

Ось — это название и список значений через запятую. Оси перемножаются:

```
Цвет: Чёрный, Белый, Красный      →  3 × 2 = 6 вариаций
Размер: S, L                          «Чёрный / S», «Чёрный / L», …
```

Распознаются три типа осей — по названию: `цвет`, `размер`, `пластик`
(материал). Значения цвета попадают в `color_name`/`color_hex`, размера — в
`size`, пластика — в `material`. Остальные оси просто участвуют в имени и
артикуле.

Артикул собирается из артикула товара и транслита значений:
`ADR-1` + «Чёрный матовый» → `ADR-1-chernyy-matovyy`.

Повторный запуск не плодит дубли: сочетание, которое уже есть (по имени или
артикулу), пропускается. Перед созданием карточка показывает, сколько вариаций
получится и сколько уже есть.

**Пределы.** До 6 осей и до 2000 вариаций на товар. Это не экономия места, а
защита от опечатки: три оси по сорок значений дают 64 000 строк, которые потом
не удалить из интерфейса. При превышении сервер отказывает словами с числами
(сколько вышло и каков предел).

## Цена из себестоимости

Расчёт идёт существующим `Accounting.cost_breakdown` — тем же, что считает
партию, — но с ценой катушки варианта:

```
себестоимость = пластик (граммы × цена катушки / вес катушки)
              + электричество + амортизация + обслуживание
              + постобработка + упаковка + накладные + резерв на брак
              ÷ сколько штук влезает на стол
```

Пластик считается по цене привязанной катушки, а не «в среднем по
справочнику»: у одного магазина PLA за 1200 и PETG за 3600 за килограмм.

Цена продажи — `Accounting.suggest_price`: наценка из настроек, комиссия
канала, округление, минимальная сумма заказа. Полученную цену можно
перекрыть своей — тогда пересчёт меняет только себестоимость.

## Маршруты

| Метод | Путь | Что делает |
| --- | --- | --- |
| POST | `/api/nomenclature/variants/generate` | собрать вариации по осям; `preview: true` — только посчитать |
| POST | `/api/nomenclature/variants/recalc` | пересчитать себестоимость и цены всех вариаций товара |
| POST | `/api/nomenclature/variant/spool` | привязать катушку к вариации |
| POST | `/api/nomenclature/variant/save` | свои поля вариации, в том числе цена |
| POST | `/api/nomenclature/variant/delete` | удалить вариацию |
| GET | `/api/nomenclature/variant/economics` | себестоимость, цена и раскладка одной вариации |
| GET | `/api/nomenclature/spools` | катушки склада с ценой за грамм |

Вариации на стеллаже идут теми же маршрутами, что и раньше, плюс поле
`variant_id` в теле:

| Метод | Путь | Что делает |
| --- | --- | --- |
| POST | `/api/shelf/transfer` | перенос со склада на полку; `variant_id` — какая вариация едет |
| POST | `/api/shelf/save-from-stock` | завести позицию полки сразу с переносом, тоже с `variant_id` |
| GET | `/api/shelf/stock-available` | что можно перенести: отдельная строка на каждую вариацию со своим штрихкодом и артикулом |

## Чего здесь нет — и пока не обещано

* **Вариаций в приёмке, списании и перемещениях складскими документами.**
  Регистр движения умеет `variant_id`, стеллаж и касса им пользуются, а
  документы склада по-прежнему пишут движение на товар целиком.
* **Своего файла модели на вариацию.** Поле `file` есть, но слайсер его не
  использует: файл один на товар.
* **Подбора катушки по остатку при печати.** Сейчас выбор катушки — решение
  оператора в карточке; авто-подбор под партию не делается.
* **Цвета из палитры.** Цвет вводится названием; `color_hex` подставляется
  генератором, только если значение оси задано с кодом.

## Тесты

`connector/tests/test_shelf_variants.py` — 18 проверок: позиция полки знает свою
вариацию, перенос со склада берёт остаток и себестоимость именно её, чужой товар
дает отказ словами, свободный остаток виден по каждой вариации отдельно,
касса показывает вариации разными плитками и не смешивает их удержания, а
позиция без вариации работает как раньше.

`connector/tests/test_nom_variants.py` — 23 проверки: перемножение осей,
заполнение полей по типу оси, артикул, отказ на превышении предела, повторный
запуск без дублей, предпросмотр без записи, цена катушки в себестоимости,
подбор катушки, приоритет ручного выбора, пересчёт цен и сохранение своей
цены, маршруты и разметка карточки.
