# Отчёт 18.19.0 — надзор за процессами (И263)

Дата: 24.09.2026, версия 18.19.0.

## Что просили

Идея **И263** из списка «надёжность и самовосстановление»: лёгкий второй процесс
следит за агентом и панелью, поднимает упавшее и записывает причину.

## Что сделано

### Надзиратель (`agent/watchdog.py`, новый)

- **Пульс.** Подопечный раз в 30 секунд пишет `~/.printflow/watchdog.json`:
  pid, время, заметка. Запись атомарная (временный файл + `os.replace`) — читатель
  никогда не видит половину пульса.
- **Проверка pid** без psutil: Windows — `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)`,
  остальные — `os.kill(pid, 0)`.
- **`status()`** различает два разных несчастья: «процесс не отвечает» (pid мёртв)
  и «пульс старше порога» (процесс висит). Лечится это по-разному, поэтому и
  причины разные.
- **`pass_once(restart=True)`** — один проход: записать причину, поднять упавших,
  не дёргать роль чаще, чем раз в `cooldown` (120 с), после `max_restarts` (5)
  подряд — **эскалация** вместо бесконечного цикла «упало — поднял».
- **`watch(interval)`** — цикл для автозапуска; **`start_role/stop_role/restart_role`** —
  подъём отдельным процессом (`DETACHED_PROCESS` на Windows, вывод в
  `watchdog-<роль>.out`), мягкая остановка → жёсткая.
- **`log_event` / `tail_log`** — `watchdog.log`, строки «время, роль, событие, подробность».
- **`self_check()`** — восемь вопросов к самому себе: папка, файлы, запись, свой pid
  отвечает, чужой pid отвергается, команды ролей собираются, настройки читаются,
  надзор не следит за собой.
- **CLI:** `--beat ROLE`, `--status`, `--once`, `--dry`, `--watch`, `--log`,
  `--clear-log`, `--self-check`, `--arm`, `--disarm`, `--start/--stop/--restart ROLE`,
  `--roles`, `--interval`, `--stale`, `--max-restarts`.

### Пульс у подопечных

- `agent/server.py`: при старте — `beat("agent", "старт агента")` и поток
  `beat_forever("agent", 30)`. Без этого надзор считал бы агента мёртвым сразу
  после старта и поднимал второй экземпляр на занятый порт.
- `pf.py`: отметка роли `panel` в `cmd_start` и перед нативным окном, плюс команда
  `python pf.py watchdog …` — тонкая обёртка: pf.py не решает ничего сам.

### Навыки (+3, всего 96 записей, 94 с обработчиком)

| Навык | Риск | Что делает | Подтверждение |
| --- | --- | --- | --- |
| `system.watchdog` | read | `mode=status\|log\|self_check`: пульс ролей, журнал, проверка надзирателя | нет |
| `system.watchdog_arm` | write | `enabled=on\|off` + `interval`, `stale_sec`, `max_restarts` | `confirm_text` = «вооружить» / «снять» |
| `system.watchdog_once` | write | один проход с подъёмом упавших, `dry=on` — только посмотреть | `confirm_text` = «поднять» |

Исполнитель: `_system_watchdog`, `_system_watchdog_arm`, `_system_watchdog_once`.
Каждый подъём и каждая причина ложатся в новую таблицу **`watchdog_events`**
(миграция `_migrate_1819`, индексы по роли и виду события) — «что падало на этой
неделе» ассистент отвечает из памяти, а не чтением текстового лога. `stats_18()`
добавляет цифру событий к прежним.

### Панель и границы

- `connector/printflow/assistant.py` — три обёртки через `_call_agent_skill`.
- `routes_assistant.py` — 89 маршрутов (было 86): `GET /api/assistant/system/watchdog`,
  `POST /api/assistant/system/watchdog/arm`, `POST /api/assistant/system/watchdog/once`
  (audit + подтверждение; без `confirmed` маршрут отвечает `needs_confirmation`).
- `assistant.html` — карточка **«Надзор за процессами (И263)»**: «Кто жив», «Журнал
  надзора», «Проверка надзирателя», поля ролей/интервала/порога, «Вооружить»,
  «Снять надзор», «Поднять упавших (с подтверждением)».
- Границы не нарушены: надзор не исполняет навыки, не двигает деньги и печать, не
  удаляет файлы. Он умеет ровно две вещи — видеть пульс и поднимать процесс.

### Починен встроенный JS панели помощника (найдено при работе)

`site/assistant.html` в 18.15–18.18 накапливал правки, и встроенный скрипт
перестал парситься:

- висячий `function` без имени (строка-обрывок) — весь блок был `SyntaxError`;
- дубль функций автоустановки после `})();`;
- карточки 18.15–18.18 дописывались в конец файла **за** закрывающим тегом
  скрипта: к моменту выполнения скрипта этих кнопок не существовало, слушатели не
  ставились — «кнопка есть, а нажатие молчит»;
- `esc()` собирался из `\"` вместо `"`.

Исправлено: карточки перенесены выше скрипта, функции надзора и автоустановки
определены внутри одного блока, `esc()` исправлен, для всех десяти карточек
слушатели ставятся таблицей `wiring` с проверкой существования элемента.

Чтобы это не повторилось, `scripts/check.py` получил проверку **«Встроенный JS в
HTML»**: баланс `<script>`/`</script>` и `node --check` для каждого встроенного
блока (без Node проверяется только баланс). Проверок стало 37 вместо 36 — именно
этот пропуск и позволил поломке дожить до релиза.

### Починено по дороге (не входило в задачу, но ломало работу)

- **`system.check` / `system.install` в 18.18 не существовали.** В исполнителе
  были ссылки на `self._system_check` и `self._system_install`, а самих методов
  не было: навыки автоустановки отзывались «Навык упал: AttributeError». Методы
  написаны заново, тесты навыков это больше не пропустят.
- **Справка маршрутов считала пары, а не пути.** Группа `/api/assistant` была
  записана как 86/89 маршрутов, тогда как в справке группы считаются уникальными
  путями (шесть путей помощника объявлены и на чтение, и на запись). Теперь
  записано честно: 83 пути, 89 маршрутов, плюс измеренные числа **652**
  уникальных пути и **138**, которые не зовёт фронт.
- **Правило «необратимо».** Тест 18.14 запрещал любой навык с риском
  `irreversible`, а с 18.17 такой навык есть — `screen.archive_erase` (стирает
  метаданные архива экрана, то есть свою базу агента). Тест приведён к правилу:
  необратимость допустима только для собственной памяти агента, только с
  подтверждением и только когда навык вообще не работает с файлами.
- **Каталог идей не догонял репозиторий.** Идеи 18.17–18.18 (И206–И222) не были
  записаны, из-за чего тест «у навыка есть идея в каталоге» падал. Дописаны
  части 3 (И206–И277) и 4 (И278–И300: сайты и чужой экран) — всего в каталогах
  300 идей.
- **Список имён живых навыков.** Справка описывала навыки 18.17-18.19 группами
  (`assistant.macro/macros/macro_run`), а тест ищет каждое имя отдельно. В
  `docs/НАВЫКИ.md` добавлен полный алфавитный перечень 96 имён.

## Как проверить

```bash
python -m agent.watchdog --self-check                       # может ли надзиратель вообще работать
python -m agent.watchdog --status                           # пульс ролей
python -m agent.watchdog --beat agent                       # отметиться вручную
python -m agent.watchdog --once                             # поднять упавших
python -m agent.watchdog --arm --roles agent,panel --interval 30
python -m agent.watchdog --watch                            # цикл (можно ставить в автозапуск)
python pf.py watchdog --status                              # то же одной командой pf.py
python pf.py watchdog --dry                                 # посмотреть правду, ничего не поднимая
```

В панели помощника: карточка «Надзор за процессами» → «Кто жив» → «Поднять
упавших» (слово «поднять» в поле подтверждения) → «Вооружить» (слово «вооружить»).

## Что осталось за границей захода

- Уведомление человека при эскалации пока только в журнале и в ответе навыка: звук,
  тост Windows и сообщение в ТГ — следующий заход (там уже есть `voice.say` и ТГ-идеи).
- Надзор не следит за внешними рантаймами (Ollama, tesseract): их падение видно
  через `system.check` из 18.18, но поднимать их — отдельное решение владельца.
