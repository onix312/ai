# Маршруты API PrintFlow — реестр и правило

Дата замера: 13.09.2026, версия 17.0.17.

Маршрутов в сервере **513**: 435 объявлены `if path == "/api/…"` внутри
`Api.get()`/`Api.post()` (и частично в `http_handler.py`), 78 — декоратором
`@router.get`/`@router.post` из `connector/printflow/router.py`.

Порядок разбора запроса: `Api.get()` и `Api.post()` **сначала** спрашивают
реестр декораторов (`api.py:988`, `api.py:2018`) и только если маршрута там
нет — идут по if-цепочке. Поэтому путь, объявленный и декоратором, и
if-цепочкой, во втором месте **мёртв**: до него никогда не доходит очередь.
Таким был `/api/search` (ветка в `api.py` против живого
`routes_system.search`) — снято в 17.0.16.

## Правило для нового маршрута

1. Новый маршрут объявляется **декоратором** в `routes_*.py`: у него есть
   `public`, `roles`, `audit`, `idempotent` и `doc`, и он сам попадает в
   `/api/openapi.json`. If-цепочка в `api.py` ничего из этого не даёт.
2. Путь не должен совпадать с уже объявленным для того же метода: реестр
   бросает `ValueError("Маршрут уже объявлен")` при загрузке, а контракт
   `connector/tests/test_routes_registry.py` ловит пару «декоратор +
   if-цепочка», которая не падает, а молча делает ветку мёртвой.
3. Каждый путь, который набирает фронт (`site/**/*.html`,
   `site/assets/*.js`), обязан существовать в сервере — это проверяет тот же
   тест. Так в 17.0.16 нашлась палитра команд, читавшая старый плоский ответ
   `/api/search`.
4. Перенос существующего маршрута из if-цепочки в декоратор — отдельный
   коммит: меняется способ разбора, а не поведение.

## Приложение: непрошеные маршруты (замер 13.09.2026)

Из **503** уникальных путей **115** не вызываются ни одной страницей или
скриптом в `site/`; из них **99** не упоминаются вообще нигде — ни в `site/`,
ни в `connector/tests/`, ни в `scripts/`, ни в `android/`.

Число «нигде» не равно числу «не зовёт `site/`», и это не ошибка: путь может
жить в тесте или в скрипте приёмки. Так в 17.0.17 случилось с
`/api/openapi.json` — `scripts/acceptance.py` сверяет по нему живую
спецификацию, и путь ушёл из «нигде» (100 → 99), оставшись непрошеным для
панели. Удалять маршрут по этому списку нельзя: сначала решение владельца.

Как посчитать самому:

```bash
python3 - <<'PYEOF'
import re, pathlib, sys
sys.path.insert(0, '.')
from connector.printflow.api import router
known = {r["path"] for r in router.reference()}
for f in ("api.py", "http_handler.py"):
    for line in pathlib.Path("connector/printflow", f).read_text(encoding="utf-8").splitlines():
        if re.search(r"if path (==|in )", line):
            known |= set(re.findall(r'"(/api/[^"]+)"', line))
def callers(*dirs):
    hits = set()
    for d in dirs:
        for f in pathlib.Path(d).rglob("*"):
            if f.suffix in {".js", ".html", ".py", ".kt"} and f.is_file():
                hits |= set(re.findall(r"/api/[A-Za-z0-9_\-/.]+",
                                       f.read_text(encoding="utf-8", errors="ignore")))
    return {h.rstrip(".") for h in hits}
front = callers("site")
everywhere = front | callers("connector/tests", "scripts", "android")
print("всего путей:", len(known))
print("не зовёт site/:", len([p for p in known if p not in front]))
print("не упоминаются нигде:", len([p for p in known if p not in everywhere]))
PYEOF
```

Что с этим делать — **решение владельца, а не правка**. Список не означает
«мертво»: маршрут может звать Telegram-бот, внешняя интеграция, QR-ссылка или
будущий экран. Категории, с которых разумно начать разбор:

| Категория | Примеры | Что проверять |
| --- | --- | --- |
| Аналитика, до которой не дошли руки | `/api/analytics/oee`, `/api/analytics/investment`, `/api/payback`, `/api/break-even` | нужен ли раздел в панели или снять |
| CRUD без экрана | `/api/model/save`, `/api/jobs/save`, `/api/defect/save`, `/api/nomenclature/variant/save` | есть ли другой путь к тем же данным |
| Сеть и диагностика | `/api/network/scan`, `/api/network/mdns`, `/api/network/ips` | дублируют ли «Найти сервер» в оболочке |
| Дубли с другим именем | `/api/client-bot/chat/read` рядом с `/api/client-bot/read` | объединить в кортеж или снять один |
| Служебные | `/api/openapi.json`, `/api/openapi.json/stats`, `/api/audit` | оставить: их зовут не из `site/` |

Контракт `connector/tests/test_routes_registry.py` держит эти три числа
в справке равными коду: появился или исчез маршрут — справка устарела,
и тест об этом скажет.

## Что этот реестр не делает

Справка не подменяет живой реестр и не претендует на полноту описаний:
единственный источник правды о маршруте — его объявление в коде. Числа здесь
нужны, чтобы рост API был виден, а `test_routes_registry` не даёт им
разойтись с кодом молча.
