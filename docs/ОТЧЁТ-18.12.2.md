# Отчёт 18.12.2 — Mini App цеха: адрес вместо «Example Domain»

**Статус:** готово. Базис — 18.12.1. Релиз точечный: одна живая жалоба
владельца («MINIAPP не работает, при открытии пишет example domain»), разбор
причины и починка. Новых возможностей нет, кроме поля адреса, без которого
Mini App было не настроить.

## Что видел владелец

В боте сотрудников кнопка **«🏭 Открыть цех»** открывала страницу
**«Example Domain»** вместо цеха. Telegram тут ни при чём: приложение
открывалось по адресу, который дала панель.

## Причина: адрес было нечем задать

`staffbot/core/config.py:get_miniapp_url` искал адрес по пяти ключам
(`miniapp_url`, `staff_miniapp_url`, `public_url`, `base_url`, `app_url`) — но
в `DEFAULT_SETTINGS` (`connector/printflow/config.py`) был только `public_url`.
`Database.set_settings` пишет исключительно известные ключи:

```python
for key, value in patch.items():
    if key not in DEFAULT_SETTINGS:
        continue           # ← остальные молча выбрасываются
```

Значит, отдельного адреса Mini App в системе не существовало: оставался
`public_url` («Публичный адрес панели»), о котором в контексте Mini App никто
не знал, — а при пустом `public_url` функция отдавала
`https://example.com/staff`. Отсюда «Example Domain».

Вторая мина рядом: Telegram принимает **web_app-кнопку только по HTTPS**
(`WebAppInfo.url`), и если отдать `http://192.168.1.50:8765/staff`, Bot API
отвечает `400 BUTTON_URL_INVALID` **на всё сообщение**. То есть у владельца с
LAN-адресом в `public_url` пропадали не кнопка, а все уведомления: `manager._notify`
собирал ряд кнопок безусловно.

## Что сделано

### 1. Адрес стал настройкой

- `connector/printflow/config.py`: `staff_miniapp_url: ""` в `DEFAULT_SETTINGS`
  с комментарием, почему нужен именно HTTPS.
- `connector/printflow/settings_schema.py`: группа `telegram`, подпись
  «Адрес Mini App цеха», лимит 300 символов, подсказка с примером и ссылкой на
  `docs/MINIAPP-ЦЕХА.md` — поле видно и в карточке «Telegram-уведомления», и во
  вкладке «Все настройки».
- `site/assets/app.js`: строка поля в карточке Telegram-уведомлений + вердикт
  под ней (`miniappTarget`/`miniappStatusRow` считают адрес так же, как сервер):
  «Кнопка ведёт на …» либо «Mini App цеха выключен: адрес не задан / нужен https».

### 2. Кнопка web_app отдаётся только за готовый адрес

- `staffbot/core/config.py`: `normalize_miniapp_url` (схема по умолчанию
  `https://`, хвостовой слэш убирается), `get_miniapp_url` без example.com,
  `miniapp_reason`, `miniapp_state`, `miniapp_hint`, константа `MINIAPP_HINT`.
  Приоритет: `staff_miniapp_url`/`miniapp_url` → `public_url`/`base_url`/`app_url`
  + `/staff` (без удвоения, если `/staff` уже есть).
- `staffbot/ui.py`: `miniapp_button` возвращает `None` для пустого и не-HTTPS
  адреса, `web_app_keyboard` просто не добавляет ряд — «Открыть цех» остаётся в
  меню (Помощь/Мой код), а не превращается в ошибку доставки.
- `manager._notify`: ряд с web_app-кнопкой собирается только при
  `miniapp_state(...)["ready"]`; action-кнопки (Кадр/Продолжить/Снял) не
  зависят от Mini App.
- `staffbot/handlers/notify.py`: `_notify_with_button` шлёт callback-кнопку
  «🏭 Открыть цех» → `cmd:menu` (web_app живёт в самом меню), а прямой fallback
  в чат владельца добавляет `reply_markup` только для готового адреса. Убрана
  ветка с `example.com` и запутанный комментарий с обходом `notify_async`.

### 3. Бот объясняет, а не притворяется

`staffbot/handlers/menu.py`: если адрес не готов, «меню» и «помощь» отвечают
инструкцией `MINIAPP_HINT` (три шага: адрес → поле в панели → «Меню» ещё раз) с
первой строкой-причиной из `miniapp_state` — «Адрес Mini App не задан…» или
«Адрес Mini App — http://192.168.1.50:8765/staff, а Telegram открывает Mini App
только по https». Если клавиатура вышла пустой (не готова ни одна кнопка),
`reply_markup` в `sendMessage` не отправляется вовсе: Telegram отклоняет пустой
`inline_keyboard`. Плюс `staffbot/ui.py:markup_or_none` и `bot.py:_miniapp_note` —
тексты «откройте цех кнопкой ниже» в приветствии по коду, незнакомой команде и
ответе на недоступную роль больше не обещают кнопку, которой нет. Перезапуск не
нужен: настройки читаются на каждое сообщение.

### 4. Документация

- `docs/MINIAPP-ЦЕХА.md` — настройка по шагам: три способа дать HTTPS
  (Tailscale `tailscale serve --bg 8765`; Cloudflare Tunnel с фильтром путей в
  `ingress` и Zero Trust Access; свой домен + прокси), куда вписать адрес, как
  проверить с телефона, доступ сотрудникам, таблица частых ошибок, предупреждение
  о том, что пароля в панели нет и открывать её целиком в интернет нельзя.
- `docs/TELEGRAM.md`, README — ссылки и раздел про адрес Mini App.

## Проверка

- `python3 -m unittest discover -s connector/tests` — новый файл зелёный,
  набор без новых падений (4 известных падения из 18.12.1/18.12.0 не связаны с
  Mini App: конструктор FarmLoop, вкладка конвейера, SQL в `routes_farmloop`,
  сторож Watch Folder).
- Живая проверка владельцем: заполнить «Адрес Mini App цеха», нажать «Меню» —
  кнопка должна открыть цех, а не Example Domain.

## Что осталось за рамками

- Автопроверка доступности адреса из панели (пинг туннеля) не делалась: у панели
  может не быть выхода в интернет, и «адрес недоступен» — не всегда ошибка
  настройки (Tailscale-адрес виден только своим устройствам).
- Обходной путь для тех, кто физически в цехе без HTTPS, не добавлен: Telegram
  не открывает Mini App по http, и это ограничение платформы, а не системы.
  LAN-пользователям остаются пульт `/pult` и APK — см. `docs/ПУЛЬТ-НА-ТЕЛЕФОНЕ.md`.
