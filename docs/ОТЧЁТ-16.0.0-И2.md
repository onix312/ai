# Отчёт · Касса 16.0 · Итерация 2 — мобильная касса в LAN

Дата: 2026-09-06. Ветка: `arena/01a07625-ai`. Версия: `16.0.0`.

## Что сделано

Мобильная касса кассира: телефон/планшет в локальной сети магазина продаёт
с полки за наличные и по СБП, видит остатки и подтверждает СБП-поступления.
Использует то же ядро СБП из Итерации 1 и тот же учёт полки (`shelf.py`).

### Новые файлы
- `connector/printflow/cashier.py` — сервис кассы: сессии по коду, каталог,
  продажа (наличные/СБП), подтверждение/отклонение СБП, аудит.
- `connector/printflow/routes_cashier.py` — HTTP-маршруты кассы.
- `connector/tests/test_cashier.py` — 12 тестов.
- `site/cashier.html` — интерфейс кассира (вход по коду → полка → оплата →
  входящие), большие кнопки, работает в LAN без интернета.

### Изменённые файлы
- `db.py` — таблица `cashier_sales` (корзина продажи: метод, сумма, кассир,
  отметка подтверждения) + 2 индекса.
- `config.py` — настройка `cashier_code` (общий код магазина).
- `settings_schema.py` — группа «Касса и СБП» + подписи всех новых настроек.
- `router.py`, `api.py`, `openapi.py` — регистрация и тег `routes_cashier`.
- `sw.js` — pre-кэш v25 (+`cashier.html`, `sbp.html`), `manifest.webmanifest` —
  ярлык «Касса».
- `CHANGELOG.md`, `docs/КАССА-16.0.md` — записи.

## Сценарии кассира (3–4 касания)

1. Открыть `/cashier.html` на телефоне → ввести код магазина.
2. Товар (тап по плитке — в корзину, повторный тап — +1).
3. «Оплатить» → способ: наличные / СБП.
4. Подтвердить → продажа проведена (наличные) или СБП-платёж создан → «Входящие» → подтвердить поступление.

## Гарантии (покрыты тестами)

| Требование | Как обеспечено |
|---|---|
| Один учёт полки | наличные и СБП списывают через `shelf.sale` — тот же метод, что панель и бот |
| СБП не трогает склад до подтверждения | создание платёжа не списывает и не пишет выручку |
| Подтверждение = выдача | одна транзакция: проверка остатков → списание → деньги на счёт СБП |
| Нет дублей | `request_id` на продаже + идемпотентный HTTP-слой + статус в `cashier_sales` |
| Нет перепродажи | остатки перепроверяются при подтверждении; нехватка — ошибка, ничего не меняется |
| Роли | кассир (код магазина) = продажи + подтверждение СБП; возвраты — только панель (руководитель/владелец) |
| LAN без интернета | страница и API локальные; СБП отключается `sbp_enabled` |

## API

- `POST /api/cashier/login` (`code`) / `POST /api/cashier/logout` (`token`)
- `GET /api/cashier/catalog?token=` — полка, цены, остатки, касса магазина
- `GET /api/cashier/incoming?token=` — СБП-продажи на сверке
- `POST /api/cashier/sell` (`token`, `method`, `items`, `request_id`) — идемпотентна
- `POST /api/cashier/confirm-sbp` / `POST /api/cashier/reject-sbp`
