# 0001. Конвейер: единый мастер «Подготовка серии», конструктор финала G-code и тестовая очистка стола

- **Статус:** принято
- **Дата:** 2026-09-20
- **Версия:** 18.9.0

## Контекст

Исторически инструменты нарезки Stage 1, экспорт из внешних слайсеров (Watch Folder) и ссылка на FarmLoop находились в разделе «Печать» (`#view-print`), который предназначен для бумажных бланков, наклеек и этикеток. Вкладка «Конвейер» содержала лишь плоский список настроек и статус. При этом отсутствовала возможность протестировать физическую механику сброса детали толкателем без долгой реальной печати, а G-code сброса задавался только фиксированным внешним файлом шаблона.

## Решение

1. Собрать единый сквозной 3D-процесс во вкладке «Конвейер» (`#view-conveyor`):
   - Мастер «Подготовка серии» (ступенчатый сценарий: загрузка файла → параметры и смета с авто-подбором катушки склада → запуск серии в Конвейер).
   - Watch Folder закреплён за внешними слайсерами (`.3mf`, `.gcode`), а загрузка `.stl` идёт через браузерный виджет.
2. Реализовать визуальный «Конструктор финала (FarmLoop)»: блочный параметрический редактор шагов завершения печати (охлаждение стола, обдув, отвод сопла, проход толкателя, свободные дополнения), генерирующий проверенный шаблон с маркерами `; PRINTFLOW FARMLOOP BEGIN/END`.
3. Добавить безопасный эндпоинт `POST /api/farmloop/test-clean` для тестового прогона толкателя по шаблону, заблокированный при любых статусах принтера, кроме `IDLE`.
4. Раздел «Печать» оставить строго за бумагой и наклейками, сохранив обратную совместимость старых элементов разметки.

## Последствия

- Оператор получает понятный и безопасный 2-шаговый цикл подготовки деталей на P1S без переключения между несвязанными вкладками.
- Механика сброса проверяется до запуска многочасовых серий на свободном принтере.
- Внешние слайсеры и встроенный движок Stage 1 гармонично сведены к единому результату — серии FarmLoop с катушкой склада.
