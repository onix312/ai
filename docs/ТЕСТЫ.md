# Тесты PrintFlow: поведение и строки

Дата замера: 24.09.2026, версия 18.19.0. Файлов в `connector/tests/` — **168**.
Последний прогон на ПК: `python scripts/check.py --quick` — **38/38**;
`python scripts/check.py` — **39/39**, **3033 теста**, 8 пропусков.
Ollama, Windows, MQTT, принтер и Telegram проверялись имитациями, не на устройстве.

Тесты здесь двух разных видов, и путать их нельзя: один проверяет, что код
работает, второй — что файл выглядит так, как договорились.

| Вид | Файлов | Что проверяет |
| --- | --- | --- |
| Поведение | **107** | Запускает настоящий код: база, репозиторий, маршруты, сервисы. Падает, когда сломалась логика. |
| Поведение + строки | **38** | Запускает код и сверяет текст файлов: вёрстка, ресурсы, документы. |
| Только строки | **23** | Читает файлы как текст: вёрстка, оболочка, метаданные Android, версии. Код не запускается. |
| **Всего** | **168** | |

## Правило

1. Если поведение можно запустить — тест обязан его запускать. Строковый
   контракт вместо прогона кода считается временным и пишется с пометкой,
   почему прогон невозможен: нет браузера, нет устройства, нет Gradle.
2. Строковый контракт годится там, где проверяется сам текст: разметка страницы,
   `sw.js`, `strings.xml`, заголовки документов, числа в справке.
3. Строковый контракт не заменяет поведенческий. Оба вида могут жить в одном
   файле, но в разных классах — как `SiteMarkupTests` и `OrderArchivePanelTests`
   в `test_site_markup.py`.
4. `scripts/panel-check.js` для DOM-логики не годится: его заглушка отвечает
   цепочкой на любой `querySelector`. Нужна проверка клика — это строковый
   контракт или прогон в node по исходному тексту функции. Так проверены
   `ordersSource()`/`filtered()`, чипы каналов принтера и модули пульта 18.11
   (`test_hero_controls`: регулятор, тракт AMS, инциденты, звуки — чистые
   функции модулей прогоняются в node с заглушкой DOM) и конвейер GPU-сечений
   18.12 (`test_gpuslice`: STL, плоскости, сечения, контуры, аналитика —
   CPU-часть `gpuslice.js` в node; WGSL и точки монтирования — строками).
5. Если у модуля есть свой стенд — проверять его стендом, а не строками:
   `scripts/kassa-check.js` (касса), `scripts/pult-check.js` (пульт: команды,
   preflight, идемпотентный запуск, обрыв связи), `scripts/print-check.js`
   (раздел «Печать»: каталог форм по настоящему реестру, сборка параметров,
   лист в окне печати).
