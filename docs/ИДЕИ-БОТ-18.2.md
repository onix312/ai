# Идеи 18.2 — сотрудники в один тап, владелец — картинкой

> Продолжение после переписывания бота в пакет `staffbot` (18.1.0): каркас
> готов — сцены, маршрутизатор, права, exactly-once кнопки. Ниже — что класть
> сверху. К каждой идее — макет экрана (SVG, стиль Telegram): постер всех
> шести — `img/bot-ideas-182.svg`. Оценка: 🟢 дёшево (часы), 🟡 средне
> (день–два), 🔴 дорого/рискованно. Всё — stdlib, SQLite, без облака.

## Б1. Меню-дашборд при старте смены 🟢

**Суть.** Любое сообщение боту вне команды → живая панель: выручка смены,
сколько в кассе, что печатается, что ждёт на полке. Снизу — reply-клавиатура
главных действий. Новый сотрудник работает без единой команды.

**Макет:** `img/bot-idea-menu.svg` (панель + reply-клавиатура).

**Как в новой архитектуре.** В `router.py` текст без маршрута сейчас уходит в
подсказку — заменяем её на панель из `views.py` (`text_panel` уже собирает
сводку). Reply-клавиатура — один `reply_markup` в `ui.py`. Точка входа уже
есть: `BotCore.dispatch` → `ROUTER.match_text` → default-обработчик.

---

## Б2. Повтор продажи одним тапом 🟢

**Суть.** После чека продажи — кнопка «↻ Ещё раз»: та же позиция, тот же
прайс, минус один шаг. Под кнопкой — «🧾 Последние продажи», повтор любой из
пяти последних.

**Макет:** `img/bot-idea-repeat.svg` (кнопки после чека + список повторов).

**Как в новой архитектуре.** В `sales.py` после `sell_complete` уже уходят
кнопки «Продать ещё» (продолжение сцены) — «↻ Ещё раз» добавляется как
callback `sell:again:<id>`: берёт `sale` из SQLite и повторяет INSERT +
`register_move`. Список последних — `SELECT ... ORDER BY id DESC LIMIT 5` из
`sales.py`.

---

## Б3. Кнопки во всех уведомлениях 🟢

**Суть.** Каждое уведомление бота — с действиями: СБП-заявка → «✅ Подтвердить /
✖ Отклонить»; очередь печати → «▶ Следующее» уже есть, добавить в
«ошибка принтера» и «заказ готов». Сотрудник отвечает тапом, не набирая текст.

**Макет:** `img/bot-idea-sbp.svg` (заявка на оплату с кнопками решения).

**Как в новой архитектуре.** В `manager.py` у `notify(..., buttons=...)` кнопки
уже передаются для событий complete/error — расширяем на СБП-заявки
(`_client_payment_action` — сейчас текстовая команда в `client_bot.py`),
отправляем через `notify_async`. Приём и защита от дублей — готовый
`answerCallbackQuery`-контур `core.py`.

## Б4. Отчёт-картинка за неделю 🟡

**Суть.** «Отчёт неделя» → в чат летит PNG-график: столбики выручки по дням,
строка прибыли и брака. Текст владелец не читает — картинку смотрит всегда.

**Макет:** `img/bot-idea-chart.svg` (фото-сообщение с графиком 7 дней).

**Как в новой архитектуре.** Техника уже обкатана в `qrgen.png_bytes` —
чистый zlib+PNG без Pillow: столбики — прямоугольники, подписи — готовый
текстовый растеризатор из QR-генератора. Данные — SQL-агрегат по
`sales.ts`. Отправка — `sendPhoto` (метод уже используется для кадров).

## Б5. Карточка полки с фото 🟢

**Суть.** «Полка» показывает не только текст: карточка товара — фото с полки,
цена, остаток, кнопки «Продать 1», «Пополнить». Вопрос «что за „Костица"?»
решается взглядом.

**Макет:** `img/bot-idea-photo.svg` (фото-бирка «КОСТИЦА» + кнопки действий).

**Как в новой архитектуре.** В `db.py` у `shelf_items` поле `photo` уже есть
(файлы в `DATA_DIR/photos/`, витрина `shelf.html` их показывает) — боту не
хватает только `sendPhoto`. Кнопки продают через ту же сцену SELL из `scenes.py`
(прайс подтягивается из позиции).

---

## Б6. Кнопка «Открыть пульт цеха» 🟢

**Суть.** Кнопка-ссылка прямо в чате: «Открыть пульт цеха» → браузер на панель
управления печатью. Не искать адрес, не сохранять закладку.

**Макет:** `img/bot-idea-pult.svg` (URL-кнопка в панели).

**Как в новой архитектуре.** Telegram `InlineKeyboardButton(url=...)` —
разрешённый «согласованный выход в интернет». Адрес берём из UDP-маяка
`discovery.py` (панель уже объявляет себя в LAN). Кнопку добавляем в панель Б1
и в уведомление о старте печати.

---

## Б7. Выемка кассы с фото чека 🟡

**Суть.** Сцена выемки просит сумму, фото чека и сразу прикладывает оба к
записи смены. Обещано ТЗ-15.4, после сцен из 18.1 — осталось только собрать.

**Макет:** сцена-диалог в стиле `img/bot-idea-sbp.svg` (шаги «сумма → фото →
итог»).

**Как в новой архитектуре.** Копия сцены CASH_RECONCILE из `scenes.py`
(TTL-хранилище то же): шаг 2 принимает `photo` из апдейта — приём файлов в
боте уже есть (`document`/`photo` обрабатываются для чеков заказов). Итог —
`cash_moves` + фото в `DATA_DIR/photos/`.

---

## Б8. Мастер заказа кнопками 🟡

**Суть.** Приём заказа по шагам: клиент → товар → тираж → срок → предоплата.
Без «шпаргалки команд», без ошибок в свободной форме.

**Макет:** последовательность кнопок-вопросов (стиль `img/bot-idea-menu.svg`).

**Как в новой архитектуре.** Третья родственница сцен SELL/CLIENT_REPLY:
`scenes.py` хранит состояние в SQLite (переживает рестарт), каждый шаг —
inline-клавиатура из справочников (`catalog.py`: номенклатура, цены). Финал —
та же запись заказа, что и текстом.

---

## Б9. Вечерний итог смены 20:00 🟢

**Суть.** Каждый день в 20:00 — сообщение-итог: выручка, наличные по кассе,
что не продано, что печатается ночью не будет (смена кончается). Дисциплина
сверки без напоминаний владельца.

**Макет:** панель в стиле `img/bot-idea-menu.svg` с заголовком «Итог смены».

**Как в новой архитектуре.** В `schedules.py` планировщик уже живёт (там
сидят напоминания) — добавляем задачу с фиксированным временем и
`views.text_panel` как тело. Доставка — существующий `notify_async`.

---

## Б10. «Попросить владельца» при отказе прав 🟢

**Суть.** Вместо сухого «нет прав» — кнопка «📩 Попросить доступ»: владельцу
уходит заявка с именем сотрудника и командой, которую он хотел выполнить.
Одним тапом владелец открывает доступ (или молчит).

**Макет:** кнопка под сообщением об отказе (стиль `img/bot-idea-sbp.svg`).

**Как в новой архитектуре.** Точку отказа прав видно в `router.py`
(`rights` → «статус N»); заявка — `notify_async` владельцу + callback
`team:grant:<id>`, обработчик — в `team.py` рядом с существующим управлением
ролями.

## Клиентский бот (коротким блоком, отдельно от 18.2)

- **Повтор заказа одним тапом** 🟢 — «↻ Повторить заказ №N» в истории клиента;
  черновик собирается из SQLite (`orders`), подтверждение — кнопкой. Макет —
  тот же приём, что Б2.
- **Трекер заказа с фото прогресса** 🟡 — клиенту раз в смену фото с полки
  принтера и статус; фото уже приходят боту цеха (Б4), переотправка —
  `copyMessage`. Шаблоны ответов для статусов уже есть
  (`client_bot_templates`).

## Чего сознательно НЕ предлагаем

Запреты проекта остаются в силе: голосовой ввод, ночная смена,
авто-перепечатка без подтверждения человеком, облачный CRM/автопостинг,
новые генераторы ценников. Всё вышеперечисленное — локальный компьютер,
SQLite как источник правды, Python stdlib.
