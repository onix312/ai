# Отчёт — «Склад 15.5.0», итерация 1: кнопки «−1» / «+1» и «Вернуть»

Дата: 2026-09-04. ТЗ: `docs/ТЗ-СКЛАД-15.5.md`. Версия: **15.4.0 → 15.5.0**.

## Что сделано

Ручная корректировка остатка одной кнопкой — **без последствий для денег**:

- **«−1»** — списание 1 шт со склада; **«+1»** — оприходование найденной
  штуки. Оба действия пишут в регистр `stock_moves` движение с
  `doc_kind="manual"`. Это не продажа: не создаются чек, заказ, выручка,
  маржа и доход; не меняются касса магазина, онлайн-деньги (Авито/ТГ),
  долги клиентов и статистика продаж (она считает только `doc_kind='sale'`);
  в финансовых отчётах мусорных документов не появляется.
- Остаток и средняя себестоимость пересчитываются штатной логикой
  регистра — никаких прямых правок `qty`.
- **Где кнопки**:
  - вкладка «Продукты → Склады»: на каждой карточке склада — кнопка
    **«Позиции»**, открывает список позиций (название, остаток, резерв,
    свободно, себестоимость) с кнопками «−1»/«+1» в каждой строке;
  - карточка товара, разрез остатков по складам: у каждого склада —
    «−1»/«+1» и подпись «резерв N · свободно M · сумма».
- **Подтверждение**: один клик по кнопке → короткий диалог
  «Убрать 1 шт „Адресник“ со склада „Магазин“? … действие можно вернуть»
  → подтверждение или «Отмена». Полей и форм нет.
- **Защита**:
  - остаток не уходит в минус: при нуле свободного остатка кнопка
    неактивна (подсказка в title), сервер отклоняет с понятной ошибкой;
  - списывать можно только **свободное** (остаток − активные резервы):
    зарезервированное под заказы неприкосновенно;
  - «+1» ограничений по резерву не имеет;
  - неизвестная позиция/склад, `delta` ≠ ±1 — отклоняются (400).
- **Обратимость**:
  - сразу после действия — тост с кнопкой **«Вернуть»** (один клик,
    без второго вопроса — это и есть подтверждение намерения);
  - в истории движений товара у каждой корректировки — кнопка
    **«↩️ Вернуть»** (с подтверждением);
  - откат = удаление движения (как распроведение документа): остаток и
    средняя восстанавливаются пересчётом, в оборотке пара «−1/+1» не
    висит; повторный откат невозможен (движения уже нет);
  - откат оприходования («+1») запрещён, если найденной штуки уже нет
    в свободном остатке (ушла продажей/в резерв) — иначе возникли бы
    минус или недобор по резерву. Откат списания («−1») только добавляет
    штуку обратно и разрешён всегда, пока движение существует.
- **Аудит**: каждое списание/оприходование/возврат — событие в журнале
  («Склад: списание 1 шт — … · движение mv_… · ручное списание»,
  «Склад: корректировка возвращена — … откат движения mv_…»).
- Метка типа движения: «Корректировка» в движениях и в мастере документов.

Попутно исправлен латентный баг в `api.post`: два локальных
`from .accounting import uid` внутри метода делали `uid` локальной
переменной всей функции, из-за чего ветки выше по тексту (в т.ч.
`/api/warehouse/save`) могли падать `UnboundLocalError` до выполнения
импорта. Лишние локальные импорты убраны — `uid` уже импортирован
на уровне модуля.

## Сценарий приёмки в панели

1. Продукты → Склады → кнопка **«Позиции»** на карточке склада.
2. У строки с остатком нажать «−1» → подтвердить → остаток уменьшился,
   сразу виден тост с кнопкой «Вернуть».
3. Проверить: в «Итогах»/кассе ничего не изменилось; в оборотке
   корректировка не дублируется как продажа.
4. Создать заказ с резервом всей позиции → «−1» на складе серая/отказ.
5. Открыть карточку товара → внизу разрез по складам с «−1»/«+1»;
   в истории движений у строки «Корректировка» — «↩️ Вернуть».
