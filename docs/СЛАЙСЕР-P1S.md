# Свой слайсер PrintFlow Stage 1 для Bambu Lab P1S

Дата: 14.09.2026. Первый целевой принтер — Bambu Lab P1S.

## Что построено

До этого PrintFlow умел только звать чужой CLI (`OrcaSlicer`, `Bambu Studio`,
`PrusaSlicer`, `CuraEngine`) и честно отказывался, если бинаря нет. Настройки
нарезки при этом лежали мёртвым грузом: восемнадцать полей `slicer_*` никто
не читал.

Теперь появился свой движок. Он не обёртка и не заглушка: модель режется на
слои, из сечений строятся контуры, контуры смещаются в периметры, области
крыши и дна определяются сравнением с соседними слоями, остальное
заполняется узором, и всё это превращается в G-code с оценкой веса и времени.

```text
STL
  → чтение сетки и проверка замкнутости
  → проверка влезаемости в стол 256 × 256 и предела по высоте
  → сечения по слоям → контуры и дыры
  → периметры, крыша/дно, заполнение, поддержки, brim
  → G-code с температурами, ретрактом и обдувом
  → аудит результата
  → отдельный файл в библиотеке
```

Исходная модель никогда не перезаписывается, а нарезанный файл сам не
уезжает ни в очередь, ни на принтер.

## Важное ограничение

Это **Stage 1** — честный, но простой движок. Он не заменяет OrcaSlicer для
сложных деталей и не притворяется им. Первая печать нарезанным файлом —
всегда ручная, под присмотром владельца: сначала калибровочный куб, потом
мелкая полезная деталь, и только потом серия.

## Профиль P1S

- Принтер: Bambu Lab P1S
- Стол: 256 × 256 мм, предел высоты 256 мм
- Сопло: 0,4 мм, филамент 1,75 мм
- Высота слоя: 0,06–0,32 мм и не толще 0,75 диаметра сопла
- Температуры: сопло 170–300 °C, стол 0–110 °C
- Формат на входе: только STL (бинарный и текстовый)
- Материалы: из общего справочника `materials.py` — плотность, температуры,
  обдув и множитель скорости берутся оттуда, а не из второго справочника
- Результат: отдельный `.gcode` с маркерами Stage 1

## Что движок умеет

- периметры: любое число стенок, печать изнутри наружу, шов в ближайшей
  к предыдущей точке
- крыша и дно: определяются сравнением с четырьмя соседними слоями, а не
  «первые и последние N слоёв» — поэтому у наклонной стенки сплошная
  поверхность получается там, где она действительно сверху
- заполнение: `lines`, `grid`, `triangles`, `concentric` с чередованием угла
  по слоям
- поддержки: там, где под областью предыдущего слоя пустота
- brim: петли вокруг первого слоя
- ретракт с настройкой порога переезда, подъём по Z, обдув, пауза на первый
  слой, парковка головы в конце
- оценка веса, объёма, длины филамента и времени с учётом разгона

## Чего в Stage 1 нет

Это не «ещё не дописано», а заявленные границы. Каждое ограничение видно в
ответе `/api/slicer/engine`, а не спрятано в коде:

- переменная высота слоя
- тонкие стенки, заполнение зазоров, сглаживание углов
- поддержки-деревья, интерфейсный слой, отделяемый зазор
- мультиматериал и назначение AMS по цвету: слот уходит в отчёт, но не в
  G-code, потому что смену филамента движок не делает
- глажка, спиральный режим, дуги, настройка нависаний
- 3MF, OBJ, STEP на входе и чтение готовых профилей слайсера

Узор `gyroid` (и другие заявленные, но не реализованные) не отклоняется
молча: движок подменяет его на `grid` и пишет об этом в предупреждениях.

## Безопасный конвейер

1. Выбрать модель STL.
2. Проверить настройки: высота слоя, стенки, заполнение, материал.
3. Проверить влезаемость в стол и предел по высоте.
4. Проверить сетку: незамкнутая или рваная даёт предупреждение, а не тихую
   порчу детали.
5. Нарезать: получить G-code и отчёт.
6. Проверить G-code: температуры, наличие выдавливания, высота, маркеры.
7. Положить файл в библиотеку — отдельным файлом, исходник не тронут.
8. Показать оператору отчёт и предупреждения.
9. В очередь и на печать — только человеком.

Шаги 2–6 делает машина состояний `slicer_run.py`. Неизвестное состояние
блокирует конвейер, а не «пробуем всё равно».

## Гейты (зеркало FarmLoop)

| Гейт | Что требует | По умолчанию |
| --- | --- | --- |
| `engine` | выбран свой движок `slicer_provider=printflow` | выключен |
| `profile` | профиль `bambu-p1s-printflow-stage1` | совпадает |
| `operator` | подтверждение оператора в ручном режиме | не подтверждено |
| `verification` | принят первый реальный прогон | не принят |
| `unattended` | режим `auto` + принятый прогон + серия больше одного | запрещено |

В ручном режиме (`slicer_mode=manual`, значение по умолчанию) автоматическая
постановка в очередь запрещена всегда. Печать без оператора запрещена даже в
автоматическом режиме, пока не принят первый прогон и не разрешена серия.

## Команды

```bash
# план: только аудит, файл не пишется
python3 scripts/slicer-slice.py model.stl --plan --report plan.json

# нарезка
python3 scripts/slicer-slice.py model.stl --output model.gcode \
  --layer-height 0.16 --walls 3 --infill 25 --pattern grid \
  --material PETG --brim --brim-width 6
```

Команда не отправляет файл на принтер и не ставит его в очередь.

## Маршруты

| Маршрут | Назначение |
| --- | --- |
| `GET /api/slicer/engine` | статус движка, версия, пределы, чего нет |
| `GET /api/slicer/profile` | профиль, материалы, гейты, причина блокировки |
| `GET /api/slicer/settings` | разрешённые настройки, предупреждения, гейты |
| `GET /api/slicer/status` | статус внешнего CLI-слайсера (как раньше) |
| `POST /api/slicer/plan` | аудит модели без записи файла |
| `POST /api/slicer/slice` | нарезка своим движком + аудит + библиотека |
| `POST /api/slicer/run` | общая точка входа: сама выберет движок по настройке |

## Приёмка первой печати

До того как печатать серию, владелец проверяет вручную:

- калибровочный куб 20 × 20 × 20 мм: вес и время против отчёта движка;
- первый слой: прилипание по всей площади, без задиров и щелей;
- периметры: нет недоэкструзии на стыке шва, стенка держит ногтем;
- крыша: нет дыр и проседаний над заполнением;
- заполнение: совпадает с заявленным процентом по весу;
- поддержки: снимаются, не отдирая поверхность;
- размеры: сопоставимы с моделью в пределах допуска материала;
- файл не уехал на принтер сам — только по команде оператора.

После принятого прогона выставляется `slicer_first_print_verified`, и только
тогда в настройках можно включать автоматический режим.
