## Задача 1. Визуальный рефакторинг существующих систем

Идеи переработки текущих вкладок и компонентов панели (12.2.0–13.0.0).
Файлы указаны как ориентиры: очередь/журнал рендерит `printer.js`
(`renderQueue`), канбан заказов — `ops.js`, товары — `products.js`,
принтеры — `printer.js`, клиент-бот — `clientbot.js`, финансы — `finance.js` +
`money.js`, калькулятор — `money.js`, стеллаж — `shelf.js`, маркетинг —
`marketing.js`, обзор — `app.js`, мобильная/ТВ — `m.html`/`tv.html`.

### Очередь и журнал печати

1. **Умная строка поиска вместо двух полей.** Сейчас поиск журнала
   (`history_search`) отдельно от фильтров очереди. Один input с модами
   «задание/журнал» (seg-переключатель рядом) — меньше полей, один паттерн.
   ⚡

2. **Живой прогресс в карточках заданий.** У заданий в работе — тонкая
   полоса прогресса с плавной анимацией (CSS transition по данным),
   у ожидающих — «порядковый номер в очереди». Взгляд сразу отвечает «что
   происходит». ⚡

3. **Группировка очереди по принтерам.** Переключатель «списком / по
   принтерам»: во втором режиме задания сгруппированы колонками под
   карточками парка — видно загрузку каждого принтера и свободные окна. ◐

4. **Drag-n-drop перестановки приоритета.** В очереди сейчас нет
   перестановки заданий (только в канбане заказов). Перетаскивание карточки
   задания вверх/вниз меняет порядок — привычный жест, повторяющий уже
   существующий паттерн канбана. ◐

5. **Мини-таймлайн задания в карточке.** Точки upload → start → progress →
   done с временами; клик по точке открывает журнал. Визуализация «цифровой
   нити» задания, частично данные уже есть. ◐

6. **Плашка дефицита пластика в карточке.** Если на задание не хватает
   катушки — цветная плашка «мало PETG белого (120 г)» прямо в карточке до
   старта, а не только в дашборд-виджете. ⚡

7. **Авто-подсветка активного задания.** При каждом обновлении — мягкая
   пульсация фона у задания, которое сейчас печатается (и авто-скролл к
   нему при входе на вкладку). Глаз сразу находит живое. ⚡

8. **Виртуализация журнала.** Журнал растёт бесконечно; рендер тысяч строк
   тормозит вкладку. Подгрузка порциями при скролле (IntersectionObserver)
   + «показать ещё 50». ▣

9. **Empty-state журнала с обучением.** Вместо «пусто» — карточка «сюда
   попадут завершённые печати», с иконкой и ссылкой «как это работает».
   Единый паттерн emptyBox уже есть — применить. ⚡

10. **Кластер журнала: очистка и экспорт.** Кнопка «Очистить завершённые»
    с подтверждением (confirmDanger) + «Экспорт CSV» журнала — журнал
    становится управляемым архивом, а не мусорником. ⚡

11. **Полоса загрузки парка за 24 ч.** Над очередью — горизонтальные
    полосы занятости каждого принтера по часам (как в `dash_timeline`, но
    компактно и кликабельно). Видно окна для срочных заданий. ◐

### Склад, товары, катушки

12. **Единый поиск «товары + катушки + документы».** Одна строка с
    подсказками-разделами (как командная палитра), вместо трёх поисков по
    вкладкам. Меньше переключений при «где у меня…». ◐

13. **Бублик остатка в плитке товара.** Вместо тонкого бара `prod-stock-bar`
    — мини-donut: свободно / резерв / витрина, с цветом здоровья. Остаток
    читается формой, а не числом. ◐

14. **Цветовой код катушек.** В плитках и таблицах катушек — полоска
    фактического цвета материала (hex из катушки), а не только текст
    «PLA белый». Мгновенное опознание у стеллажа. ⚡

15. **Сортировки плиток.** Переключатель сортировки над сеткой: по марже,
    по продажам 7 дней, по «кончается первым». Сейчас порядок фиксирован —
    для «что допечатать» приходится открывать план. ⚡

16. **Мини-спарклайны продаж в плитке.** SVG-линия 60×20 (7 дней) под
    ценой — тренд виден без клика. Данные `sold_7` уже есть; добавить
    историю по дням. ◐

17. **Сворачиваемые группы в плитках.** Список товаров — секции по группам
    (details-аккордеон) со счётчиками и подытогом остатка. Длинная
    номенклатура перестаёт быть «простынёй». ◐

18. **Режим «полка глазами покупателя».** Переключатель вида плиток:
    как их видит клиент в боте (фото, цена, статус «скрыт» 🙈 крупно).
    Сверка витрины без открытия бота. ⚡

19. **Бейдж «цены просели» на KPI-панели.** Если у N товаров маржа ушла
    в минус или цены давно не пересчитывались — жёлтый бейдж-предупреждение
    над сеткой, клик фильтрует «убыточные». Сейчас статус виден только
    внутри карточки. ⚡

20. **Кластер: горячие клавиши склада.** `N` — новый товар, `S` — продажа
    сфокусированной плитки, `R` — пересчитать цену. Товарные операции —
    самые частые у прилавка. ⚡

21. **План пополнения как «заказ на печать».** Карточки плана с мини-превью
    модели (STL-viewer уже есть), количеством, временем печати и чек-боксом
    выполнения — план превращается в рабочий список. ◐

### Принтеры

22. **Единый пульт вместо простыни.** `job-card` + температуры +
    вентиляторы + графики + управление — колонка с секциями-аккордеонами,
    «Управление» и «История» свёрнуты по умолчанию. Меньше скролла,
    критичное (прогресс, AMS, температуры) — вверху. ◐

23. **Гейджи температур с историей.** Под цифрой сопла/стола — уже есть
    `tspark`; добавить такие же мини-спарклайны к вентиляторам и камере
    (данные истории уже пишутся). Живая «дыхание» принтера. ◐

24. **Процент остатка на AMS-трубках.** Сейчас слоты AMS — цветные точки;
    добавить двухцветную полоску «остаток %» внутри точки (или тултип с
    граммами). Низкий остаток виден формой, не только флажком ◍. ⚡

25. **«Замороженная» телеметрия офлайна.** Если связь пропала — карточка
    показывает последние известные температуры и прогресс (помеченные
    «данные N мин назад»), а не пустые «—». Не выглядит, что всё сломалось,
    и видно, что именно замерло. ◐

26. **Контекстные кнопки управления.** «Пауза» видна только при печати,
    «Продолжить» — только в паузе, «Стоп» приглушён вне печати. Сейчас
    кнопки статичны — лишние вопросы «а зачем эта кнопка». ⚡

27. **Камера на плитке «Стены».** В режиме стены у печатающего принтера —
    живой кадр камеры вместо статичной плитки (если камера доступна). Стена
    становится настоящим мониторингом. ◐

28. **Сводная строка парка.** Над карточками: «3 в работе · 1 офлайн ·
    14 ч печати за сутки» — одна строка вместо чтения каждой карточки. ⚡

29. **Кластер: кадр и видео из карточки.** Кнопки «📷 Кадр» и «🎬 Видео»
    (keyframes уже есть) с модалкой-превью прямо в пульте принтера, без
    перехода в отдельный просмотрщик. ⚡

30. **Текущие значения на сеттерах.** У «Скорость/Поток» — подпись
    «сейчас 100%» на кнопке; select скорости — с пометкой активного
    профиля. Не нужно открывать, чтобы узнать текущее. ⚡

31. **Сравнение истории «вчера в это же время».** Пунктирная линия вчерашней
    температуры на графике истории — видно отклонения (забитый фильтр,
    холодная комната). ◐

### Заказы (канбан и таблица)

32. **Прогресс печати на карточке канбана.** Если заказ связан с заданием —
    мини-полоса с % и иконкой принтера на карточке. В канбане сразу видно
    «это уже печатается». ⚡

33. **Плотный режим канбана.** Переключатель плотности как в принтерах:
    компактные карточки без отступов для больших потоков. ⚡

34. **Группировка таблицы с подытогами.** Таблица заказов группируется по
    нише/каналу, в шапке группы — сумма дохода и количество. Финансовый
    срез без отдельного отчёта. ◐

35. **Тепловая подсветка сроков.** На карточках канбана фон дедлайна:
    «сегодня» — жёлтое, «просрочен» — красное, «завтра» — янтарная точка.
    Срочное видно цветом, не чтением. ⚡

36. **Авто-сохранение черновика заказа.** Поля модалки нового заказа
    пишутся в localStorage (debounce), при F5 — восстановление с тостом.
    Больше ни один введённый заказ не теряется. ⚡

37. **Fuzzy-подсветка в поиске заказов.** В результатах совпадения
    обёрнуты в `<mark>` — видно, почему строка нашлась. ⚡

38. **Кластер таблицы: «последнее событие» + сортировка.** Колонка «Был
    изменён N мин назад» и сортировка по заголовкам (клик по th).
    Таблица становится рабочим инструментом, а не снимком. ◐

39. **«Выдать заказ» с предпросмотром.** Модалка показывает текст клиенту,
    чек и кнопки «Скопировать» / «Уже выдал» — меньше возвратов и
    случайных нажатий. ◐

40. **Telegram-бейджи кликабельны.** Бейдж канала на карточке открывает
    диалог клиента в клиент-боте (связка контуров одним кликом). ⚡

### Клиенты и клиент-бот

41. **Inbox как мессенджер.** Вместо таблицы «Диалоги» — пузыри
    входящих/исходящих с аватаром (avatarEmoji уже есть) и временем.
    Читается как Telegram, с которым все работают. ◐

42. **Шаблоны ответов чипами.** В треде — чипы шаблонов с превью по ховеру
    вместо select. Ответ в два клика. ⚡

43. **Сплит-вью inbox.** Слева список диалогов со счётчиками
    непрочитанных, справа тред — без прыжков по вкладкам. ⚡

44. **Приглушение «спящих» клиентов.** Аватар/имя клиента без активности
    N дней — полупрозрачные; тёплые видны сразу. ⚡

45. **Кластер треда: автопрокрутка и «вниз».** Новое сообщение —
    авто-скролл к последнему; плавающая кнопка «↓» при отскролле. И
    пометка «прочитано» при клике вне треда. ⚡

46. **Воронка барами.** Вместо таблицы событий UTM — конверсионные бары
    этапов (просмотр → заявка → заказ → оплата) с процентами. ⚡

### Финансы

47. **Один график с переключателем метрик.** Доход/расход/прибыль/часы на
    одном полотне с seg-переключателем (паттерн `dash_chart_mode` уже
    есть) и кросс-подсветкой при наведении. ◐

48. **Канбан долгов.** Карточки должников по срокам давности с кнопкой
    «Напомнить» (копирует текст напоминания в буфер). Долги — это
    действия, а не строки. ◐

49. **Плашка кассы «кошелёк».** Крупная цифра кассы + «ожидается / 
    просрочено» на одной карточке вместо поиска по таблицам. ⚡

50. **Тепловая карта месяца.** Квадратики 7×5 (доход/расход по дням) с
    цветом от зелёного к красному — месяц виден одним взглядом. ◐

51. **Кластер экспорта: PNG и PDF месяца.** Кнопка «Скачать PNG» для
    графиков (canvas) и «PDF отчёта» (паттерн `dash_pdf` уже есть) для
    месяца. ⚡

52. **Коридор прогноза кассы.** На графике прогноза — пунктирная линия
    + полупрозрачный коридор неопределённости. «Кассовый разрыв» виден
    как зона, а не число. ◐

### Калькулятор

53. **Большая цифра результата.** Над формой — крупный бейдж
    «цена/прибыль/час» с анимацией «перекатывания» цифр при изменении
    параметров (number-roll). Расчёт чувствуется руками. ⚡

54. **Режим сравнения А/Б.** Две колонки расчётов (например, PLA vs PETG
    или 1 шт vs 10 шт) с разницей — выбор варианта без пересчёта в уме. ◐

55. **История расчётов чипами.** Последние 10 расчётов — чипы под формой;
    клик возвращает параметры. Повторные оценки в один клик. ⚡

56. **Кластер: «в заказ» и QR из расчёта.** Кнопка «Создать заказ из
    расчёта» (предзаполненная модалка) и QR-ценник результата. Калькулятор
    замыкается на продажу. ◐

### Стеллаж и ценники

57. **Превью QR-ценника в карточке.** Рядом с карточкой стеллажа — мини-вид
    «как будет напечатан ценник» (паттерн price-tags). Видно до печати. ⚡

58. **Мини-карта полки.** Сортировка ячеек по расположению (A1, A2…) с
    сеткой-схемой полки и подсветкой пустых/полных ячеек. Стеллаж — это
    пространство, а не список. ◐

59. **Кластер: режим «проверка полки».** Чек-лист «пересчитал/выставил»
    с галочками и временем + подсветка расхождений остатка с учётом.
    Инвентаризация без бумажки. ◐

### Маркетинг

60. **Доска контента по дням недели.** Канбан пн–вс с карточками постов
    (drag между днями, паттерн канбана заказов). План недели — как
    заказы. ◐

61. **Превью поста как в Telegram.** В карточке поста — мини-макет
    сообщения (текст, кнопки, фото) — как увидит подписчик. ⚡

62. **Кластер: «заполнить фактами» и счётчик недели.** Кнопка подстановки
    фактов цеха в шаблон + прогресс «N из 7 постов готово» в шапке. ⚡

### Библиотека

63. **Карточка «следующий шаг».** Под прогресс-баром — «Дальше: чек-лист
    №3 „Стеллаж“» с кнопкой. Маршрут ведёт, а не просто показывает %. ⚡

64. **Поиск по библиотеке с подсветкой.** Строка поиска + чипы-категории;
    совпадения в `<mark>`. Материалов много, навигация — по ключевым
    словам. ⚡

65. **Кластер: «прочитано» и память прокрутки.** Отметка прочитанного и
    возврат к месту, где остановился (localStorage). ⚡

### Обзор (дашборд)

66. **Перетаскивание виджетов.** Порядок карточек дашборда — drag-n-drop
    (сейчас только скрытие через «Виджеты»). Каждый строит свой утренний
    экран. ◐

67. **Режим «Утренний брифинг».** Одна карточка: KPI + «сейчас нужно
    сделать» + активная печать — кнопка в шапке. Для взгляда с кофе. ⚡

68. **Лента событий с группировкой.** События сгруппированы по часам,
    «ещё 5» раскрывает группу; чипы-фильтры по типам (печать/склад/деньги).
    Лента перестаёт быть потоком. ◐

69. **Спарклайны в KPI-плитках.** Под значением — мини-линия тренда за
    период (7/30 дней). Тренд виден без переключения периода. ◐

70. **Интерактивный таймлайн дня.** Клик по отрезку печати открывает
    задание/заказ; ховер — тултип с именем и граммами. Сейчас таймлайн
    статичен. ◐

71. **Кластер: «год назад сегодня» и рекорды.** Строка «в этот день год
    назад: прибыль X, граммы Y» (идея из старого бэклога) + «рекорды
    цеха» (самая долгая печать, лучший день). Эмоциональный дашборд. ⚡

### Мобильная и ТВ-панели

72. **m.html на общих токенах.** Инлайн-CSS m.html вынести в общий файл
    (или хотя бы подключить `theme.css`) — одна палитра, проще правки и
    авто-тема. ◐

73. **Тактильный отклик в m.html.** `navigator.vibrate(15)` на нажатия
    кнопок у станка (Android) — подтверждение без взгляда на экран.
    Опционально, настраивается. ⚡

74. **TV: режим «витрина».** Между печатью — слайды с промо/постерами
    (карусель, данные из marketing) и крупные часы с датой. ТВ продаёт,
    пока цех печатает. ◐

75. **Кластер TV: «следующее задание» и ночное затемнение.** Тикер
    «дальше в очереди: …» + автоматическое затемнение по часам (после
    23:00 яркость падает). ⚡

## Задача 2. Визуальные инновации — новые паттерны и микро-взаимодействия

### Дизайн-система и консолидация

1. **Единый `tokens.css`.** Палитра/радиусы/тени размазаны по `app.css`,
   `theme.css`, `more.css` и инлайну m.html/tv.html. Один файл токенов +
   комментарии — основа всей дальнейшей консистентности. ◐

2. **Глобальная плотность интерфейса.** Переключатель «компактно/уютно»
   для всей панели (сейчас плотность только у принтеров, `pr_density`).
   Один атрибут на `<html>`, CSS-переменные отступов. ◐

3. **`tabular-nums` для всех чисел.** `font-variant-numeric: tabular-nums`
   в таблицах и KPI — цифры не «прыгают» при обновлении. Мелочь, которую
   глаз ловит каждый день. ⚡

4. **Единый формат денег/веса.** Все деньги через один `money()`/Intl
   (сейчас местами `toLocaleString` вразнобой). Гарантия «₽ и граммы
   выглядят одинаково везде». ⚡

5. **Унификация empty-state.** Один компонент: эмодзи-иллюстрация, заголовок,
   подсказка, CTA (паттерн `emptyBox` в products.js) — на все вкладки.
   «Пусто» перестаёт быть тупиком. ⚡

6. **Хлебные крошки в шапках вкладок.** Под заголовком — «Раздел → подраздел»
   (особенно в «Ещё»). Ориентация в глубокой навигации. ⚡

7. **Скелетоны с shimmer по всей панели.** Единый класс `.skel` с бегущим
   градиентом (сейчас — статичные серые полосы) + отключение при
   `prefers-reduced-motion`. Загрузка ощущается живой. ⚡

8. **Staggered-появление карточек.** Списки карточек появляются лёгкой
   «волной» (transition-delay по индексу, до 8 элементов) — приятный ритм,
   отключается reduced-motion. ⚡

9. **Фокус-кольца и skip-link.** Единый стиль `:focus-visible` (сейчас
   разнобой) + «Перейти к содержимому» — панелью можно пользоваться
   с клавиатуры. ⚡

10. **`prefers-reduced-motion` как настройка.** Медиа-запрос + ручной
    переключатель «меньше анимаций» в настройках (переопределяет
    медиа). Доступность без запретов. ⚡

11. **Высококонтрастный режим.** Класс `contrast` на `<html>`: усиленные
    границы, тёмнее текст, различимые статусы. Для проектора у станка
    и слабого зрения. ◐

12. **Режим для дальтоников.** Палитра статусов дублируется паттернами
    (штриховка/точки на графиках, иконки в бейджах) — не только цветом.
    Проверено на красно-зелёной слепоте. ◐

### Микро-взаимодействия и анимации

13. **Number-roll у KPI.** Цифры «прокручиваются» к новому значению
    (одометр, 300 мс) при обновлении данных. Живые деньги вместо мигания. ◐

14. **«Всплеск» финиша печати.** При завершении задания — лёгкий конфетти
    из частиц-гранул (CSS, 12 частиц, 1.2 с) + тост. Праздник без звука. ⚡

15. **Пульс активной печати.** Кольцо прогресса в карточке принтера мягко
    «дышит» (scale 1→1.03) во время печати; замирает при паузе. Жизнь
    видна на периферии зрения. ⚡

16. **Bump-анимация бейджей-счётчиков.** При изменении числа — короткий
    scale-«подскок» (у непрочитанных, долгов, очереди). Событие заметно
    даже краем глаза. ⚡

17. **Кнопка-«галочка» после действия.** После «Сохранить»/«Выдать»
    кнопка на 800 мс становится ✓ (паттерн action-feedback) — подтверждение
    на месте, без тоста. ⚡

18. **Ховер-превью карточек.** Наведение на название товара/заказа в
    таблице показывает мини-карточку (фото, остаток, статус) рядом с
    курсором. Разведка без кликов. ◐

19. **Призрак при drag-n-drop.** Перетаскиваемая карточка канбана — слегка
    повёрнутый «призрак» с тенью; целевая колонка подсвечивается рамкой.
    Паттерн «оживления» уже существующего жеста. ⚡

20. **Плавные переходы статусов.** Бейджи статусов меняют цвет с
    transition (0.25 с), а не скачком. Мозг успевает считать изменение. ⚡

21. **Градиентная рамка активной карточки.** Выбранный принтер/товар —
    акцентное свечение по контуру (outline + glow), а не только фон. ⚡

22. **«Приподнимание» карточек при ховере.** Единый класс `.lift`:
    translateY(−2px) + тень. Тактильность курсора во всей панели. ⚡

23. **Тонкая полоса загрузки сверху.** При каждом fetch — 2px-полоска
    прогресса под шапкой (как YouTube). «Сеть жива» видно, даже когда
    экран не меняется. ⚡

24. **Плавный переход между вкладками.** Лёгкий fade/slide контента при
    смене раздела (150 мс, reduced-motion — off). Панель перестаёт
    «щёлкать». ⚡

### Производительность и техника

44. **Lazy-рендер вкладок.** Неактивные вкладки не рендерят DOM до
    первого открытия (или рендерят, но с `content-visibility: auto`).
    Старт панели быстрее. ◐

45. **Виртуализация длинных списков (общий хелпер).** `virtualList(el,
    items, renderFn)` для журнала, документов, движений — 10 тыс. строк
    без лагов. Переиспользуется везде. ▣

46. **requestAnimationFrame-батчинг обновлений.** Телеметрия принтеров
    (renderTabs) и часы обновляются разом за кадр, а не по каждому
    событию. Меньше перерисовок. ⚡

47. **Web Worker для парсинга G-code/STL.** Тяжёлый разбор файлов — в
    worker, интерфейс не подвисает на больших моделях. ▣

48. **Stale-while-revalidate для API.** Дашборд и парк показывают
    последние данные мгновенно, обновляя в фоне (кэш с TTL). Панель
    ощущается мгновенной. ◐

49. **Мемоизация карточек.** Кэш HTML-строк карточек по ключу
    «id + статус» — повторные рендеры не пересоздают разметку. ⚡

50. **`content-visibility` для карточек.** CSS-подсказка браузеру
    рендерить только видимые карточки сетки. Одна строка CSS на всех
    вкладках. ⚡

51. **Дебаунс всех поисков через единый слой.** `U.debounce` уже есть —
    пройтись по всем input-поискам (заказы, товары, документы, журнал,
    библиотека) и убедиться, что каждый под дебаунсом. ⚡

## Бортовое предложение

Находки по ходу анализа репозитория, которые я бы выправил, будь это мой цех:

- **Б1. Пины версий скриптов в index.html разъехались.** `?v=` от 9.1.2 до
  12.2.0 — часть файлов (money.js, finance.js, shelf.js, products.js —
  11.0.1) не бампалась с релизами, хотя правилась. Браузер может годами
  показывать кэшированную версию. Предлагаю завести один `ASSETS_VERSION`
  (константа, обновляется при каждом релизе) и единый суффикс для всех
  `<script>`/`<link>` — механика на 20 минут, лечит класс ошибок «я
  обновил, а оно не изменилось». ⚡

- **Б2. Очередь живёт в `printer.js`, а не в «своём» файле.** `renderQueue`
  и журнал печати лежат в модуле принтеров (2031 строка — самый большой
  файл панели). При крупном рефакторинге Задачи 1 стоит вынести очередь в
  отдельный `queue.js` — вкладка «Очередь» станет самодостаточной. ◐

- **Б3. `check.py` прогоняет `node --check` по всем `site/assets/*.js`.**
  Любой вендоренный файл должен проходить синтаксис-чек (никакого
  top-level await и свежего синтаксиса без проверки). При добавлении
  библиотек — держать в уме; заодно это бесплатный тест на опечатки. ⚡

- **Б4. В таблице товаров колонки «Резерв», «Свободно», «₽/час», «7 дн.»**
  всегда «—», хотя в плитках те же данные считаются. Табличный режим
  выглядит беднее, чем есть. Досчитать значения для таблицы — режимы
  перестанут врать. ◐

- **Б5. В канбане заказов не видно связи с заданием печати.** Карточка
  «В печати» ничем не отличается от «Новой заявки» (без идеи 32).
  Мини-полоса прогресса на карточке — самый частый вопрос «а оно уже
  печатается?» закрывается взглядом. ⚡

- **Б6. `m.html` не использует дизайн-токены панели** — инлайн-CSS с
  собственной палитрой. Кандидат на подключение `theme.css` (идея 72
  Задачи 1) — тогда тёмная/светлая тема и бренд синхронны. ◐

- **Б7. `?rotate` в tv.html переключает только режимы tv/monitor.** Тот же
  механизм легко расширить на ротацию контентных блоков (идея 57 Задачи
  2) — ТВ станет витриной, а не только монитором. ⚡

- **Б8. У `pr_density` («Компактно») паттерн уже готов** — переключатель
  плотности, атрибут на контейнере. Расширение на всю панель (идея 2
  Задачи 2) — это переиспользование существующего, а не новая механика. ⚡
