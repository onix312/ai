# Навыки ассистента компьютера

Справка о том, что умеет личный ассистент на компьютере цеха. Реестр навыков —
данные в `agent/skills.py`, а не ветки кода: объявление навыка содержит название,
описание, хост, риск, параметры, требуемые способности и идею, из которой он
вырос. Исполнение живёт в `agent/executor.py`, своя база — в `agent/store.py`.

Числа в этой справке сверяются с кодом контрактом
`connector/tests/test_assistant_skills.py`: навык, которого нет в справке, и
справка, которой нет в коде, тест не пропускает.

## Форма навыка

```json
{
  "name": "files.to_order",
  "title": "Файл в заказ",
  "description": "Отдать файл в PrintFlow и получить черновик заказа.",
  "host": "agent",
  "risk": "read",
  "params": {"path": "path", "order": "text", "kind": "oneof:model|invoice|photo|document"},
  "requires": ["files", "panel"],
  "ideas": ["И144"]
}
```

| Поле | Что значит |
| --- | --- |
| `name` | Идентификатор вида `группа.навык`. Выученные навыки — только `my.*` |
| `host` | `agent` — исполняет эта программа; `panel` — исполняет PrintFlow по loopback |
| `risk` | `read`, `own` (своя база), `write` (чужое), `system`, `irreversible` |
| `confirm` | Не задаётся руками: считается из риска. `write`, `system`, `irreversible` — всегда с подтверждением |
| `params` | Имена и типы: `text`, `int`, `float`, `bool`, `date`, `path`, `object`, `oneof:a\|b` |
| `requires` | Способности из `agent/capabilities.py`. Нет способности — навык недоступен и показывает причину |
| `ideas` | Номер идеи из каталогов `docs/ИДЕИ-100.md` и `docs/ИДЕИ-АССИСТЕНТ-ПК.md` |

## Правила исполнения

1. **Модель выбирает только из реестра.** В промпт попадают доступные навыки
   (`skills.prompt`), а недоступные показывает интерфейс с причиной. Адреса,
   признаки подтверждения и состав параметров модель не задаёт.
2. **Подтверждение спрашивает человек на этом компьютере.** Навык с риском
   `write` и выше становится ожидающим (`server.Agent.queue_action` с
   `kind="skill"`) и исполняется только после `POST /action/confirm` или окна
   подтверждения. Поле `confirmed` в теле запроса не читается вовсе.
3. **Параметры разбираются по типам.** Необъявленное имя отбрасывается с
   предупреждением, неразобранное значение останавливает навык.
4. **Отказ — это ответ.** У любого отказа есть `reason`, он пишется в журнал и
   показывается навыком `agent.why`.
5. **Чтение в журнал не пишется**, отказ чтения — пишется. Правило то же, что у
   журнала действий панели (18.13): иначе лента утонет.
6. **Граница папок.** Файловые навыки читают и двигают файлы только внутри
   папок из настроек агента (`fileops.inside_allowed`).
7. **Сеть — только по запросу.** Авито-навыки ходят в сеть обычным urllib с
   таймаутом, без loopback-проверки: Авито — внешний сайт, но запросы и фильтры
   остаются в своей базе ассистента, а не в панели.

### Надзор за процессами (18.19) — И263

- `system.watchdog` — чтение надзора: `mode=status|log|self_check`. Пульс ролей `agent` и `panel` из `~/.printflow/watchdog.json` (pid, время, заметка), причина протухания у каждого («процесс не отвечает» ≠ «пульс старше порога»), журнал `watchdog.log`, проверка самого надзирателя. Ничего не поднимает.
- `system.watchdog_arm` — вооружить или снять надзор: `enabled=on|off`, `interval`, `stale_sec`, `max_restarts`, `confirm_text` («вооружить» / «снять»). Пишет `watchdog_config.json`, включает или выключает роль; сам подъём делает отдельный процесс, а не панель.
- `system.watchdog_once` — один проход по кнопке владельца: проверить пульс и поднять упавшие роли, `dry=on` — только посмотреть. Подтверждение словом «поднять», каждый подъём и причина ложатся в `watchdog_events`.

## Границы, которые навыками не нарушаются

- данных нет вне машины: рантайм модели и панель — только loopback, индекс и
  журнал лежат в своей SQLite; Авито-запросы уходят наружу, но фильтры и
  переписка остаются в своей базе, а не в панели;
- ассистент не удаляет файлы: перемещение с планом и подтверждением — потолок;
- деньги и печать по-прежнему исполняет панель и только после «Подтвердить»;
- навык без способности не предлагается модели, а человеку показывается с
  причиной — молча неработающих кнопок нет;
- надзор не исполняет навыки и не двигает деньги: он только видит пульс и поднимает упавший процесс, а после порога падений сдаётся вслух (эскалация) вместо бесконечного цикла;
- микрофон и камера в 18.17 используются через внешние рантаймы вовсе: голос и зрение — следующие
  заходы (18.16 и 18.17);
- Авито-ответы — только черновики: отправка в Авито делается человеком руками,
  навык лишь предлагает варианты.

## Как проверить на живой машине

1. `cd agent && python -m venv .venv && .venv\Scripts\activate && pip install -r requirements.txt`
2. `set PRINTFLOW_ASSISTANT_FOLDERS=C:\Users\вы\Documents` и `set PRINTFLOW_MODEL_NAME=qwen2.5:7b`
3. `python -m agent` — агент напечатает адреса, окно откроется на
   `http://127.0.0.1:8799/ui`, недостающие способности перечислит честно.
4. В окне: выполните `files.index`, затем `files.search` со словом из своих
   документов, затем `day.briefing` (нужна запущенная панель).
5. `files.tidy_plan` покажет план раскладки загрузок; `files.tidy_apply` спросит
   подтверждение — без него файлы не двигаются.
6. `avito.watch` добавьте «3d принтер, Москва, до 50000», затем `avito.check` —
   новые объявления попадут в `avito.listings`.
7. `avito.reply` с текстом переписки — 3 варианта ответа, с моделью — живые.
8. `tg.ideas` → темы, `tg.draft` с темой «что напечатали» — черновик в `tg.drafts`.
9. `agent.why` на любом навыке объяснит отказ; `agent.journal` покажет след.
10. `python -m agent.watchdog --status` покажет пульс ролей; `python -m agent.watchdog --self-check` — может ли надзиратель вообще видеть и поднимать; `python pf.py watchdog --arm --roles agent,panel --interval 30` вооружит надзор.
    Надзор в цикле: `python pf.py watchdog --watch` (или `python -m agent.watchdog --watch`) — его и стоит ставить в автозапуск рядом с панелью.
