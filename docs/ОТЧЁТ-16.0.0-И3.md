# Отчёт · Касса 16.0 · Итерация 3 — клиентский бот: оплата и статусы

Дата: 2026-09-06. Ветка: `arena/01a07625-ai`. Версия: `16.0.0`.

## Что сделано

Оплата по СБП в клиентском Telegram-боте теперь идёт через единое ядро СБП:
платёж, заявка на сверку, статус в карточке заказа и подтверждение в панели
связаны в один контур без расхождений.

### Изменённые файлы
- `db.py` — колонка `client_payment_intents.sbp_id` (связь с СБП-платежом;
  догоняющая миграция для существующих баз).
- `client_bot.py`:
  - `_sbp()` — ленивый доступ к ядру СБП;
  - `_paid_notice()` — «✅ Я оплатил» создаёт заявку **и** СБП-платёж
    (pending), деньги/долг не трогаются;
  - `_pay_card()` / `_order_card_keyboard()` — QR из `client_bot_pay_qr` или
    статического `sbp_shop_qr`;
  - `_payment_line()` — состояние оплаты в карточке заказа и «статусе».
- `api.py` — `/api/client-bot/payment`: подтверждение через `self.sbp.confirm`
  (счёт «СБП», идемпотентно), отклонение гасит и связанный СБП-платёж;
  старые заявки без `sbp_id` — прежним путём (обратная совместимость).
- `CHANGELOG.md`, `docs/КАССА-16.0.md`.
- Тесты: `connector/tests/test_client_bot_sbp.py` (5).

## Сценарий клиента

1. Клиент в боте: «мои заказы» → «💳 Оплатить» → сумма + назначение перевода
   + QR (статический магазина или заданный в настройках).
2. Клиент платит и жмёт «✅ Я оплатил» → бот: «Заявка на сверку создана»,
   в карточке заказа «💳 Оплата: ожидает подтверждения».
3. Владелец/кассир подтверждает в панели (или на экране СБП) → деньги на
   счёт «СБП», долг закрыт, клиент получает «оплата подтверждена мастером ✓»,
   в карточке «✅ Оплачено».

## Гарантии (покрыты тестами)

| Требование | Как обеспечено |
|---|---|
| Нет фейковой выручки | «Я оплатил» создаёт платёж pending, проводки нет, долг не закрыт |
| Один учёт | подтверждение в панели = `Sbp.confirm` = те же `payments`/`transactions` |
| Нет дублей | idempotent: повторный «Я оплатил» не плодит заявку/платёж; повторное подтверждение не пишет вторую проводку |
| Счёт СБП | подтверждённый платёж — на счёт `sbp_account_id` (по умолчанию «СБП») |
| Отмена обратима | отклонение гасит и заявку, и связанный СБП-платёж |
| Видно клиенту | статус оплаты в карточке заказа + уведомление «оплачено» |
| Обратная совместимость | старые заявки (без `sbp_id`) подтверждаются прежним путём |
